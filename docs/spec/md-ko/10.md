# 10 제어

#### 구문

```ebnf
control = "if" { body } [ "else" { body } ] "end"
        | "loop" { body } "end"
        | "match" { branch } [ "otherwise" { body } "end" ] "end" ;
branch  = "when" case-value { case-value } "do" { body } "end" ;
leave   = ( "break" | "continue" ) [ INT ] "." | "return" ;
block   = "do" { "to" NAME } { body } "end"
        | "def" effect "do" { body } "end"       (* a block value, 10.5 *)
        | "ref" NAME ;
```

(1) `end` 는 가장 안쪽에 열린 것 하나를 닫는다. 여는 낱말은 `def` `forward` `extern` `test` `record` `do` `if` `loop` `match` `when` `otherwise` `or_else` `defer` 다. (`forward` 와 `extern` 은 서명 뒤의 `end` 로, `type NAME proc … end` 도 닫는다.) (텍스트 리터럴과 `note` 주석은 자기 꼬리표로 닫는다, 6.3, 6.5.)

(2) 처리기는 적재 때 모든 갈래의 스택을 견준다. 갈래가 다시 만나는 자리에서 스택은 어느 갈래로 왔든 같아야 한다. **떠나는 갈래**(leaving branch) — `return` `fail` `break` `continue` 로 끝나거나 끝나지 않는 루프로 끝나는 갈래 — 는 견주지 않는다.

## 10.1 갈림

(1) `조건 if 몸 end` 는 맨 위의 `bool` 을 내려 참이면 몸을 돈다. `조건 if 몸 else 몸 end` 는 거짓이면 `else` 의 몸을 돈다.

(2) `else` 가 없는 `if` 의 몸은 스택을 들어올 때와 같게 둬야 한다. `else` 가 있으면 두 몸은 같은 스택을 남겨야 한다.

`10-if.pnx`

```pinax
use io .
def sign n int gives str do n 0 lt if "negative" else n 0 eq if "zero" else "positive" end end end
-5 sign io.println
0 sign io.println
def warn n int do n 100 gt if "big" io.println end end      rem no else: the branch leaves the stack as it was
500 warn
```

*출력*

```text
$ pnx 10-if.pnx
negative
zero
big
```

#### 제약

(3) 두 갈래가 남기는 스택이 다르면 거절된다.

`10-if-unequal.pnx`

```pinax
def f n int gives int do n 0 lt if 1 2 else 3 end end
```

*거절*

```text
$ pnx 10-if-unequal.pnx
10-if-unequal.pnx:1:47: the two branches of this if leave different stacks
```

## 10.2 루프

(1) `loop 몸 end` 는 몸을 되풀이한다. 몸 안에서 다음 문장이 루프를 떠난다.

- `break .` — 루프를 떠나 `end` 뒤의 코드로 간다.
- `continue .` — 한 바퀴의 나머지를 건너뛰고 다음 바퀴를 시작한다.
- `break N .` `continue N .` — 안쪽에서 세어 `N` 번째 루프에 한다( `N` 은 1 이상의 정수 리터럴, 빼면 1). 안쪽 루프들은 한 번에 떠난다.

조건은 `if` 로 쓴다: `x 0 eq if break . end`. 문장은 마침표로 끝난다. `break` 와 `continue` 는 몇 번이든 쓸 수 있고, 루프의 몸에 바로 쓰거나 그 안의 갈래(`if` `else` `match` `or_else`) 안에 쓴다.

(2) 한 바퀴는 스택을 들어올 때와 같게 둬야 한다. 떠나는 자리마다 스택은 루프에 들어올 때와 같아야 한다. 루프의 결과가 필요하면 지역 변수에 둔다.

`10-loop.pnx`

```pinax
use io .
use str .
def digits n int gives int do            rem how many decimal digits
  1 to count_
  loop
    n 10 div to n
    n 0 eq if break . end
    count_ 1 add to count_
  end
  count_
end
12345 digits str.to_str io.println
def first_square_over limit int gives int do
  1 to i
  loop
    i i mul limit gt if break . end
    i 1 add to i
  end
  i
end
50 first_square_over str.to_str io.println
```

*출력*

```text
$ pnx 10-loop.pnx
5
8
```

(3) 루프에는 이름이 없다. 바깥 루프를 떠나려면 세는 수를 쓴다: `break 2 .` 는 두 루프를 한 번에 떠난다.

`10-loop-named.pnx`

```pinax
use io .
use str .
def find_pair target int gives str do      rem the first a, b in 1..9 with a*b = target
  1 to a
  0 to b
  loop
    1 to b
    loop
      a b mul target eq if break 2 . end       rem leaves both loops at once
      b 1 add to b
      b 9 gt if break . end
    end
    a 1 add to a
    a 9 gt if "none" return end
  end
  args a " x " b . cat
end
42 find_pair io.println
```

*출력*

```text
$ pnx 10-loop-named.pnx
6 x 7
```

(4) 자기를 떠나는 `break` 가 하나도 없는 루프는 끝나지 않는 루프다. 끝나지 않는 루프는 떠나는 갈래로 센다. 그래서 그 뒤에 결과를 적지 않아도 프로시저의 서명이 맞는다. 안쪽 루프의 `break .` 는 바깥 루프를 떠나는 것으로 세지 않지만, 안쪽에 쓴 `break 2 .` 는 센다.

`10-forever.pnx`

```pinax
use io .
use str .
def first_multiple n int, k int gives int do     rem a loop with no exit counts as leaving
  loop
    n k mod 0 eq if n return end
    n 1 add to n
  end
end
100 7 first_multiple str.to_str io.println
```

*출력*

```text
$ pnx 10-forever.pnx
105
```

## 10.3 고르기

(1) `값 match when 값… do 몸 end … otherwise 몸 end end` 는 맨 위의 `int`, 좁은 정수(7.6), `err` 나 `str` 를 내려 가지의 값과 견주고, 같은 첫 가지의 몸을 돈다. 가지는 `when` 으로 시작한다. 가지의 값은 리터럴, 이 소스의 `const`, 오류 코드(`err.range`), 또는 다른 모듈이 내보낸 상수나 실패 코드(`모듈.이름`, 8.14)다. 한 가지에 값이 여럿이면 `when` 뒤에 공백으로 늘어놓는다(쉼표나 괄호 없이). 값들 뒤의 `do` 가 몸을 연다. 맞는 가지가 없으면 `otherwise` 의 몸을 돈다. 가지마다 같은 스택을 남겨야 한다.

`10-case.pnx`

```pinax
use io .
const quit_code 9
def describe cmd str gives str do
  cmd match
    when "add" do "adds a line" end
    when "rm" "del" do "deletes a line" end
    otherwise "unknown command" end
  end
end
def level n int gives str do
  n match
    when 0 do "off" end
    when 1 do "low" end
    when quit_code do "quit" end
    otherwise "high" end
  end
end
"del" describe io.println
"mv" describe io.println
9 level io.println
```

*출력*

```text
$ pnx 10-case.pnx
deletes a line
unknown command
quit
```

#### 제약

(2) 같은 값이 두 가지에 있으면 거절된다.

`10-case-twice.pnx`

```pinax
def f n int gives int do n match when 1 do 10 end when 1 do 20 end otherwise 0 end end end
```

*거절*

```text
$ pnx 10-case-twice.pnx
10-case-twice.pnx:1:56: this value is already in an earlier branch of the case
```

(3) 모듈의 상수(`json.key`, `err.full` 같은 경로)는 가지의 값이 되지 못한다. 그런 값은 `eq` 로 견준다.

`10-case-path.pnx`

```pinax

```

*거절*

```text
$ pnx 10-case-path.pnx
10-case-path.pnx:2:40: a case value is a literal or the name of a const
```

#### 결함

(4) `otherwise` 가 없고 맞는 가지도 없으면 결함 `range` 다.

`10-case-nomatch.pnx`

```pinax

## 10.4 돌아가기

(1) `return` 은 프로시저를 그 자리에서 끝낸다. 그 자리의 스택은 결과와 맞아야 한다(9.2 (4)).

#### 제약

(2) `return` 은 정의(프로시저, 값이 되는 블록, 시험) 안에서만 쓴다. 정의 밖의 코드에 쓰면 거절된다.

return
```

*거절*

```text

```

## 10.5 블록

(1) `do … end` 는 **블록**(block)이다. 블록은 조합 낱말에 주는 것으로만 쓴다(`if` 의 몸처럼 낱말 없이 홀로 있는 `do … end` 는 없다). 값이 되는 블록은 `def` 로 적는다(`def 서명 do … end`, (2a)). 블록은 두 가지로 쓰인다.

- **끼워 넣는 블록** (inline block) — 조합 낱말(10.6)에 바로 준 블록. 그 자리에 펼쳐진다. 그래서 바깥의 지역 변수를 읽고 쓸 수 있고, 안에서 `return` 하면 바깥 낱말을 떠난다.
- **값이 되는 블록** (block value) — `def 서명 do … end` 로 적어 지역 변수에 넣거나, 블록을 받는 매개변수( `proc … end` 타입, 7.4)에 주는 것. 이름 없는 프로시저 하나가 되며 `call` 로 부른다. 바깥의 지역 변수를 보지 못한다(붙잡지 않는다). 전역은 본다.

(2) 끼워 넣는 블록은 `do` 바로 뒤에 `to 이름` 을 하나씩 이어 써서 레일이 내는 값(과 `each_index` 의 번호)을 지역 변수로 받는다. 이름은 값이 놓인 차례의 거꾸로 받는다: `do to i to s … end each_index` 는 `s` 가 원소, `i` 가 번호다(레일의 원소가 먼저 놓이므로 맨 위가 `i`). 값이 되는 블록의 서명은 프로시저의 서명과 같고, 이름들은 지역 변수가 된다.

`10-inline-locals.pnx`

```pinax
use io .
use str .
def total_over limit int gives int do
  0 to acc
  1 10 range do to i i limit gt if acc i add to acc end end each   rem the block sees acc and limit
  acc
end
5 total_over str.to_str io.println
```

*출력*

```text
$ pnx 10-inline-locals.pnx
30
```

`10-value-block.pnx`

```pinax
use io .
use str .
type Proc1 proc int gives int end def twice n int, f Proc1 gives int do n f call f call end
5 def x int gives int do x 3 mul end twice str.to_str io.println
def add_one int gives int do 1 add end
def demo gives int do
  def x int gives int do x add_one end to step     rem a block value in a local
  41 step call
end
demo str.to_str io.println
```

*출력*

```text
$ pnx 10-value-block.pnx
45
42
```

(2a) `ref 이름` 은 `def` 로 정의한 프로시저(이 소스의 것이든 쓰는 모듈이 내보낸 것이든) 자체를 값으로 준다(`ref by_len`, `ref geo.area`). 타입은 그 프로시저의 서명을 가진 `proc` 이고, `call` 은 그 프로시저를 부른다. 언어의 다른 낱말은 서명을 쓴 블록으로 준다. 타입만 쓴 입력은 스택에 남으므로(9.2 (2)) 블록의 몸은 그 낱말 하나다: `def str, str gives bool do str.starts_with end`.

`10-word-value.pnx`

```pinax
use io .
use str .
def by_len a str, b str gives bool do a str.len b str.len lt end
type Proc1 proc str, str gives bool end def shorter f Proc1, a str, b str gives str do a b f call if a else b end end
def demo do
  ref by_len to order                          rem the word by_len itself: word (str, str gives bool)
  args "shorter: " order "pear" "fig" shorter . cat io.println
  def str, str gives bool do str.starts_with end to starts    rem a word of the language, with its signature
  "banana" "ban" starts call if "starts with ban" io.println end
end
demo
```

*출력*

```text
$ pnx 10-word-value.pnx
shorter: fig
starts with ban
```

## 10.6 레일과 조합 낱말

(1) **레일**(rail)는 차례로 값을 내는 것이다. 레일은 값이 아니어서 지역 변수에 넣지 못하고, 바로 뒤의 조합 낱말이 받아야 한다. 둘이 합쳐 루프 하나가 된다. 레일을 내는 것은 다음과 같다.

| **레일** | **원소** |
|---|---|
| 배열, 목록의 이름 | 칸의 값(레코드면 줄). 목록은 길이까지. 큐, 버퍼, 찾아보기는 레일이 아니다 |
| 풀의 이름 | 살아 있는 줄, 칸의 차례로. `each` 에만(8.9 (3a)) |
| `lo hi range` | `lo` 부터 `hi` 앞까지의 `int` |
| `s sep str.split`, `s str.lines`, `s str.words`, `s str.chars` | `str` 뷰(16.1). `chars` 는 UTF-8 글자 하나씩 |
| `s str.bytes` | `u8`: 바이트(16.1) |
| `s pat ptn.matches`, `s re rex.matches`, `s re rex.split` | 맞은 부분(16.6, 16.7) |
| `s csv.fields` | 필드(16.9) |

(2) 조합 낱말은 다음과 같다. “블록” 열은 블록이 받고 주는 것이다.

| **낱말** | **블록** | **결과** |
|---|---|---|
| `each` | `(T)` | 없음 |
| `each_index` | `(T, i int)` | 없음 |
| `fold` | `(acc U, T gives U)` | `U`. 첫 값을 레일 앞에 둔다: `0 xs do … end fold` |
| `count` | `(T gives bool)` | `int` |
| `any` `all` | `(T gives bool)` | `bool`. 답이 정해지면 일찍 끝난다 |
| `first` | `(T gives bool)` | `T or fail`. 없으면 `err.not_found` |
| `sum` | 없음 | `int`(`dec N` 의 레일이면 `dec N`). 넘치면 결함 `overflow` |
| `minimum` `maximum` | 없음 | `int or fail`(`dec N` 도 같다). 빈 레일이면 `err.not_found` |
| `map_into` | `(T gives U)` | 뒤에 목적지. `or fail` |
| `filter_into` | `(T gives bool)` | 뒤에 목적지. `or fail` |
| `n times` | `()` | 없음. 레일 없이 `n` 번 |

(1a) **어댑터**(adapter)는 레일을 받아 레일을 준다. `skip N` 은 처음 N 개를 건너뛰고, `head N` 은 처음 N 개만 남기고, `step N` 은 N 개마다 하나(첫째부터)를, `rev` 는 끝에서 처음으로 훑는다. 레일 뒤에 쓴 차례대로 적용되어 어댑터가 몇이든 루프는 하나다: `scores skip 2 head 3` 은 셋째부터 다섯째까지, `scores head 3 skip 1` 은 둘째와 셋째다. `N` 은 `int` 를 하나 남기는 코드이고 쉼표, `do`, 다음 어댑터, `sum` `minimum` `maximum` 앞에서 끝난다. 루프 앞에서 한 번만 계산한다. `N` 이 음수(`step` 은 1 보다 작음)이면 결함 `range` 다. 어댑터는 `range`, 배열, 목록, `str.bytes` 처럼 길이를 아는 레일에만 쓰고, `step` 은 맨 끝에만 온다. 한 레일에 넷까지 쓴다. `each_index` 는 어댑터 뒤의 레일을 아직 세지 않는다. `each` `fold` `count` `any` `all` `first` `map_into` `filter_into` `sum` `minimum` `maximum` 이 받는다.

`10-rail-adapters.pnx`

```pinax
use io .
use str .
array scores int 8
assign scores (10, 20, 30, 40, 50, 60, 70, 80)
def show n int do " " io.print n str.to_str io.print end
0 10 range step 3 do to i i show end each "" io.println          rem 0 3 6 9
scores skip 2 head 3 do to s s show end each "" io.println       rem the third to the fifth
scores head 3 skip 1 do to s s show end each "" io.println       rem the second and the third
scores rev head 3 do to s s show end each "" io.println          rem from the last
0 20 range skip 2 3 add, head 4 step 2 do to i i show end each "" io.println   rem N may be code, ended by a comma
scores skip 1 head 3 sum show "" io.println                      rem 20 + 30 + 40
```

(1b) `filter` `map` `skip_while` `head_while` 은 바로 앞에 쓴 블록을 받는다(`do to s s 4 gt end filter`). 블록은 원소를 받아 `bool` 을 내고(`filter` 는 참인 원소만 남기고, `skip_while` 은 참인 동안 버리고, `head_while` 은 처음 거짓인 원소에서 훑기를 끝낸다), `map` 은 같은 타입의 값을 내어 원소 자리를 대신한다. 블록은 루프 안에서 원소마다 적은 차례로 돌고, 앞의 것이 버린 원소에는 돌지 않는다: 루프는 하나이고 저장소도 부름도 없다. 블록 어댑터는 길이를 모르는 레일(`str.words`, `str.lines` …)에도 쓴다. `skip` `head` `step` `rev` 는 이들보다 앞에 온다. 블록이 원소에 붙이는 이름은 마지막 블록의 이름과 같아도 된다.

`10-rail-block-adapters.pnx`

```pinax

scores do to s s 10 mul end map do to s s show end each "" io.println             rem every element times ten
scores do to s s 5 lt end skip_while do to s s show end each "" io.println        rem from the first that is not below 5
scores do to s s 8 lt end head_while do to s s show end each "" io.println        rem until the first that is not below 8
scores do to s s 4 gt end filter do to s s 100 mul end map sum show "" io.println  rem 3000
"one two three four" str.words do to w w str.len 3 gt end filter do to w w io.println end each
```

(3) `map_into` 와 `filter_into` 는 새 저장소를 만들지 않고 목적지에 쓴다. 목적지가 목록이면 끝에 `push` 하고 아무것도 주지 않는다. 목적지가 배열이면 0 번 칸부터 쓰고 쓴 칸의 수를 준다(`gives n int orfail`). 목적지가 차면 `err.full` 로 실패하고, 그때까지 쓴 것은 남는다. 목적지는 모음 매개변수여도 된다(9.9).

(4) 레일과 조합 낱말은 루프 하나를 이루고, `each`, `each_index`, `times` 의 블록 안에서 `break .` 는 그 루프를 떠나고 `continue .` 는 다음 원소로 간다. 레일은 멈추고 조합 낱말 뒤의 코드가 돈다. 루프를 떠나는 규칙이 그대로다: 스택은 블록이 시작할 때와 같고(10.2 (2)), 블록의 미룬 코드가 돈다(10.7). 블록 안의 `loop` 에 쓴 `break .` 는 그 루프를 떠난다. `break N .` 와 `continue N .` 는 이런 블록과 `loop` 를 모두 한 단계로 센다(10.2 (1)): 안쪽 블록의 연산 값들은 함께 떠난다. 모든 원소로 결과를 만드는 다른 조합 낱말의 블록은 일찍 떠나지 못하고, 그 블록을 건너 떠나지도 못한다.

## 10.7 미룬 코드

#### 구문

```ebnf
defer = "defer" { body } "end" ;
```

(1) `defer 코드 end` 는 둘러싼 블록을 떠날 때 돌 코드를 적는다. 블록은 낱말의 몸, 루프의 몸(한 바퀴마다), 조합 낱말의 `do` 블록(한 번 돌 때마다)이다. 그 블록을 떠나는 모든 길에서 돈다: 블록의 `end`, 루프의 한 바퀴 끝, `break`, `continue`, `return`, `or_return`, `or_fail`, `fail`. 여럿이면 적은 차례의 거꾸로 돈다. 결함으로 끝날 때는 돌지 않는다(그때는 상태가 핸들을 닫는다, 19.6).

`10-defer.pnx`

```pinax
use io .
use str .
buffer trace 256
def say s str do s trace append or_else to e end end
rem Every way out of a block runs its defers, the last written first.
def step n int or fail do
  "open " say
  defer "close " say end
  defer "flush " say end
  n 0 lt if err.range fail end
  "work " say
end
1 step or_else to e end
-1 step or_else to e "(failed) " say end
trace contents str.trim io.println
```

*출력*

```text
$ pnx 10-defer.pnx

```

(2) 미룬 코드가 소유 값을 소비하면(`m release`, `f file.close`) 그 값은 미룬 코드가 맡는다. 블록을 떠나는 모든 길에서 소비된 것으로 치므로 실패 경로마다 닫는 코드를 따로 쓸 일이 없다. 블록 안에서는 그 값을 빌려 쓸 수 있다.

`10-defer-owned.pnx`

```pinax

  1 50 range do to i
    mark to m
    defer m release end
    args "row " i ": " i i mul "\n" . cat report append or_fail
  end each

```

#### 제약

(3) `defer` 는 프로시저의 몸, 루프의 몸, `do` 블록에 바로 쓴다. `if`·`match`·`or_else` 의 가지 안이나 정의 밖에 쓰면 거절된다.

`10-defer-branch.pnx`

```pinax

(4) 미룬 코드는 스택을 받은 그대로 두고 아무것도 남기지 않는다. `return` `fail` `break` `continue` `to` `set` `loop` `do` `match` `defer` 와 `or_fail` `or_return` 을 쓸 수 없다. 실패하는 낱말은 그 안에서 `or_else` 로 다룬다.

(5) 미룬 코드가 맡은 소유 값을 블록 안에서 소비하면 거절된다.

#### 진단

| **조건** | **메시지** |
|---|---|
| 두 갈래의 스택이 다름 | `the two branches of this if leave different stacks` |
| 한 바퀴가 스택을 바꿈 | `one turn of a loop must leave the stack as it found it` |
| 루프 밖의 `break` `continue` | `break and continue belong inside a loop` |
| 결과를 주는 낱말의 블록 안의 `break` | `only the block of each, each_index or times is left early; this word gives a result made from every element` |
| `do` 블록 밖 루프로의 `break N .` | `a named loop outside this block is not left from inside it; break leaves the block` |
| 닿지 않는 코드 | `this code cannot be reached: the code before it always leaves` |
| `match` 의 같은 값 | `this value is already in an earlier branch of the case` |
| 펼쳐지는 블록이 스택을 바꿈 | `this block must leave the stack as it found it` |
| 정의 밖의 `return` | `return belongs inside a definition` |
| 상수가 아닌 가지의 값 | `a case value is a literal or the name of a const` |
| 레일이 아닌 것에 조합 낱말 | `only an array, a list or a pool is a rail (not a queue, a buffer or an index)` |
| 가지 안의 `defer` | `defer is written right in a word's body, a loop's body or a do block, not in a branch` |
| 정의 밖의 `defer` | `defer belongs inside a definition` |
| 미룬 코드가 스택을 바꿈 | `a defer leaves the stack as it found it` |
| 미룬 코드 안의 떠나는 낱말 | `a defer holds no return, fail, break, continue, to, set, loop, do, match or defer` |
| 미룬 코드 안의 `or_fail` `or_return` | `a defer does not leave the word; a failure in it is taken with or_else` |
| 미룬 코드가 맡은 값을 소비 | `a defer gives this owned value when the block is left; here it can only be lent` |
| 서명이 없는 값이 되는 블록에서 값이 모자람 | `a block without a signature takes nothing; a procedure of the program is given as ref NAME, any other word with the block's signature: def str, str gives bool do str.starts_with end` |
| 정의 전의 forward 프로시저를 값으로 | `a word declared with forward is given as a value only after its definition` |

## 10.8 문장의 끝

(1) 코드에 쓴 쉼표나 점(서명이나 `args … .` 안이 아닌 곳)은 **문장**(statement)을 끝낸다: 마지막 쉼표나 점 뒤의 코드다. 둘 다 스택을 바꾸지 않고, 둘 다 꼭 써야 하는 것은 아니다. 둘이 없는 코드는 전과 같은 뜻이다.

(2) 쉼표는 아무것도 기다리지 않는다: 다음 문장이 시작할 때 이 문장의 효과가 아직 진행 중일 수 있다.

(3) 점은 **장벽**(barrier)이다: 점 앞에서 시작한 모든 효과가 점 뒤의 무엇보다 먼저 끝난다. 처리기의 몫은 호스트가 `pinax_on_barrier`(19.4 (3))로 준 함수를 부르는 것이고, 호스트의 몫은 호스트 낱말이 붙들고 있는 것(표준 출력, 파일에 쓴 것)을 내보내고 뒤에서 시작한 일을 기다리는 것이다. 적재한 코드의 끝과 세션 줄의 끝은 점이다. 결함으로 끝나도 그렇다. 데이터로 적재한 소스에서 둘은 문장을 나눌 뿐 아무것도 부르지 않는다.

(4) 문장이 결과를 써야 하는 효과(읽기, 명령의 출력)는 닿은 자리에서 끝낸다. 두 점 사이에서 같은 자원에 대한 효과는 프로그램의 순서를 지키고, 다른 자원에 대한 효과는 겹칠 수 있다. 이 판은 모든 효과를 프로그램의 순서대로 돌린다. 겹침은 뒤의 판이 쓸 수 있는 여지다.

  args "square: " n n mul . cat io.println .

3 show ,
4 show .
```
