# 16 표준 모듈

(1) 표준 모듈은 처리기에 들어 있다. `use 모듈` 로 열고 `모듈.낱말` 로 쓴다(13.1). 표준 모듈의 낱말은 호스트의 허락 없이 바깥과 닿지 못한다 — 파일도, 시계도, 환경도 쓰지 않는다.

(2) 표준 모듈의 낱말은 새 저장소를 만들지 않는다. 결과는 다음 가운데 하나다.

- 받은 바이트를 가리키는 뷰. 복사가 없다.
- 구역(12.2)에 새로 쓴 바이트의 뷰.
- 부른 쪽이 준 버퍼에 붙인 바이트. 이런 낱말은 이름이 `_into` 로 끝나거나 버퍼를 받고, 자리가 모자라면 `err.full` 로 실패한다.

## 16.1 str — 문자열

(1) 모듈 `str` 은 문자열을 바이트로 다룬다. 바이트의 번호는 0 부터 센다. 글자 단위로 다루는 낱말 (`chars` `char_count` `is_utf8`)만 UTF-8 로 읽는다. 대소문자 바꾸기(`upper` `lower`)는 ASCII 만 바꾼다.

(2) 구분자나 찾는 것을 받는 자리(`sep`, `part`)에는 `str` 이나 문자 하나(`int`, 6.5)를 줄 수 있다.

### 16.1.1 보기와 자르기

(3) 결과는 모두 받은 문자열의 뷰다.

| **낱말** | **서명** | **뜻** |
|---|---|---|
| `len` `is_empty` | `(str gives int)` `(str gives bool)` | 바이트 수, 비었는가 |
| `take` `skip` | `(s str, n int gives str)` | 앞의 `n` 바이트, 앞의 `n` 바이트를 뺀 나머지. 모자라면 있는 만큼 |
| `take_last` `skip_last` | `(s str, n int gives str)` | 뒤의 `n` 바이트, 뒤의 `n` 바이트를 뺀 앞 |
| `slice` | `(s str, start int, n int gives str)` | `start` 부터 `n` 바이트. 범위 밖이면 결함 `range` |
| `trim` `trim_left` `trim_right` | `(str gives str)` | 앞뒤의 공백(스페이스, 탭, CR, LF)을 뺀 뷰 |
| `cut` | `(s str, sep gives str, str)` | 처음 `sep` 의 앞과 뒤. `sep` 이 없으면 `s` 와 빈 글 |
| `try_cut` | `(s str, sep gives str, str or fail)` | `cut` 과 같으나 `sep` 이 없으면 `err.not_found` |
| `span` | `(s str, class int gives str, str)` | 앞에서 그 갈래의 바이트가 이어진 부분과 나머지 |

(4) `span` 의 갈래는 상수 `str.digit` `str.alpha` `str.alnum` `str.space` `str.upper_case` `str.lower_case` `str.hex_digit` `str.punct` 다(ASCII).

`16-str-views.pnx`

```pinax
use io
use str
word show (label str, s str) cat (label, " [", s, "]") io.println end
word demo ()
  "  key = value  " to line
  "trim" line str.trim show
  "trim_left" line str.trim_left show
  "take 5" "hello, world" 5 str.take show
  "skip 7" "hello, world" 7 str.skip show
  "take_last 5" "hello, world" 5 str.take_last show
  "skip_last 7" "hello, world" 7 str.skip_last show
  "take 99" "short" 99 str.take show                 rem n beyond the end: what is there
  "slice 7 3" "hello, world" 7 3 str.slice show
  "key = value" " = " str.cut to (k, v)
  "cut, before" k show
  "cut, after" v show
  "a=b=c" '=' str.cut to (k2, v2)                    rem the separator may be a character
  "cut at a char" v2 show
  "2026-10-15" str.digit str.span to (year, rest)
  "span digits" year show
  "span rest" rest show
end
demo
```

*출력*

```text
$ pnx 16-str-views.pnx
```

(5)

|---|---|---|

### 16.1.3 새 글 만들기

(6) 결과는 구역에 쓴 새 바이트다. 구역이 모자라면 결함 `full` 이다(12.2). 수로 읽는 낱말은 실패할 수 있다.

| **낱말** | **서명** | **뜻** |
|---|---|---|
| `upper` `lower` | `(str gives str)` | ASCII 대소문자 바꾸기 |
| `repeat` | `(s str, n int gives str)` | `n` 번 이은 글. `n` 이 음수면 결함 `range` |
| `replace` | `(s str, old str, new str gives str)` | 모든 `old` 를 `new` 로 |
| `pad_left` `pad_right` | `(s str, width int gives str)` | 스페이스로 채워 `width` 바이트로. 이미 길면 그대로. `width` 가 음수이거나 232 이상이면 결함 `range` |
| `to_str` | `(int gives str)` | 십진 글. `dec(N)` 은 점 아래 `N` 자리까지(7.5) |
| `to_dec` | `(s str, N gives dec(N) or fail)` | 십진 소수로 읽기: 부호, 숫자, 점과 그 아래 `N` 자리까지(`N` 은 상수). 자리가 더 많거나 다른 꼴이면 `err.format` |
| `to_int` | `(str gives int or fail)` | 십진으로 읽기. 부호 하나와 숫자만 받는다(공백도 안 된다). 아니거나 64 비트를 넘으면 `err.format` |
| `to_int_base` | `(s str, base int gives int or fail)` | 2–36 진법으로 읽기. 그 밖의 `base` 는 결함 `range` |

`16-str-make.pnx`

```pinax
use io
use str
"Hello, World" str.upper io.println
"Hello, World" str.lower io.println
"ab" 3 str.repeat io.println
"one two one" "one" "1" str.replace io.println
cat ("[", "7" 4 str.pad_left, "]") io.println
cat ("[", "7" 4 str.pad_right, "]") io.println
-42 str.to_str io.println
"ff" 16 str.to_int_base or_else (e) -1 end str.to_str io.println
"  12" str.to_int or_else (e) -1 end str.to_str io.println
"12x" str.to_int or_else (e) -1 end str.to_str io.println
"한글" str.len str.to_str io.println
"한글" str.char_count str.to_str io.println
"\xff" str.is_utf8 if "utf-8" else "not utf-8" end io.println
```

*출력*

```text
$ pnx 16-str-make.pnx

hello, world
ababab
1 two 1
[   7]
[7   ]

-1
```

### 16.1.4 줄기와 버퍼에 쓰기

(7) 줄기(10.6)를 내는 낱말:

- `s sep str.split` — `sep` 으로 가른 조각. 빈 조각도 낸다. `sep` 은 `str` 이거나 바이트 하나( `u8` 상수, 보통 문자 리터럴)다. `cut` 과 `try_cut` 의 `sep` 도 같다.
- `s str.words` — 공백으로 가른 조각. 빈 조각은 내지 않는다.
- `s str.lines` — 줄. 줄 끝의 LF 와 CR LF 는 빼고 낸다.
- `s str.bytes` — 바이트( `u8` ).
- `s str.chars` — UTF-8 글자 하나씩의 뷰( `str` ).

(8) 버퍼에 쓰는 낱말:

- `sep buf 줄기 str.join_into` — 줄기의 조각을 `sep` 으로 이어 버퍼에 붙인다( `or fail` ). 줄기는 바로 뒤의 낱말이 받아야 하므로 줄기를 맨 뒤에 둔다.
- `s old new buf str.replace_into` — 바꾼 글을 버퍼에 붙이고 바꾼 횟수를 준다( `gives n int or fail` ).

`16-str-stems.pnx`

```pinax
use io
use str
"one two  three" str.words do (w str) cat ("<", w, ">") io.print end each
"" io.println
"a,b,,c" ',' str.split do (w str) cat ("<", w, ">") io.print end each
"" io.println
text END
first line
second line
END
str.lines do (l str) cat ("line: ", l) io.println end each
"hi" str.bytes do (b u8) b str.to_str io.print " " io.print end each
"" io.println
"가a!" str.chars do (c str) cat ("<", c, " ", c str.len, ">") io.print end each
"" io.println
buffer out 64
", " out "x y z" str.words str.join_into or_else (e) end
out contents io.println
out clear
word swap_dashes () "a-b-c" "-" "+" out str.replace_into or_else (e) 0 end to n  cat (out contents, " (", n, " replaced)") io.println end
swap_dashes
```

*출력*

```text
$ pnx 16-str-stems.pnx
<one><two><three>
<a><b><><c>
line: first line
line: second line
104 105 
<가 3><a 1><! 1>
```


## 16.2 fmt — 수를 글로

(1) `cat` 은 `int` 를 십진으로 넣는다(9.8). 다른 모양은 모듈 `fmt` 의 낱말로 `str` 을 만든다. 형식을 적는 작은 언어(`%08x` 같은 것)는 없다. 결과는 구역에 쓴다.

| **낱말** | **서명** | **뜻** |
|---|---|---|
| `hex` `bin` | `(n gives str)` | 십육진(소문자), 이진. `n` 은 `int` 나 좁은 정수(7.6): `int` 의 음수는 64 비트 2 의 보수로, 좁은 정수는 그 폭의 비트로 |
| `hex_pad` | `(n, width int gives str)` | 십육진을 앞에 0 을 채워 `width` 자리로. `n` 은 `hex` 와 같다 |
| `zero_pad` | `(n, width int gives str)` | 십진을 앞에 0 을 채워 `width` 자리로. 부호도 자리를 차지한다. `n` 은 `int` 나 좁은 정수(`u64` 는 부호 없이) |
| `append_hex` | `(n, buf or fail)` | 십육진을 버퍼에 붙인다. `n` 은 `hex` 와 같다 |

십진은 `str.to_str`, 버퍼에 붙이는 십진은 `append_int`(15.3)다. `hex_pad` 와 `zero_pad` 의 `width` 가 음수이거나 232 이상이면 결함 `range`, 구역이 모자라면 결함 `full` 이다.

`16-fmt.pnx`

```pinax
use io
use fmt
255 fmt.hex io.println
5 fmt.bin io.println
255 8 fmt.hex_pad io.println
7 3 fmt.zero_pad io.println
-7 3 fmt.zero_pad io.println
buffer out 32
"0x" out append or_else (e) end
48879 out fmt.append_hex or_else (e) end
out contents io.println
```

*출력*

```text
$ pnx 16-fmt.pnx
ff
101
000000ff
007
-07
0xbeef
```

(2) `fmt` 의 낱말은 `int` 를 받는다. 다른 타입의 값은 거절된다. `dec(N)` 은 `str.to_str` 과 `cat` 이 적는다(7.5).

`16-fmt-type.pnx`

```pinax

```

*거절*


## 16.3 hash — 해시

(1) 모듈 `hash` 는 바이트의 해시를 `int` 로 준다. 암호에 쓰는 해시는 없다 — 그런 것은 호스트 낱말로 준다.

| **낱말** | **서명** | **뜻** |
|---|---|---|
| `crc32` | `(str gives u32)` | CRC-32 (IEEE 802.3, zlib 과 같음) |
| `fnv1a` | `(str gives u64)` | 64 비트 FNV-1a |
| `hash64` | `(str gives u64)` | 키가 0 인 SipHash-2-4 |

`16-hash.pnx`

```pinax
use io
use hash
use fmt
"hello" hash.crc32 fmt.hex io.println
"hello" hash.fnv1a fmt.hex io.println
"hello" hash.hash64 fmt.hex io.println
```

*출력*

```text
$ pnx 16-hash.pnx
3610a686
a430d84680aabd0b
8cc15d5db2f752b9
```

(1a) 검사 값: 빈 글의 `crc32` 는 0 이고, `"123456789"` 의 `crc32` 는 `cbf43926` 이다(CRC-32 의 표준 검사 값). 빈 글의 `fnv1a` 는 FNV 의 시작값 `cbf29ce484222325` 다. 다른 처리기는 같은 값을 내야 한다.

`16-hash-vectors.pnx`

```pinax
use io
use str
use fmt
use hash
"" hash.crc32 str.to_str io.println
"123456789" hash.crc32 fmt.hex io.println
"" hash.fnv1a fmt.hex io.println
"" hash.hash64 fmt.hex io.println
```

*출력*

```text
$ pnx 16-hash-vectors.pnx
0
cbf43926
cbf29ce484222325
1e924b9d737700d7
```

#### 제약

(2) `str` 가 아닌 값의 해시는 거절된다. 수의 해시는 먼저 바이트로 만든다(16.5).

`16-hash-type.pnx`

```pinax

```

*거절*

## 16.4 encode — 바이트를 글로

(1) 모듈 `encode` 의 낱말은 모두 `(s str, buf or fail)` 이다. 바꾼 결과를 버퍼에 붙이고, 자리가 모자라면 `err.full`, 입력의 모양이 틀리면 `err.format` 으로 실패한다.

| **낱말** | **뜻** |
|---|---|
| `base64_encode` `base64_decode` | RFC 4648 의 Base64. 풀 때 끝의 `=` 는 없어도 된다 |
| `hex_encode` `hex_decode` | 바이트마다 십육진 두 자리. 쓸 때 소문자, 읽을 때 대소문자 모두 |
| `url_encode` `url_decode` | RFC 3986 의 퍼센트 부호화. 문자, 숫자, `-` `.` `_` `~` 밖의 바이트를 `%XX` 로 |

`16-encode.pnx`

```pinax
use io
use encode
buffer out 64
word show (label str) cat (label, " ", out contents) io.println  out clear end
word demo (or fail)
  "Pinax!" out encode.base64_encode or_fail  "base64" show
  "UGluYXgh" out encode.base64_decode or_fail  "decoded" show
  "\x00\xff" out encode.hex_encode or_fail  "hex" show
  "a b&c=d/é" out encode.url_encode or_fail  "url" show
  "a%20b" out encode.url_decode or_fail  "url decoded" show
end
demo or_else (e) cat ("failed: ", e err_text) io.println end
```

*출력*

```text
$ pnx 16-encode.pnx
base64 UGluYXgh
decoded Pinax!
hex 00ff
url a%20b%26c%3Dd%2F%C3%A9
url decoded a b
```

`16-encode-bad.pnx`

```pinax
use io
use encode
buffer out 16
"zz" out encode.hex_decode or_else (e) cat ("hex_decode: ", e err_text) io.println end
"ab*c" out encode.base64_decode or_else (e) cat ("base64_decode: ", e err_text) io.println end
```

*출력*

```text
$ pnx 16-encode-bad.pnx

```

#### 제약

(2) `str` 와 버퍼가 아닌 값을 주면 거절된다. 수를 바꾸려면 먼저 글이나 바이트로 만든다(16.1, 16.5).

`16-encode-type.pnx`


| `str` 와 버퍼가 아닌 값 | `this word takes a str and a buffer, as: s buf encode.base64_encode` |

## 16.5 bytes — 이진 자료

(1) 모듈 `bytes` 는 수와 글을 정해진 바이트 모양으로 버퍼에 쓰고, 바이트에서 읽는다. 쓰는 낱말은 `(값, buf or fail)` 이고(자리가 모자라면 `err.full`, 아무것도 쓰지 않는다), 읽는 낱말은 `(s str gives 값, 나머지str or fail)` 이다(바이트가 모자라거나 모양이 틀리면 `err.format`).

(2)

| **낱말** | **바이트** |
|---|---|
| `put_u8` `put_u16` `put_u32` `put_u64`  
`put_i8` `put_i16` `put_i32` `put_i64` | 이름이 말하는 타입의 값(7.6; `put_i64` 는 `int`). 작은 끝이 먼저 |
| 같은 이름 뒤에 `_be` | 큰 끝이 먼저 |
| `get_u8` … `get_i64`, `get_u16_be` … | 위의 짝. 이름이 말하는 타입의 값을 준다(`get_i64` 는 `int`) |
| `put_varint` `get_varint` | LEB128. 값을 부호 없는 64 비트로 보고 7 비트씩 쓴다(음수는 10 바이트) |
| `put_str` `get_str` | 길이(varint) 다음에 바이트 |

`16-bytes.pnx`

```pinax

  258 u16 out bytes.put_u16_be or_fail         rem big end first: 01 02

  s3 bytes.get_str or_fail to (d, s4)
```

### 16.5.1 레코드

(3) `줄 buf bytes.pack` 은 레코드(8.8)의 줄 하나를 필드의 차례대로 버퍼에 붙인다(`or fail`). `s 줄 bytes.unpack` 은 바이트에서 필드를 읽어 줄에 넣고 나머지 뷰를 준다(`gives str or fail`). `줄 bytes.packed_size` 는 `pack` 이 쓸 바이트 수다.

(4) 필드의 바이트: 정수 폭은 그 폭으로(레코드에 `big_endian` 이 있으면 큰 끝이 먼저, 없으면 작은 끝이 먼저), `int` 는 8 바이트, `bool` 은 1 바이트, `varint` 는 LEB128, `str(N)` 은 길이(varint) 다음에 바이트, 줄을 담는 필드는 담긴 수(varint).

(5) `pack` 이 실패하면 버퍼는 부르기 전의 길이로 돌아간다. `unpack` 은 모든 필드를 읽을 수 있을 때만 줄에 쓴다 — 실패하면 줄은 그대로다.

`16-bytes-pack.pnx`

```pinax

end

  big_endian
  id u16

  dump

  1 items idx to b
  out contents b bytes.unpack or_fail to rest
  cat (b item.id, " ", b item.name, " ", b item.delta, ", rest ", rest str.len) io.println
  "\x01\x02\x05" b bytes.unpack or_else (e) cat ("short input: ", e err_text) io.println "" end drop
  cat ("the row is unchanged: ", b item.name) io.println
  out clear
  0 wires idx to w
```

## 16.6 ptn — 작은 패턴

(1) 모듈 `ptn` 은 Lua 의 패턴과 같은 크기의 **패턴**(pattern)으로 문자열을 찾고 바꾼다. 갈래 선택(`|`), 묶음의 되풀이, 역참조는 없다. 더 큰 문법은 `rex`(16.7)가 맡는다.

### 16.6.1 패턴의 글

(2) 패턴은 다음 항목의 나열이다. 바이트 단위로 맞춘다.

| **항목** | **맞는 것** |
|---|---|
| 보통 글자 | 그 바이트 |
| `.` | 아무 바이트 |
| `%a` `%d` `%l` `%u` `%s` `%w` `%x` `%p` `%c` | 글자, 숫자, 소문자, 대문자, 공백, 글자나 숫자, 십육진 숫자, 구두점, 제어 문자(ASCII). 대문자로 쓰면 그 밖 |
| `%` 와 글자·숫자가 아닌 것 | 그 바이트 자체(`%.` `%%` `%(`) |
| `[…]` `[^…]` | 집합과 그 여집합. 안에 `a-z` 범위와 `%` 갈래를 쓴다. 여는 `[` 나 `[^` 바로 뒤의 `]` 는 글자다 |
| 항목 뒤의 `*` `+` `-` `?` | 0 번 이상(길게), 1 번 이상(길게), 0 번 이상(짧게), 0 번이나 1 번 |
| `( … )` | 갈무리(capture). 아홉까지 |
| 처음의 `^`, 끝의 `$` | 글의 처음, 글의 끝에 붙임 |

`16-ptn-classes.pnx`

```pinax
use io
use ptn
"a1 B2_c3!" "%a" "." ptn.replace io.println     rem letters
"a1 B2_c3!" "%d" "." ptn.replace io.println     rem digits
"a1 B2_c3!" "%W" "." ptn.replace io.println     rem not letter or digit
"a1 B2_c3!" "[%u_]" "." ptn.replace io.println  rem a set: upper case or _
"aaab" "a-b" "<%0>" ptn.replace io.println      rem - is the shortest repetition
"color colour" "colou?r" "#" ptn.replace io.println
```

*출력*

```text

a. B._c.!
a1.B2.c3.
a1 .2.c3!
<aaab>
# #
```

### 16.6.2 낱말

(3)

| **낱말** | **서명** | **뜻** |
|---|---|---|
| `is_match` | `(s str, pat gives bool)` | 어디든 맞는 곳이 있는가 |
| `match` | `(s str, pat gives str or fail)` | 처음 맞은 부분의 뷰. 없으면 `err.not_found` |
| `capture` | `(n int gives str)` | 마지막 `match` 의 갈무리 `n` (1–9). 0 은 맞은 전체 |
| `matches` | 줄기 | 맞은 부분을 차례로. 겹치지 않게 다음 자리에서 다시 찾는다 |
| `replace` | `(s str, pat, rep str gives str)` | 맞은 곳을 모두 `rep` 로 바꾼 새 글. `rep` 의 `%0`–`%9` 는 갈무리, `%%` 는 `%` |

(4) `^` 로 시작하는 패턴은 처음 자리에서만 맞춰 본다. 그래서 `matches` 와 `replace` 도 많아야 한 번 맞는다.

(5) `capture` 가 읽는 마지막 맞음은 실행(작업)마다 따로 있다. 다른 `match` 를 부르면 바뀐다. 호스트가 시작한 실행은 맞음이 없는 채로 시작한다: 지난 실행의 맞음은 보이지 않는다. 그 갈무리는 지난 실행이 맞춘 글의 뷰이고, 그 글은 이미 없을 수 있기 때문이다.

`16-ptn.pnx`

```pinax
use io
use ptn
const date "(%d+)-(%d+)-(%d+)"
word yes (b bool gives str) b if "true" else "false" end end
"abc 123" "%d+" ptn.is_match yes io.println
word demo ()
  "on 2026-10-15 ok" date ptn.match or_else (e) "?" end io.println    rem the whole match
  cat (1 ptn.capture, "/", 2 ptn.capture, "/", 3 ptn.capture) io.println
  "key = value" "^(%w+)%s*=%s*(%w+)$" ptn.match or_else (e) "?" end drop
  cat (2 ptn.capture, " <- ", 1 ptn.capture) io.println
end
demo
"x=1, y=22, z=333" "%a=%d+" ptn.matches do (m str) cat ("[", m, "]") io.print end each
"" io.println
"2026-10-15" date "%3.%2.%1 (%0)" ptn.replace io.println
"  trim me  " "^%s*(.-)%s*$" "%1" ptn.replace io.println
"aaa" "^a" "-" ptn.replace io.println              rem ^ anchors: one match, at the start
```

*출력*

```text

true
2026-10-15
2026/10/15
value <- key
[x=1][y=22][z=333]
15.10.2026 (2026-10-15)
trim me
-aa
```

## 16.7 rex — 정규 표현식

(1) 모듈 `rex` 는 **정규 표현식**(regular expression)으로 찾고 바꾼다. 맞추는 방법은 되돌아가지 않는 방식이라, 걸리는 시간이 글의 길이와 패턴의 크기의 곱을 넘지 않는다. 패턴을 적을 때는 날 문자열(6.5)을 쓴다 — 보통 문자열에서 `"\d"` 는 모르는 이스케이프로 거절되고, `"\b"` 는 백스페이스가 된다.

(2) `use rex` 가 있는 소스에서는 타입 이름 `regex` 가 보인다. `regex` 값은 만든 뒤에 고치지 못하는 패턴 프로그램이다. 지역 변수, 인자, 결과에만 쓴다.

### 16.7.1 패턴의 글

(3)

| **모양** | **뜻** |
|---|---|
| 글자 | 그 바이트들. 여러 바이트 글자는 그 바이트열 |
| `.` | UTF-8 글자 하나. `(?s)` 가 없으면 줄바꿈은 뺀다 |
| `[abc]` `[a-z]` `[^…]` | 글자 집합. 범위는 ASCII. 부정 집합은 UTF-8 글자 하나를 먹는다 |
| `\d` `\w` `\s` `\D` `\W` `\S` | 숫자, 낱말 글자, 공백과 그 부정(ASCII) |
| `*` `+` `?` `{n}` `{n,}` `{n,m}` | 되풀이(길게). 뒤에 `?` 를 붙이면 짧게 |
| `a\|b` | 고르기. 왼쪽이 먼저 |
| `( … )` `(?: … )` | 묶음(갈무리함), 묶음(갈무리 안 함) |
| `^` `$` | 글의 처음과 끝. `(?m)` 이면 줄마다 |
| `\b` `\B` | 낱말 경계와 그 부정(ASCII) |
| `\n` `\t` `\r` `\f` `\v` `\0` `\xNN` | 그 바이트 |
| `\` 와 그 밖의 글자 | 그 글자(`\.` `\*` `\\`) |
| `\zs` `\ze` | 맞은 부분의 시작과 끝을 여기로 좁힌다. 패턴 전체는 그대로 맞아야 한다 |
| `(?i)` `(?m)` `(?s)` | 패턴의 맨 앞에만. 대소문자 무시(ASCII), 줄마다의 닻, `.` 이 줄바꿈도 |

역참조, 둘러보기, 유니코드 속성, 이름 붙은 묶음은 없다.

(4) 빈 글에 맞을 수 있는 몸을 되풀이하는 패턴(`(a*)*` 같은 것)은 Perl 이나 Python 과 갈무리의 결과가 다를 수 있다.

### 16.7.2 낱말

(5) `re` 는 `regex` 값이다. “맞은 부분” 은 `\zs` `\ze` 로 좁힌 범위다.

| **낱말** | **서명** | **뜻** |
|---|---|---|
| `rx` | `(pat gives regex)` | 적재 때 패턴을 프로그램으로 만든다. `pat` 은 리터럴이나 `const` |
| `compile` | `(pat str gives regex or fail)` | 돌 때 만든다. 틀린 패턴은 `err.format`. 프로그램은 구역에 놓인다 |
| `is_match` | `(s str, re gives bool)` | 맞는 곳이 있는가 |
| `match` | `(s str, re gives str or fail)` | 처음 맞은 부분. 없으면 `err.not_found` |
| `cut_match` | `(s str, re gives str, str, str or fail)` | 처음 맞은 부분의 앞, 그 부분, 뒤 |
| `matches` | 줄기 | 맞은 부분을 차례로. 블록은 맞은 전체와 묶음마다 `str` 매개변수를 받는다 |
| `split` | 줄기 | 맞은 부분으로 가른 조각 |
| `with_match` | `(s str, re, 블록 or fail)` | 처음 맞은 것으로 블록을 한 번 돌린다. 없으면 `err.not_found` |
| `replace` | `(s str, re, rep str gives str)` | 모두 바꾼 새 글. `rep` 의 `\0`–`\9` 는 묶음 |
| `replace_into` | `(s str, re, rep str, buf gives int or fail)` | 바꾼 글을 버퍼에 붙이고 바꾼 횟수를 준다 |
| `replace_by` | `(s str, re, buf, 블록 gives int or fail)` | 맞은 곳마다 블록이 준 글로 바꿔 버퍼에 붙인다 |

(6) `matches` `split` `replace` 는 다음 자리에서 다시 찾을 때도 글 전체를 본다. 그래서 `^` 와 `\b` 는 그 자리 앞의 바이트를 안다.

`16-rex.pnx`

```pinax
use io
use str
use rex
const pair r"(\w+)=(\d+)"
word yes (b bool gives str) b if "true" else "false" end end
word total (line str gives n int)               rem groups arrive as block parameters
  0 to n
  line pair rex.rx rex.matches do (whole str, key str, value str)
    n value str.to_int or_else 0 end add to n
  end each
  n
end
word demo ()
  cat ("sum ", "id=7, x=20; name=kim, n=3" total) io.println
  "abc 123" r"\d+" rex.rx rex.is_match yes io.println
  "on 2026-10-15 ok" r"(\d+)-(\d+)" rex.rx rex.match or_else (e) "?" end io.println
  "key: value" r":\s*" rex.rx rex.cut_match or_else (e) "" "" "" end to (before, m, after)
  cat ("[", before, "|", m, "|", after, "]") io.println
  "from 2026-10-13 to 2026-11-02" r"(\d{4})-(\d{2})-(\d{2})" rex.rx r"\3/\2/\1" rex.replace io.println
  "a , b;c ,d" r"\s*[,;]\s*" rex.rx rex.split do (part str) cat ("<", part, ">") io.print end each
  "" io.println
  "가나다" r"." rex.rx rex.matches do (ch str) cat ("<", ch, ">") io.print end each   rem . is one UTF-8 character
  "" io.println
  "foobar" r"foo\zsbar" rex.rx rex.match or_else (e) "?" end io.println              rem \zs: the match starts here
```

## 16.8 json — JSON

(1) 모듈 `json` 은 JSON(RFC 8259) 글을 나무로 만들지 않고 한 방향으로 읽고 쓴다. 읽기는 토큰 하나씩, 쓰기는 버퍼에 바로 한다.

### 16.8.1 읽기

(2) `s json.next` 는 `s` 의 첫 토큰을 읽어 `(kind int, value str, rest str)` 를 준다(`or fail`). 끝에 이르면 `err.not_found`, 토큰이 아닌 것을 만나면 `err.format` 으로 실패한다. 토큰 사이의 공백, 쉼표, 쌍점은 건너뛴다. 괄호의 짝이나 쉼표의 자리 같은 문법의 짜임은 검사하지 않는다.

(3) `kind` 는 아래 상수다. 문자열의 `value` 는 따옴표를 뗀 글이고, 이스케이프가 있으면 풀어서 구역에 쓴 글이다. 수의 `value` 는 적힌 그대로의 글이다.

| **상수** | **토큰** |
|---|---|
| `json.object` `json.object_end` | `{` `}` |
| `json.array` `json.array_end` | `[` `]` |
| `json.key` | 쌍점이 뒤따르는 문자열 |
| `json.string` | 그 밖의 문자열 |
| `json.number` | 수 |
| `json.boolean` `json.null` | `true` `false`, `null` |

(4) `s json.skip` 은 값 하나(객체나 배열이면 그 안 전부)를 건너뛰고 나머지를 준다(`gives str or fail`).

`16-json-read.pnx`

```pinax

  k json.key eq if "key" return end
  k json.string eq if "string" return end
  k json.number eq if "number" return end
  k json.boolean eq if "boolean" return end
  k json.null eq if "null" return end
  k json.object eq k json.array eq or if "open" return end
  "close"
end
word tokens (s str)
  s to rest
  loop
    rest json.next or_else (e) break end to (kind, value, rest)
    cat (kind kind_name, " ", value) io.println
  end
end
text END
{"name": "kim", "tags": [1, -2.5e3, true, null], "note": "café"}
END
tokens
```

*출력*

```text

```

(5) 쓰는 낱말은 모두 버퍼에 붙이고, 자리가 모자라면 `err.full` 로 실패한다. 쉼표는 낱말이 알아서 넣는다.

| `put_bool` | `(b bool, buf or fail)` |

### 16.8.3 경로, 검증, 모양

(5a) 말 넷이 글 전체를 RFC 8259 의 엄격한 문법으로 읽는다(위의 토큰 읽기는 흐름을 읽으려고 일부러 느슨하다). 글이 값 하나와 공백뿐이면 유효하다. 64 단보다 깊은 중첩은 여기서 유효하지 않다. 경로는 값을 가리킨다: 점으로 이은 이름, 괄호 안의 번호, 점이나 괄호가 든 이름은 `["a.b"]` (`user.langs[1]`, `[0].id`). 빈 경로는 글 전체다. 이름은 키의 이스케이프를 푼 글과 견준다. 값을 찾으면 거기서 읽기를 멈추므로, 나머지 글은 검사하지 않는다.

| **말** | **서명** | **뜻** |
|---|---|---|
| `valid` | `(s str gives bool)` | `s` 가 JSON 값 하나와 그 둘레의 공백뿐인지 |
| `at` | `(path str, s str gives kind int, value str or fail)` | `s` 에서 `path` 가 가리키는 값: 종류(위의 상수, `json.key` 는 없다)와 글. 글은 `json.next` 가 주는 그대로이되, 객체와 배열은 적힌 대로 통째로 주어 `json.next` 나 `json.at` 으로 다시 읽을 수 있다. 그런 값이 없으면(없는 이름, 끝을 넘은 번호, 배열에 이름을 묻거나 객체에 번호를 묻기) `err.not_found`, 경로가 잘못됐거나 읽은 곳의 글이 잘못됐으면 `err.format` |
| `minify` | `(s str, b buffer or fail)` | 토큰 사이의 공백을 뺀 `s` 를 덧붙인다. `s` 가 유효하지 않으면 `err.format`, 자리가 모자라면 `err.full`(버퍼는 그대로) |
| `pretty` | `(s str, indent int, b buffer or fail)` | 멤버와 요소마다 한 줄, 한 단에 `indent` 칸(0에서 16, 그 밖은 결함), 키 뒤에 `": "` 로 덧붙인다. 빈 객체와 배열은 그대로 둔다. 실패는 `minify` 와 같다 |

`16-json-path.pnx`

```pinax

  text END
{"user": {"name": "kim", "langs": ["ko", "en"], "age": 31}, "ok": true}

  cat ("valid: ", fine) io.println
  "user.name" doc json.at or_fail io.println drop     rem a value by its path: the text, and its kind
  "user.langs[1]" doc json.at or_fail io.println drop
  "user.langs" doc json.at or_fail to langs drop      rem an array is given as written, to be read again
  "[0]" langs json.at or_fail io.println drop
  "user.size" doc json.at or_else (e) cat ("no value: ", e err_text) io.println 0 "" end drop drop
  doc 2 shown json.pretty or_fail                     rem laid out, two blanks to a level
  shown contents io.println
end
```


### 16.8.4 레코드

(6) `줄 buf json.pack` 은 레코드의 줄을 필드 이름을 키로 한 객체로 붙인다. `s 줄 json.unpack` 은 객체를 읽어 이름이 같은 필드에 넣고 객체 뒤의 나머지를 준다. 모르는 키의 값은 건너뛴다. 수는 정수만 받고, 필드의 폭에 맞아야 한다. `dec(N)` 필드는 점 아래 `N` 자리까지의 수를 받고, `N` 자리를 모두 써서 적는다(7.5). `null` 은 받지 않는다. 모든 것이 맞을 때만 줄에 쓴다 — 실패하면(`err.format`) 줄은 그대로다.

## 16.9 csv — CSV

(1) 모듈 `csv` 는 RFC 4180 꼴의 CSV 를 읽고 쓴다. 필드는 쉼표로 가르고, 쉼표, 따옴표, 줄바꿈을 담은 필드는 따옴표로 싸며, 안의 따옴표는 두 번 적는다.

(2) `s csv.fields` 는 줄 하나의 필드를 차례로 내는 줄기(10.6)다. 따옴표로 싼 필드는 따옴표를 떼고 겹친 따옴표를 풀어서 낸다. 닫히지 않은 따옴표는 남은 글 그대로를 마지막 필드로 낸다(줄기는 실패를 알리지 못한다).

(3) 쓰는 낱말은 버퍼에 붙인다(`or fail`, 자리가 모자라면 `err.full`). `s buf csv.put`, `n bufcsv.put_int`, `d buf csv.put_dec`, `b buf csv.put_bool` 은 필드 하나를(앞에 필요한 쉼표와 함께), `buf csv.end_line` 은 줄 끝을 붙인다. 참거짓은 `true` `false` 로 쓴다.

(4) `줄 buf csv.pack` 은 레코드의 줄 하나를 한 줄로 붙인다. `s 줄 csv.unpack` 은 한 줄을 읽어 필드의 차례대로 넣고 그 줄 뒤의 나머지를 준다. 모든 필드가 맞을 때만 줄에 쓴다(`err.format`). `dec(N)` 필드는 `json` 처럼 읽고 쓴다(16.8).

## 16.10 sheet — 줄과 열의 표를 모은 작업책

(1) 모듈 `sheet` 는 프로그램이 선언한 버퍼(8.7) 안에 줄과 열의 표, 곧 **시트**(sheets)를 여럿 둔다. 버퍼 하나가 **작업책**(book) 하나다. 자료형이 아니라 라이브러리이고, 어댑터처럼 돌아간다: 프로그램이 작업책을 열고, 그 안에 시트를 만들고, 이름이나 번호로 하나를 고르면, 다른 모든 낱말은 그 **현재 시트**(current sheet)에 닿는다. `sheet` 의 모든 낱말은 모음 매개변수(9.9)처럼 버퍼를 맨 끝에 받는다. 칸에는 아무것도 없거나, 프로그램이 넣은 `int`, `bool`, `dec(N)`, `str` 이 들어 있다. 칸의 종류는 모듈 안에서만 알고, 값은 그 형의 낱말(`int`, `str` …)로만 칸에서 나온다. 그래서 모든 낱말의 서명은 정해져 있고, 스택에 형이 없는 값이 오르는 일이 없다. 칸과 풀과 색인이 버퍼 안에 어떻게 놓이는지는 인터페이스가 아니다.

(2) 줄, 열, 시트는 0부터 센다. 줄은 `add_row` 가 끝에 더하고, 시트는 `create` 가 받은 `rmax` 줄까지 가진다. 열의 수는 `create` 가 정하고 `widen` 이 바꾼다. 칸에 넣는 값은 복사된다. 같은 값은 하나만 둔다. 작업책 전체가 풀 하나를 나눠 쓴다: 칸에 들어가지 않는 큰 수와 모든 글은 그것을 쥔 칸(어느 시트의 칸이든)의 수와 함께 풀에 놓이고, 덮어쓰거나 비우거나 잘려 나간 칸은 값을 돌려준다. 풀에 자리가 없으면 `err.full` 이고, 흩어진 글의 빈자리는 새 글이 필요로 할 때(와 `compact` 가 불릴 때) 모은다. `sheet` 는 번호로 읽고 쓰며 들어 있는 값으로 찾는 표를 위한 것이다. 이름으로 찾는 것은 색인(8.10)이 맡는다.

### 16.10.1 작업책과 시트

(3) 이 묶음이 아닌 낱말은 현재 시트가 있어야 하고, 없으면 결함 `state` 다. 작업책에 처음 만든 시트가 현재 시트가 된다. 이름은 1에서 255바이트이고 작업책에 한 번만 보관된다. 시트 번호는 만든 차례이며, 지운 시트의 번호는 다음에 만드는 시트가 다시 받는다.

| **Word** | **Signature** | **Meaning** |
|---|---|---|
| `open_book` | `(nmax int, b buffer or fail)` | 버퍼를 시트가 최대 `nmax`(1에서 256)개인 작업책으로 만든다(처음엔 시트 0개). 버퍼가 모자라면 `err.full`. 그 뒤 버퍼는 가득 찬 것으로 읽혀, 작업책 위에 덧붙일 수 없다 |
| `create` `create_cols` | `(name str, rmax int, cols int, b buffer gives int or fail)` | 줄이 최대 `rmax`, 열이 꼭 `cols` 인 시트를 만들고 그 번호를 준다. `create_cols` 는 열 단위로 저장한다: 한 열을 훑는 일이 몇 배 빠르고 한 줄을 통째로 읽는 일은 느리다. 이름이 이미 있으면 `err.format`, 자리나 번호가 없으면 `err.full` |
| `activate` `activate_n` | `(name str, b buffer or fail)` `(n int, b buffer or fail)` | 그 이름, 그 번호의 시트를 현재 시트로 한다. 없으면 `err.not_found`. 읽기 전용 작업책은 현재 시트를 바꿀 수 없다 |
| `current` `sheets` | `(b buffer gives int)` | 현재 시트의 번호(없으면 −1), 쓰는 가장 큰 번호보다 하나 큰 수 |
| `sheet_name` | `(n int, b buffer gives str or fail)` | 시트 `n` 의 이름을 보는 view. 작업책에 다음 쓰기 전까지 유효. 쓰지 않는 번호면 `err.not_found` |
| `find_sheet` | `(name str, b buffer gives int or fail)` | 그 이름의 시트 번호. 없으면 `err.not_found` |
| `remove` | `(name str, b buffer or fail)` | 시트를 색인과 함께 지우고 그 칸들이 쥔 값을 돌려준다. 현재 시트였다면 그 뒤에는 현재 시트가 없다 |
| `rename` | `(n int, name str, b buffer or fail)` | 시트 `n` 에 다른 이름을 준다. 이름이 이미 있으면 `err.format` |
| `copy_to` | `(row1 int, col1 int, n int, row2 int, col2 int, b buffer or fail)` | 현재 시트의 칸을 시트 `n` 의 칸에 복사한다. 값은 나눠 쥔다. 시트 `n` 이 없으면 `err.not_found` |

### 16.10.2 만들기와 늘리기

(4) 이 묶음의 낱말은 현재 시트에 닿는다.

| **Word** | **Signature** | **Meaning** |
|---|---|---|
| `rows` `cols` `rows_max` | `(b buffer gives int)` | 지금의 줄 수, 열 수, 최대 줄 수 |
| `add_row` | `(b buffer gives int or fail)` | 빈 줄을 더하고 그 번호를 준다. `rmax` 에 닿으면 `err.full` |
| `truncate_rows` | `(n int, b buffer)` | 앞의 `n` 줄만 남기고 나머지가 쥔 값을 돌려준다. 있는 줄보다 많으면 결함 `range` |
| `widen` | `(cols int, b buffer or fail)` | 줄, 값, 색인을 지키며 열이 `cols` 인 시트로 다시 만든다. 열을 늘리면 작업책에 자리가 있어야 하고(`err.full`), 줄이면 잘리는 열이 모두 비었을 때만 된다(`err.format`). 옛 자리는 구멍으로 남고 `compact` 가 메운다 |
| `clear` | `(b buffer)` | 모든 줄을 지운다 |
| `compact` | `(b buffer)` | 글의 빈자리를 모으고 시트 사이의 구멍을 메운다 |

### 16.10.3 칸

(5) 줄과 열을 받는 낱말은 칸이 표 밖이면 결함 `range` 다. 표가 아닌 버퍼도 같은 결함이다.

| **Word** | **Signature** | **Meaning** |
|---|---|---|
| `put_int` `put_bool` | `(v int, row int, col int, b buffer or fail)` `(v bool, row int, col int, b buffer or fail)` | 칸에 복사해 넣는다. 풀이 가득이면 `err.full` |
| `put_dec` | `(v dec(N), row int, col int, b buffer or fail)` | 자릿수와 함께 넣는다 |
| `put_str` | `(s str, row int, col int, b buffer or fail)` | 글을 복사해 넣는다. 이 표 안을 보는 view 를 줘도 된다 |
| `clear_cell` | `(row int, col int, b buffer)` | 칸을 비운다 |
| `copy_cell` | `(row1 int, col1 int, row2 int, col2 int, b buffer)` | 칸을 다른 칸에 복사한다. 값은 나눠 쥔다 |
| `int` `bool` | `(row int, col int, b buffer gives int or fail)` `(... gives bool or fail)` | 값. 다른 종류의 칸이면 `err.format` |
| `dec` | `(row int, col int, N int, b buffer gives dec(N) or fail)` | 자릿수 `N`(0에서 18의 상수)의 decimal. 종류나 자릿수가 다르면 `err.format` |
| `str` | `(row int, col int, b buffer gives str or fail)` | 표 안의 글을 보는 view. 그 표에 다음에 쓸 때까지 유효. 다른 종류면 `err.format` |
| `kind` `is_empty` | `(row int, col int, b buffer gives int)` `(... gives bool)` | 종류(`sheet.k_empty` 0, `k_int` 1, `k_bool` 2, `k_dec` 3, `k_str` 4). 비었는가 |

### 16.10.4 찾기와 고르기

(6) 찾기는 수는 수로, 글은 적힌 대로 견준다. 한 열을 아래로, 또는 한 줄을 옆으로 훑는다. 어느 칸에도 없는 글은 바로 없다고 알아낸다.

| **Word** | **Signature** | **Meaning** |
|---|---|---|
| `find_row_int` `find_row_str` | `(key int, col int, b buffer gives int or fail)` `(key str, col int, ...)` | `col` 열이 `key` 인 첫 줄. 없으면 `err.not_found`. 스프레드시트의 `MATCH` 다. 값은 그 뒤 `int`, `str` … 로 읽는다(`VLOOKUP` 처럼 형 없는 값을 돌려주는 낱말은 없다) |
| `find_col_int` `find_col_str` | `(key int, row int, b buffer gives int or fail)` | `row` 줄을 옆으로 훑어 첫 열 |
| `find_row_from_int` `find_row_from_str` `find_col_from_int` `find_col_from_str` | `(key, line int, from int, b buffer gives int or fail)` | 같되 줄이나 열 `from` 부터 |

(7) 시트는 **선택**(selection)을 가진다: 줄의 목록이고, 처음엔 모든 줄이다. `where_*` 는 모든 줄에서 다시 시작해, 그 열의 값이 `v` 와 관계 `op`(`sheet.eq` `ne` `lt` `le` `gt` `ge`)인 줄만 남기고, `narrow_*` 는 지금 선택된 줄 가운데 그런 줄만 남긴다. 종류가 다른 칸과 빈 칸은 어떤 관계도 아니다. 낱말마다 시트의 선택에 일하므로 낱말을 늘어놓으면 곧 파이프다. 선택은 버퍼 안의 한 자리이고 작업책 안에 시트마다 보관된다.

| **Word** | **Signature** | **Meaning** |
|---|---|---|
| `where_int` `narrow_int` | `(col int, op int, v int, b buffer)` | 수로 고르거나 좁힌다 |
| `where_str` `narrow_str` | `(col int, op int, v str, b buffer)` | 글로(바이트 순서) 고르거나 좁힌다 |
| `select_all` | `(b buffer)` | 모든 줄을 고른다 |
| `sel_len` | `(b buffer gives int)` | 고른 줄의 수 |
| `sel_row` | `(k int, b buffer gives int)` | `k` 번째로 고른 줄의 번호. 범위 밖이면 결함 `range` |
| `order_by` `order_by_desc` | `(col int, b buffer or fail)` | 고른 줄을 `col` 열의 순서로, 작은(큰) 것부터 안정적으로 놓는다. 수, 글, 나머지 차례. 수를 놓을 자리는 버퍼의 빈 끝에서 가져온다(`err.full`) |

(8) 합계는 int 칸만 본다. `sum_*` 는 합이 넘치면 결함 `overflow`, `min_*` 와 `max_*` 는 수가 없으면 `err.not_found` 로 실패한다.

| **Word** | **Signature** | **Meaning** |
|---|---|---|
| `sum_col` `min_col` `max_col` `count_col` | `(col int, b buffer gives int)` | `col` 열의 모든 줄. `min` 과 `max` 는 `or fail` |
| `sum_row` `min_row` `max_row` `count_row` | `(row int, b buffer gives int)` | `row` 줄의 모든 열 |
| `sum_sel` `min_sel` `max_sel` `count_sel` | `(col int, b buffer gives int)` | 고른 줄의 `col` 열 |

### 16.10.5 순서 있는 색인

(9) 열에는 **색인**(index)을 둘 수 있다: 그 열의 수와 글을 순서대로(수가 먼저, 다음 글은 바이트 순서, 같으면 줄 번호 순) 늘어놓은 구조이며, 작업책의 빈 끝에서 가져온 쪽(page)들로 된 B+트리다. `index` 가 만들고, 그 열에 쓰면 함께 고쳐지며, `unindex` 가 쪽을 돌려준다. 색인이 있으면 `find_row_*`(열을 따라 내려가기), `ne` 를 뺀 모든 관계의 `where_*`, 모든 줄을 고른 `order_by` 가 훑지 않고 답한다. 걸리는 시간은 줄 수의 로그와 찾은 줄 수에 따라 자라고, 답은 색인이 없을 때와 같다(줄은 줄 번호 순). 색인은 쓰기에 값을 치르고, 쪽과 시트가 버퍼를 채운 작업책은 새 색인을 `err.full` 로 거절한다. 없는 쪽이 필요한 쓰기도 `err.full` 이며 아무것도 바꾸지 않는다. 색인은 수단이지 뜻이 아니다: 쓰지 않는 프로그램은 전과 같이 돈다.

| **Word** | **Signature** | **Meaning** |
|---|---|---|
| `index` | `(col int, b buffer or fail)` | 현재 시트의 `col` 열에 색인을 만든다(이미 있으면 그대로). 작업책에 쪽이 없으면 `err.full` |
| `unindex` | `(col int, b buffer)` | 색인을 없앤다 |
| `indexed` | `(col int, b buffer gives bool)` | 그 열에 색인이 있는가 |

### 16.10.6 파일

(9a) CSV와 xlsx 파일을 현재 시트로 읽고 현재 시트에서 쓴다. 파일에 대한 권한은 없다: 프로그램이 파일을 `buffer` 로 읽고(`file.read_all_into`) 버퍼를 내보낸다(`contents` 를 `file.write`). 이 낱말들은 **버퍼 둘**(two buffers)을 받는다. 파일이 먼저, 작업책이 마지막이다(`0 blob book sheet.load_csv`). 둘은 서로 다른 버퍼이고, 작업책은 참조가 아닌 버퍼 자신이어야 한다(파일은 컬렉션 매개변수(9.9)여도 된다). 파일을 받는 낱말은 그 버퍼의 바이트를 바꿀 수 있다(작업 공간이다. 공유 버퍼는 거절한다). 읽기는 현재 시트의 마지막 줄 뒤에 줄을 더하고 더한 수를 주며, 실패하면 시트는 처음 그대로다. `rows_max` 를 넘는 줄이나 시트보다 많은 열은 `err.full`, CSV가 아닌 글이나 xlsx가 아닌 파일은 `err.format` 이다. `mode` 는 0 또는 1이고 다른 값은 오류(fault)다.

| **낱말** | **서명** | **뜻** |
|---|---|---|
| `load_csv` | `(mode int, f buffer, b buffer gives n int or fail)` | `f` 의 글을 읽는다. 줄은 LF나 CRLF로 끝나고 필드는 쉼표로 나뉘며, 따옴표 필드는 쉼표·줄바꿈·겹따옴표를 담을 수 있다(그 자리에서 풀어 쓴다). 빈 줄과 UTF-8 BOM은 건너뛴다. mode 0: 정규형 정수(`-?(0\|[1-9][0-9]*)`, int에 들어가는 것)는 `int`, 소수점 뒤 1 18자리인 정규형 수(들어가는 것)는 그 자릿수의 `dec`(`1.50` 은 `dec(2)`), 빈 필드는 빈 칸, 나머지는 글(`007`, `-0` 도). mode 1: 모두 글 |
| `load_xlsx` | `(mode int, n int, f buffer, b buffer gives rows int or fail)` | `f` 의 xlsx에서 `n` 번 시트(0부터, 통합 문서 순서, 없으면 `err.not_found`)를 읽는다. 숫자는 CSV 규칙을 따른다(소수 18자리를 넘는 자리는 반올림, 지수는 적용, 들어가지 않으면 글). 공유·인라인·수식 결과 문자열은 글(서식 있는 글은 이어 붙이고 발음 표기는 버린다), `t="b"` 는 `bool`, 오류값(`#N/A`)은 글, 수식은 저장된 결과를 준다. 숫자 서식이 날짜나 시간인 칸(내장 14 22, 27 36, 45 47, 50 58, 71 81, 또는 따옴표·대괄호 밖에 `y`, `d`, `h`, `s`, `m` 이 있는 사용자 서식, `[h]`, `[mm]` 포함)은 mode 0에서 Unix 초(UTC, 파일의 1900/1904 날짜 체계, 시각만 있는 값은 자정부터)의 `int`, mode 1에서는 일련번호 그대로의 `dec`. 파일이 비운 줄과 열은 빈 칸 |
| `save_csv` | `(dst buffer, b buffer gives n int or fail)` | `dst` 의 내용을 현재 시트의 CSV로 바꾼다(쓴 마지막 줄과 열까지, 쉼표·따옴표·줄바꿈이 든 글은 따옴표로 감싼다, `dec` 는 자릿수대로, `bool` 은 `true`/`false`). 쓴 바이트 수를 준다. `dst` 가 작으면 `err.full`(그때 `dst` 는 비어 있다) |
| `save_xlsx` | `(dst buffer, b buffer gives n int or fail)` | `dst` 의 내용을 현재 시트의 xlsx로 바꾼다(시트 하나, 이름은 시트 이름대로 31자까지, `[]:*?/\` 는 뺀다. 글은 인라인 문자열, 수·`dec`·`bool` 은 그대로이고, 날짜 형이 없으니 날짜는 가진 수로 쓴다). ZIP은 압축하지 않고 저장만 한다 |

(9b) **작업 공간**(work area) 아무것도 할당하지 않는다(12절). `load_xlsx` 는 파일이 든 버퍼의 마지막 바이트 뒤 남은 용량을 쓴다: 약 130 KB(inflate의 창과 훑개의 버퍼)에 풀어낸 공유 문자열(하나에 4바이트와 그 글)을 더한 만큼이다. 버퍼는 파일보다 크게 선언해야 하고 자리가 모자라면 `err.full` 이다. 파일의 부품은 ZIP의 중앙 디렉터리로 찾는다. ZIP64, 암호화된 부품, stored와 deflate 외의 방식은 `err.format`, 풀었을 때 256 MiB를 넘는 부품도 같다. 풀어낸 바이트마다 명령 예산에서 차감한다.

## 16.11 toml — TOML

(1) 모듈 `toml` 은 설정 파일인 TOML 버전 1 글을 나무로 만들지 않고 읽는다. 값은 글에 적힌 바이트 그대로 주고, 문자열은 따옴표를 뗀다. 이스케이프가 있는 문자열, 또는 줄 끝 역슬래시가 있는 여러 줄 문자열은 풀어서 구역(12.2)에 쓴 글로 준다. 아무것도 바꾸지 않는다: 수는 적힌 그대로(`5_000`, `0xff`) 주므로, 프로그램이 원하는 꼴의 말로 읽는다. 이 모듈은 읽기만 하고 TOML 을 쓰지 않는다.

(2) `kind` 는 아래 상수다.

| **상수** | **값** |
|---|---|
| `toml.table` | 머리 `[a.b]`, 또는 경로가 가리키는 표: 값 없음 |
| `toml.tables` | 표 배열의 머리 `[[a.b]]`: 값 없음 |
| `toml.string` | 네 가지 문자열 중 어느 것이든 |
| `toml.int` `toml.float` | 적힌 그대로의 수. `inf` 와 `nan` 은 float |
| `toml.bool` | `true` 또는 `false` |
| `toml.datetime` | 날짜, 시각, 또는 둘, 적힌 그대로(`1979-05-27T07:32:00Z`) |
| `toml.array` `toml.inline` | 배열이나 인라인 표를 적힌 대로 통째로. `toml.at` 으로 다시 읽을 수 있다 |

### 16.11.1 읽기

(3) `s toml.next` 는 `s` 의 첫 문장을 읽어 `(kind int, key str, value str, rest str)` 를 준다(`or fail`): 머리이면(`kind` 는 `toml.table` 또는 `toml.tables`, `key` 는 괄호 사이의 이름 그대로, `value` 는 비었다), 쌍이면(`key` 는 적힌 대로 점과 따옴표까지, `value` 는 위와 같다). 빈 줄과 주석은 건너뛴다. 끝에 이르면 `err.not_found`, TOML 이 아닌 문장은 `err.format` 으로 실패한다. 프로그램이 지금 어느 머리 아래인지는 스스로 기억한다. 모든 `key` 는 그 머리에 상대적이다.

(4) `path s toml.at` 은 `(kind int, value str)` 를 준다(`or fail`): 파일을 읽는 사람이 보는 대로 `path` 가 가리키는 값. 경로는 점으로 이은 이름(따옴표를 친 이름 `"a.b"` `'a.b'` 에는 점이 들 수 있다)과 괄호 안의 번호다: `server.ports[1]`, `user[0].name`, `a."b c".d`. 점을 쓴 키(`a.b.c = 1`), 머리가 만든 표, 인라인 표, 배열을 모두 따라가고, 번호는 값 배열이나 표 배열(`[[...]]` 머리의 차례, 한 원소 아래의 것은 그 원소에 속한다)의 원소를 고른다. 표를 가리키는 경로는 `toml.table` 과 값 없음을 준다. 없으면 `err.not_found`, 경로가 잘못됐거나 읽은 곳의 글이 잘못됐으면 `err.format`.

(5) `s toml.valid` 는 `s` 의 모든 문장이 꼴이 맞는지 준다. 검사는 문장 하나하나의 문법이다: 두 번 준 키, 두 번 정의한 표, 수의 범위, 있는 날짜인지는 검사하지 않는다.

| **말** | **서명** | **뜻** |
|---|---|---|
| `valid` | `(s str gives bool)` | `s` 의 모든 문장이 꼴이 맞는지 |
| `at` | `(path str, s str gives kind int, value str or fail)` | `s` 에서 `path` 가 가리키는 값. `err.not_found`, `err.format` |
| `next` | `(s str gives kind int, key str, value str, rest str or fail)` | `s` 의 첫 문장과 그 뒤의 나머지. 끝에서 `err.not_found`, `err.format` |

## 16.12 md — Markdown

(1) 모듈 `md` 는 사람이 쓰는 글인 Markdown 을 읽어 HTML 로 쓴다. CommonMark 의 부분집합에 GFM 의 표와 취소선을 더한 것으로, 스크립트가 만나는 메모, README, 쪽에 맞춘 것이지 규격의 구석구석까지 따르지 않는다. 글 속의 날 HTML 은 절대 넘기지 않는다: `<` 는 `&lt;` 로 쓴다. 주소의 체계가 `http`, `https`, `mailto`, `tel`, `ftp` 가 아닌 링크와 그림은 글만 쓴다. 그래서 Markdown 이 무엇이든 그 HTML 은 쪽에 넣어도 안전하다.

(2) 읽는 것. 블록: ATX 제목(`#` 에서 `######`)과 밑줄 제목, 문단, 가로줄, 인용, 목록(`-` `+` `*` 글머리표, `1.` `1)` 번호, 중첩, 촘촘한 것과 성긴 것), 울타리 코드(백틱이나 물결표 셋 이상, 정보 문자열의 첫 낱말이 글자, 숫자, `- _ + # .` 이면 `class="language-..."` 가 된다), 들여쓴 코드, 표(한 줄, 정렬을 콜론으로 적은 줄, 줄들). 인라인: 강조 `*a*` `_a_`, 굵게 `**a**` `__a__`, 취소선 `~~a~~`, 코드, 링크 `[글](주소 "제목")`, 그림 `![대체글](주소)`, 자동 링크 `<https://...>` 와 `<a@b.c>`, 역슬래시 이스케이프, 문자 참조(`&amp;` `&#65;`), 강제 줄바꿈(줄 끝 공백 둘 또는 역슬래시). 읽지 않는 것: 링크 참조 정의, 날 HTML, 목록 뒤의 밑줄 제목, 구두점 곁 강조의 CommonMark 세부 규칙. 이들은 글이나 보통 문단이 될 뿐 실패하지 않는다. 12 단보다 깊은 컨테이너나 강조의 중첩은 글로 쓴다. 링크, 강조, 코드의 닫는 표를 찾는 일은 글의 바이트마다 16 바이트의 예산으로 치르고, 예산이 다하면 남은 표는 글이 된다. 그래서 닫히지 않은 표뿐인 글도 크기에 비례하는 시간에 읽는다.

### 16.12.1 HTML 쓰기

(3) `s b md.html` 은 Markdown 글 `s` 의 HTML 을 버퍼 `b` 에 덧붙이고, `s b md.inline` 은 블록 없이 한 줄이나 한 문단만의 HTML 을 덧붙인다. 자리가 모자라면 `err.full` 로 실패한다(버퍼는 그대로). 자리는 HTML 자체에 더해, 인용이나 목록 항목을 쓰는 동안 그 복사본을 버퍼 끝에 둘 만큼, 곧 블록이 든 단마다 글보다 길지 않은 복사본 하나씩의 바이트가 더 든다. `s` 는 그 버퍼가 아니다.

### 16.12.2 블록으로 읽기

(4) `s md.next` 는 `s` 의 첫 블록을 읽어 `(kind int, level int, text str, rest str)` 를 준다(`or fail`). 끝에 이르면 `err.not_found` 로 실패한다. 아무것도 복사하지 않는다: `text` 는 `s` 의 뷰다. `kind` 는 아래 상수, `text` 는 표가 말하는 것, `level` 은 제목이면 그 단계(1에서 6), 번호 목록이면 1, 그 밖에는 0 이다.

| **상수** | **text** |
|---|---|
| `md.heading` | `#` 와 밑줄을 뗀 제목의 글. 인라인 Markdown 으로 읽는다 |
| `md.paragraph` | 문단의 줄들, 적힌 대로 |
| `md.code` | 울타리 코드: 울타리 사이의 줄들. 들여쓴 코드: 들여쓰기를 그대로 둔 줄들 |
| `md.quote` `md.list` `md.table` | 표지를 그대로 둔 블록. `md.html` 에 준다 |
| `md.rule` | 빈 글 |

| **말** | **서명** | **뜻** |
|---|---|---|
| `html` | `(s str, b buffer or fail)` | Markdown 글 `s` 의 HTML 을 덧붙인다. `err.full` |
| `inline` | `(s str, b buffer or fail)` | 한 줄이나 한 문단의 글의 HTML 을 덧붙인다. `err.full` |
| `next` | `(s str gives kind int, level int, text str, rest str or fail)` | `s` 의 첫 블록과 그 뒤의 나머지. 끝에서 `err.not_found` |
