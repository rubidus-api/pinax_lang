구문
control = "if" { body } [ "else" { body } ] "end"
        | "loop" { body } "end"
        | "match" { branch } [ "otherwise" { body } "end" ] "end" ;
branch  = "when" case-value { case-value } "do" { body } "end" ;
leave   = ( "break" | "continue" ) [ INT ] "." | "return" ;
block   = "do" { "to" NAME } { body } "end"
        | "def" effect "do" { body } "end"       (* a block value, 10.5 *)
        | "ref" NAME ;

(1) end 는 가장 안쪽에 열린 것 하나를 닫는다. 여는 프로시저는 def forward extern test record do if loop match when otherwise or_else defer 다. (forward 와 extern 은 서명 뒤의 end 로, type NAME proc … end 도 닫는다.) (텍스트 리터럴과 note 주석은 자기 꼬리표로 닫는다, 6.3, 6.5.)

(2) 처리기는 적재 때 모든 갈래의 스택을 견준다. 갈래가 다시 만나는 자리에서 스택은 어느 갈래로 왔든 같아야 한다. 떠나는 갈래(leaving branch) — return fail break continue 로 끝나거나 끝나지 않는 루프로 끝나는 갈래 — 는 견주지 않는다.

10.1 갈림

(1) 조건 if 몸 end 는 맨 위의 bool 을 내려 참이면 몸을 돈다. 조건 if 몸 else 몸 end 는 거짓이면 else 의 몸을 돈다.

(2) else 가 없는 if 의 몸은 스택을 들어올 때와 같게 둬야 한다. else 가 있으면 두 몸은 같은 스택을 남겨야 한다.

def warn n int do n 100 gt if "big" io.println end end      rem no else: the branch leaves the stack as it was

10.2 루프

(1) loop 몸 end 는 몸을 되풀이한다. 몸 안에서 다음 문장이 루프를 떠난다.

  • break . — 루프를 떠나 end 뒤의 코드로 간다.
  • continue . — 한 바퀴의 나머지를 건너뛰고 다음 바퀴를 시작한다.
  • break N . continue N . — 안쪽에서 세어 N 번째 루프에 한다(N 은 1 이상의 정수 리터럴, 빼면 1). 안쪽 루프들은 한 번에 떠난다.

조건은 if 로 쓴다: x 0 eq if break . end. 문장은 마침표로 끝난다. break 와 continue 는 몇 번이든 쓸 수 있고, 루프의 몸에 바로 쓰거나 그 안의 갈래(if else match or_else) 안에 쓴다.

(2) 한 바퀴는 스택을 들어올 때와 같게 둬야 한다. 떠나는 자리마다 스택은 루프에 들어올 때와 같아야 한다. 루프의 결과가 필요하면 지역 변수에 둔다.

10-loop.pnx

use io .
use str .
def digits n int gives int do            rem how many decimal digits
  1 to count_
  loop
    n 10 div to n
    n 0 eq if break . end
    count_ 1 add to count_
  end
  count_
end
12345 digits str.to_str io.println
def first_square_over limit int gives int do
  1 to i
  loop
    i i mul limit gt if break . end
    i 1 add to i
  end
  i
end

10.3 고르기

(1) 값 match when 값… do 몸 end … otherwise 몸 end end 는 맨 위의 int, 좁은 정수(7.6), err 나 str 를 내려 가지의 값과 견주고, 같은 첫 가지의 몸을 돈다. 가지는 when 으로 시작한다. 가지의 값은 리터럴, 이 소스의 const, 오류 코드(err.range), 또는 다른 모듈이 내보낸 상수나 실패 코드(모듈.이름, 8.14)다. 한 가지에 값이 여럿이면 when 뒤에 공백으로 늘어놓는다(쉼표나 괄호 없이). 값들 뒤의 do 가 몸을 연다. 맞는 가지가 없으면 otherwise 의 몸을 돈다. 가지마다 같은 스택을 남겨야 한다.

10-case.pnx

use io .
const quit_code 9
def describe cmd str gives str do
  cmd match
    when "add" do "adds a line" end
    when "rm" "del" do "deletes a line" end
    otherwise "unknown command" end
  end
end
def level n int gives str do
  n match
    when 0 do "off" end
    when 1 do "low" end
    when quit_code do "quit" end
    otherwise "high" end
  end
end
"del" describe io.println
"mv" describe io.println
9 level io.println

10.5 블록

(1) do … end 는 블록(block)이다. 블록은 조합 프로시저에 주는 것으로만 쓴다(if 의 몸처럼 프로시저 없이 홀로 있는 do … end 는 없다). 값이 되는 블록은 def 로 적는다(def 서명 do … end, (2a)). 블록은 두 가지로 쓰인다.

  • 끼워 넣는 블록(inline block) — 조합 프로시저(10.6)에 바로 준 블록. 그 자리에 펼쳐진다. 그래서 바깥의 지역 변수를 읽고 쓸 수 있고, 안에서 return 하면 바깥 프로시저를 떠난다.
  • 값이 되는 블록(block value) — def 서명 do … end 로 적어 지역 변수에 넣거나, 블록을 받는 매개변수(proc … end 타입, 7.4)에 주는 것. 이름 없는 프로시저 하나가 되며 call 로 부른다. 바깥의 지역 변수를 보지 못한다(붙잡지 않는다). 전역은 본다.

(2) 끼워 넣는 블록은 do 바로 뒤에 to 이름 을 하나씩 이어 써서 레일이 내는 값(과 each_index 의 번호)을 지역 변수로 받는다. 이름은 값이 놓인 차례의 거꾸로 받는다: do to i to s … end each_index 는 s 가 원소, i 가 번호다(레일의 원소가 먼저 놓이므로 맨 위가 i). 값이 되는 블록의 서명은 프로시저의 서명과 같고, 이름들은 지역 변수가 된다.

  acc

(2a) ref 이름 은 def 로 정의한 프로시저(이 소스의 것이든 쓰는 모듈이 내보낸 것이든) 자체를 값으로 준다(ref by_len, ref geo.area). 타입은 그 프로시저의 서명을 가진 proc 이고, call 은 그 프로시저를 부른다. 언어의 다른 프로시저는 서명을 쓴 블록으로 준다. 타입만 쓴 입력은 스택에 남으므로(9.2 (2)) 블록의 몸은 그 프로시저 하나다: def str, str gives bool do str.starts_with end.

(2b) proc 타입의 값은 배열이나 목록의 칸, 레코드의 필드(곧 표나 풀의 줄), global 에도 둘 수 있다(array ops Op 3, ref plus 0 set ops, 3 4 0 ops idx call). 값은 프로시저 번호에 1 을 더해 보관하므로 아무것도 쓰지 않은 칸은 없음이다: is_none 으로 묻고, 없음을 부르면 결함 range 다. 다른 서명의 프로시저는 칸에 쓰는 자리에서 거절된다. 이런 칸은 정렬, 합, 비교, 찾아보기의 키로 쓰지 못한다. 이전(버전 5 이하)에 저장한 컨테이너는 적재할 때 거절된다.

10-proc-cells.pnx

use io .
use str .
type Op proc a int, b int gives int end
def plus a int, b int gives int do a b add end
record Route
  code int
  run Op                           rem a procedure value in a field
end
array ops Op 2
list routes Route 4
global fallback Op
def main or fail do
  ref plus 0 set ops               rem a cell holds the procedure; the other cell stays none
  def int, int gives int do mul end 1 set ops
  3 4 0 ops idx call str.to_str io.println
  3 4 1 ops idx call str.to_str io.println
  routes add_row or_fail to r
  ref plus r to Route.run
  5 6 r Route.run call str.to_str io.println
  fallback is_none if "no fallback yet" io.println end
end
main or_else to e e err_text io.println end

10.6 레일과 조합 프로시저

(1) 레일(rail)는 차례로 값을 내는 것이다. 레일은 값이 아니어서 지역 변수에 넣지 못하고, 바로 뒤의 조합 프로시저가 받아야 한다. 둘이 합쳐 루프 하나가 된다. 훑기 전에 길이를 알고 어느 자리의 원소든 읽을 수 있는 레일을 닫힌 레일(closed rail)이라 하고(range, 배열, 목록, str.bytes), 그렇지 않은 레일을 열린 레일(open rail)이라 한다: 원천에서 조각을 차례로 하나씩 꺼내고 한 번만 훑는다(str.split str.lines str.words str.chars ptn.matches rex.matches rex.split csv.fields, 풀). 레일은 게으르게 평가된다: 루프는 훑는 차례대로 원소를 하나씩 꺼내고, 어댑터의 블록은 거기에 닿은 원소에만 돈다. 일찍 끝나는 훑기(head head_while first any break)는 그 뒤를 읽지도 평가하지도 않고, 단계 사이에 저장하는 것이 없다. 레일을 내는 것은 다음과 같다.

레일원소
배열, 목록의 이름칸의 값(레코드면 줄). 목록은 길이까지. 큐, 버퍼, 찾아보기는 레일이 아니다
풀의 이름살아 있는 줄, 칸의 차례로. each 에만(8.9 (3a))
lo hi rangelo 부터 hi 앞까지의 int
s sep str.split, s str.lines, s str.words, s str.charsstr 뷰(16.1). chars 는 UTF-8 글자 하나씩
s str.bytesu8: 바이트(16.1)
s pat ptn.matches, s re rex.matches, s re rex.split맞은 부분(16.6, 16.7)
s csv.fields필드(16.9)

(2) 조합 프로시저는 다음과 같다. “블록” 열은 블록이 받고 주는 것이다.

프로시저블록결과
each(T)없음
each_index(T, i int)없음
fold(acc U, T gives U)U. 첫 값을 레일 앞에 둔다: 0 xs do … end fold
count(T gives bool)int
any all(T gives bool)bool. 답이 정해지면 일찍 끝난다
first(T gives bool)T or fail. 없으면 err.not_found

(1a) 어댑터(adapter)는 레일을 받아 레일을 준다. skip N 은 처음 N 개를 건너뛰고, head N 은 처음 N 개만 남기고, step N 은 N 개마다 하나(첫째부터)를, rev 는 끝에서 처음으로 훑는다. 레일 뒤에 쓴 차례대로 적용되어 어댑터가 몇이든 루프는 하나다: scores skip 2 head 3 은 셋째부터 다섯째까지, scores head 3 skip 1 은 둘째와 셋째다. N 은 int 를 하나 남기는 코드이고 쉼표, do, 다음 어댑터, sum minimum maximum 앞에서 끝난다. 루프 앞에서 한 번만 계산한다. N 이 음수(step 은 1 보다 작음)이면 결함 range 다. step 과 rev 는 닫힌 레일에만 쓴다. skip 과 head 는 열린 레일에도 쓰고, 거기서는 조각이 오는 대로 센다. step 은 맨 끝에만 온다. 한 레일에 열여섯까지 쓴다. each_index 는 어댑터 뒤의 레일을 아직 세지 않는다. each fold count any all first map_into filter_into sum minimum maximum 이 받는다.

(1b) filter map skip_while head_while 은 바로 앞에 쓴 블록을 받는다(do to s s 4 gt end filter). 블록은 원소를 받아 bool 을 내고(filter 는 참인 원소만 남기고, skip_while 은 참인 동안 버리고, head_while 은 처음 거짓인 원소에서 훑기를 끝낸다), map 은 같은 타입의 값을 내어 원소 자리를 대신한다. 블록은 루프 안에서 원소마다 적은 차례로 돌고, 앞의 것이 버린 원소에는 돌지 않는다: 루프는 하나이고 저장소도 부름도 없다. 블록 어댑터는 닫힌 레일에도 열린 레일(str.words, str.lines …)에도 쓴다. 닫힌 레일에서는 skip head step rev 가 이들보다 앞에 오고, 열린 레일에서는 어디에든 와서 자기에게 닿은 조각을 센다. 블록이 원소에 붙이는 이름은 마지막 블록의 이름과 같아도 된다. 블록은 값을 내고 루프를 떠나지 않는다: 그 안의 break 와 continue 는 적재 때 거절된다(블록 안에 둔 자기 루프는 쓸 수 있다). 원소를 버리려면 filter 로, 훑기를 끝내려면 head_while 로 한다.

(1) defer 코드 end 는 둘러싼 블록을 떠날 때 돌 코드를 적는다. 블록은 프로시저의 몸, 루프의 몸(한 바퀴마다), 조합 프로시저의 do 블록(한 번 돌 때마다)이다. 그 블록을 떠나는 모든 길에서 돈다: 블록의 end, 루프의 한 바퀴 끝, break, continue, return, or_return, or_fail, fail. 여럿이면 적은 차례의 거꾸로 돈다. 결함으로 끝날 때는 돌지 않는다(그때는 상태가 핸들을 닫는다, 19.6).

10.8 문장의 끝

(1) 코드에 쓴 쉼표나 점(서명이나 args … . 안이 아닌 곳)은 문장(statement)을 끝낸다: 마지막 쉼표나 점 뒤의 코드다. 둘 다 스택을 바꾸지 않고, 둘 다 꼭 써야 하는 것은 아니다. 둘이 없는 코드는 전과 같은 뜻이다.

(2) 쉼표는 아무것도 기다리지 않는다: 다음 문장이 시작할 때 이 문장의 효과가 아직 진행 중일 수 있다.

(3) 점은 장벽(barrier)이다: 점 앞에서 시작한 모든 효과가 점 뒤의 무엇보다 먼저 끝난다. 처리기의 몫은 호스트가 pinax_on_barrier(19.4 (3))로 준 함수를 부르는 것이고, 호스트의 몫은 호스트 프로시저가 붙들고 있는 것(표준 출력, 파일에 쓴 것)을 내보내고 뒤에서 시작한 일을 기다리는 것이다. 적재한 코드의 끝과 세션 줄의 끝은 점이다. 결함으로 끝나도 그렇다. 데이터로 적재한 소스에서 둘은 문장을 나눌 뿐 아무것도 부르지 않는다.

(4) 문장이 결과를 써야 하는 효과(읽기, 명령의 출력)는 닿은 자리에서 끝낸다. 두 점 사이에서 같은 자원에 대한 효과는 프로그램의 순서를 지키고, 다른 자원에 대한 효과는 겹칠 수 있다. 이 판은 모든 효과를 프로그램의 순서대로 돌린다. 겹침은 뒤의 판이 쓸 수 있는 여지다.
