16 표준 모듈

(1) 표준 모듈은 처리기에 들어 있다. use 모듈 로 열고 모듈.낱말 로 쓴다(13.1). 표준 모듈의 낱말은 호스트의 허락 없이 바깥과 닿지 못한다 — 파일도, 시계도, 환경도 쓰지 않는다.

(2) 표준 모듈의 낱말은 새 저장소를 만들지 않는다. 결과는 다음 가운데 하나다.

  • 받은 바이트를 가리키는 뷰. 복사가 없다.
  • 구역(12.2)에 새로 쓴 바이트의 뷰.
  • 부른 쪽이 준 버퍼에 붙인 바이트. 이런 낱말은 이름이 _into 로 끝나거나 버퍼를 받고, 자리가 모자라면 err.full 로 실패한다.

16.1 str — 문자열

(1) 모듈 str 은 문자열을 바이트로 다룬다. 바이트의 번호는 0 부터 센다. 글자 단위로 다루는 낱말 (chars char_count is_utf8)만 UTF-8 로 읽는다. 대소문자 바꾸기(upper lower)는 ASCII 만 바꾼다.

(2) 구분자나 찾는 것을 받는 자리(sep, part)에는 str 이나 문자 하나(int, 6.5)를 줄 수 있다.

16.1.4 줄기와 버퍼에 쓰기

(7) 줄기(10.6)를 내는 낱말:

  • s sep str.split — sep 으로 가른 조각. 빈 조각도 낸다. sep 은 str 이거나 바이트 하나(u8 상수, 보통 문자 리터럴)다. cut 과 try_cut 의 sep 도 같다.
  • s str.words — 공백으로 가른 조각. 빈 조각은 내지 않는다.
  • s str.lines — 줄. 줄 끝의 LF 와 CR LF 는 빼고 낸다.
  • s str.bytes — 바이트(u8).
  • s str.chars — UTF-8 글자 하나씩의 뷰(str).

(8) 버퍼에 쓰는 낱말:

  • sep buf 줄기 str.join_into — 줄기의 조각을 sep 으로 이어 버퍼에 붙인다(or fail). 줄기는 바로 뒤의 낱말이 받아야 하므로 줄기를 맨 뒤에 둔다.
  • s old new buf str.replace_into — 바꾼 글을 버퍼에 붙이고 바꾼 횟수를 준다(gives n int or fail).

16.5.1 레코드

(3) 줄 buf bytes.pack 은 레코드(8.8)의 줄 하나를 필드의 차례대로 버퍼에 붙인다(or fail). s 줄 bytes.unpack 은 바이트에서 필드를 읽어 줄에 넣고 나머지 뷰를 준다(gives str or fail). 줄 bytes.packed_size 는 pack 이 쓸 바이트 수다.

16.7 rex — 정규 표현식

(1) 모듈 rex 는 정규 표현식(regular expression)으로 찾고 바꾼다. 맞추는 방법은 되돌아가지 않는 방식이라, 걸리는 시간이 글의 길이와 패턴의 크기의 곱을 넘지 않는다. 패턴을 적을 때는 날 문자열(6.5)을 쓴다 — 보통 문자열에서 "\d" 는 모르는 이스케이프로 거절되고, "\b" 는 백스페이스가 된다.

(2) use rex 가 있는 소스에서는 타입 이름 regex 가 보인다. regex 값은 만든 뒤에 고치지 못하는 패턴 프로그램이다. 지역 변수, 인자, 결과에만 쓴다.

16.8.1 읽기

(2) s json.next 는 s 의 첫 토큰을 읽어 (kind int, value str, rest str) 를 준다(or fail). 끝에 이르면 err.not_found, 토큰이 아닌 것을 만나면 err.format 으로 실패한다. 토큰 사이의 공백, 쉼표, 쌍점은 건너뛴다. 괄호의 짝이나 쉼표의 자리 같은 문법의 짜임은 검사하지 않는다.

(5a) 말 넷이 글 전체를 RFC 8259 의 엄격한 문법으로 읽는다(위의 토큰 읽기는 흐름을 읽으려고 일부러 느슨하다). 글이 값 하나와 공백뿐이면 유효하다. 64 단보다 깊은 중첩은 여기서 유효하지 않다. 경로는 값을 가리킨다: 점으로 이은 이름, 괄호 안의 번호, 점이나 괄호가 든 이름은 ["a.b"] (user.langs[1], [0].id). 빈 경로는 글 전체다. 이름은 키의 이스케이프를 푼 글과 견준다. 값을 찾으면 거기서 읽기를 멈추므로, 나머지 글은 검사하지 않는다.

16.10 sheet — 줄과 열의 표를 모은 작업책

(1) 모듈 sheet 는 프로그램이 선언한 버퍼(8.7) 안에 줄과 열의 표, 곧 시트(sheets)를 여럿 둔다. 버퍼 하나가 작업책(book) 하나다. 자료형이 아니라 라이브러리이고, 어댑터처럼 돌아간다: 프로그램이 작업책을 열고, 그 안에 시트를 만들고, 이름이나 번호로 하나를 고르면, 다른 모든 낱말은 그 현재 시트(current sheet)에 닿는다. sheet 의 모든 낱말은 모음 매개변수(9.9)처럼 버퍼를 맨 끝에 받는다. 칸에는 아무것도 없거나, 프로그램이 넣은 int, bool, dec(N), str 이 들어 있다. 칸의 종류는 모듈 안에서만 알고, 값은 그 형의 낱말(int, str …)로만 칸에서 나온다. 그래서 모든 낱말의 서명은 정해져 있고, 스택에 형이 없는 값이 오르는 일이 없다. 칸과 풀과 색인이 버퍼 안에 어떻게 놓이는지는 인터페이스가 아니다.

(2) 줄, 열, 시트는 0부터 센다. 줄은 add_row 가 끝에 더하고, 시트는 create 가 받은 rmax 줄까지 가진다. 열의 수는 create 가 정하고 widen 이 바꾼다. 칸에 넣는 값은 복사된다. 같은 값은 하나만 둔다. 작업책 전체가 풀 하나를 나눠 쓴다: 칸에 들어가지 않는 큰 수와 모든 글은 그것을 쥔 칸(어느 시트의 칸이든)의 수와 함께 풀에 놓이고, 덮어쓰거나 비우거나 잘려 나간 칸은 값을 돌려준다. 풀에 자리가 없으면 err.full 이고, 흩어진 글의 빈자리는 새 글이 필요로 할 때(와 compact 가 불릴 때) 모은다. sheet 는 번호로 읽고 쓰며 들어 있는 값으로 찾는 표를 위한 것이다. 이름으로 찾는 것은 색인(8.10)이 맡는다.

16.10.5 순서 있는 색인

(9) 열에는 색인(index)을 둘 수 있다: 그 열의 수와 글을 순서대로(수가 먼저, 다음 글은 바이트 순서, 같으면 줄 번호 순) 늘어놓은 구조이며, 작업책의 빈 끝에서 가져온 쪽(page)들로 된 B+트리다. index 가 만들고, 그 열에 쓰면 함께 고쳐지며, unindex 가 쪽을 돌려준다. 색인이 있으면 find_row_*(열을 따라 내려가기), ne 를 뺀 모든 관계의 where_*, 모든 줄을 고른 order_by 가 훑지 않고 답한다. 걸리는 시간은 줄 수의 로그와 찾은 줄 수에 따라 자라고, 답은 색인이 없을 때와 같다(줄은 줄 번호 순). 색인은 쓰기에 값을 치르고, 쪽과 시트가 버퍼를 채운 작업책은 새 색인을 err.full 로 거절한다. 없는 쪽이 필요한 쓰기도 err.full 이며 아무것도 바꾸지 않는다. 색인은 수단이지 뜻이 아니다: 쓰지 않는 프로그램은 전과 같이 돈다.

16.10.6 파일

(9a) CSV와 xlsx 파일을 현재 시트로 읽고 현재 시트에서 쓴다. 파일에 대한 권한은 없다: 프로그램이 파일을 buffer 로 읽고(file.read_all_into) 버퍼를 내보낸다(contents 를 file.write). 이 낱말들은 버퍼 둘(two buffers)을 받는다. 파일이 먼저, 작업책이 마지막이다(0 blob book sheet.load_csv). 둘은 서로 다른 버퍼이고, 작업책은 참조가 아닌 버퍼 자신이어야 한다(파일은 컬렉션 매개변수(9.9)여도 된다). 파일을 받는 낱말은 그 버퍼의 바이트를 바꿀 수 있다(작업 공간이다. 공유 버퍼는 거절한다). 읽기는 현재 시트의 마지막 줄 뒤에 줄을 더하고 더한 수를 주며, 실패하면 시트는 처음 그대로다. rows_max 를 넘는 줄이나 시트보다 많은 열은 err.full, CSV가 아닌 글이나 xlsx가 아닌 파일은 err.format 이다. mode 는 0 또는 1이고 다른 값은 오류(fault)다.

낱말서명뜻
load_csv(mode int, f buffer, b buffer gives n int or fail)f 의 글을 읽는다. 줄은 LF나 CRLF로 끝나고 필드는 쉼표로 나뉘며, 따옴표 필드는 쉼표·줄바꿈·겹따옴표를 담을 수 있다(그 자리에서 풀어 쓴다). 빈 줄과 UTF-8 BOM은 건너뛴다. mode 0: 정규형 정수(-?(0|[1-9][0-9]*), int에 들어가는 것)는 int, 소수점 뒤 1 18자리인 정규형 수(들어가는 것)는 그 자릿수의 dec(1.50 은 dec(2)), 빈 필드는 빈 칸, 나머지는 글(007, -0 도). mode 1: 모두 글
load_xlsx(mode int, n int, f buffer, b buffer gives rows int or fail)f 의 xlsx에서 n 번 시트(0부터, 통합 문서 순서, 없으면 err.not_found)를 읽는다. 숫자는 CSV 규칙을 따른다(소수 18자리를 넘는 자리는 반올림, 지수는 적용, 들어가지 않으면 글). 공유·인라인·수식 결과 문자열은 글(서식 있는 글은 이어 붙이고 발음 표기는 버린다), t="b" 는 bool, 오류값(#N/A)은 글, 수식은 저장된 결과를 준다. 숫자 서식이 날짜나 시간인 칸(내장 14 22, 27 36, 45 47, 50 58, 71 81, 또는 따옴표·대괄호 밖에 y, d, h, s, m 이 있는 사용자 서식, [h], [mm] 포함)은 mode 0에서 Unix 초(UTC, 파일의 1900/1904 날짜 체계, 시각만 있는 값은 자정부터)의 int, mode 1에서는 일련번호 그대로의 dec. 파일이 비운 줄과 열은 빈 칸
save_csv(dst buffer, b buffer gives n int or fail)dst 의 내용을 현재 시트의 CSV로 바꾼다(쓴 마지막 줄과 열까지, 쉼표·따옴표·줄바꿈이 든 글은 따옴표로 감싼다, dec 는 자릿수대로, bool 은 true/false). 쓴 바이트 수를 준다. dst 가 작으면 err.full(그때 dst 는 비어 있다)

(9b) 작업 공간(work area) 아무것도 할당하지 않는다(12절). load_xlsx 는 파일이 든 버퍼의 마지막 바이트 뒤 남은 용량을 쓴다: 약 130 KB(inflate의 창과 훑개의 버퍼)에 풀어낸 공유 문자열(하나에 4바이트와 그 글)을 더한 만큼이다. 버퍼는 파일보다 크게 선언해야 하고 자리가 모자라면 err.full 이다. 파일의 부품은 ZIP의 중앙 디렉터리로 찾는다. 16.11.1 읽기

(3) s toml.next 는 s 의 첫 문장을 읽어 (kind int, key str, value str, rest str) 를 준다(or fail): 머리이면(kind 는 toml.table 또는 toml.tables, key 는 괄호 사이의 이름 그대로, value 는 비었다), 쌍이면(key 는 적힌 대로 점과 따옴표까지, value 는 위와 같다). 빈 줄과 주석은 건너뛴다. 끝에 이르면 err.not_found, TOML 이 아닌 문장은 err.format 으로 실패한다. 프로그램이 지금 어느 머리 아래인지는 스스로 기억한다. 모든 key 는 그 머리에 상대적이다.

(4) path s toml.at 은 (kind int, value str) 를 준다(or fail): 파일을 읽는 사람이 보는 대로 path 가 가리키는 값. 경로는 점으로 이은 이름(따옴표를 친 이름 "a.b" 'a.b' 에는 점이 들 수 있다)과 괄호 안의 번호다: server.ports[1], user[0].name, a."b c".d. 점을 쓴 키(a.b.c = 1), 머리가 만든 표, 인라인 표, 배열을 모두 따라가고, 번호는 값 배열이나 표 배열([[...]] 머리의 차례, 한 원소 아래의 것은 그 원소에 속한다)의 원소를 고른다. 표를 가리키는 경로는 toml.table 과 값 없음을 준다. 없으면 err.not_found, 경로가 잘못됐거나 읽은 곳의 글이 잘못됐으면 err.format.

(5) s toml.valid 는 s 의 모든 문장이 꼴이 맞는지 준다. 검사는 문장 하나하나의 문법이다: 두 번 준 키, 두 번 정의한 표, 수의 범위, 있는 날짜인지는 검사하지 않는다.

말서명뜻

at(path str, s str gives kind int, value str or fail)s 에서 path 가 가리키는 값. err.not_found, err.format
next(s str gives kind int, key str, value str, rest str or fail)s 의 첫 문장과 그 뒤의 나머지. 끝에서 err.not_found, err.format

16.12 md — Markdown

(1) 모듈 md 는 사람이 쓰는 글인 Markdown 을 읽어 HTML 로 쓴다. CommonMark 의 부분집합에 GFM 의 표와 취소선을 더한 것으로, 스크립트가 만나는 메모, README, 쪽에 맞춘 것이지 규격의 구석구석까지 따르지 않는다. 글 속의 날 HTML 은 절대 넘기지 않는다: < 는 &lt; 로 쓴다. 주소의 체계가 http, https, mailto, tel, ftp 가 아닌 링크와 그림은 글만 쓴다. 그래서 Markdown 이 무엇이든 그 HTML 은 쪽에 넣어도 안전하다.

(2) 읽는 것. 블록: ATX 제목(# 에서 ######)과 밑줄 제목, 문단, 가로줄, 인용, 목록(- + * 글머리표, 1. 1) 번호, 중첩, 촘촘한 것과 성긴 것), 울타리 코드(백틱이나 물결표 셋 이상, 정보 문자열의 첫 낱말이 글자, 숫자, - _ + # . 이면 class="language-..." 가 된다), 들여쓴 코드, 표(한 줄, 정렬을 콜론으로 적은 줄, 줄들). 인라인: 강조 *a* _a_, 굵게 **a** __a__, 취소선 ~~a~~, 코드, 링크 [글](주소 "제목"), 그림 ![대체글](주소), 자동 링크 <https://...> 와 <a@b.c>, 역슬래시 이스케이프, 문자 참조(&amp; &#65;), 강제 줄바꿈(줄 끝 공백 둘 또는 역슬래시). 읽지 않는 것: 링크 참조 정의, 날 HTML, 목록 뒤의 밑줄 제목, 구두점 곁 강조의 CommonMark 세부 규칙. 이들은 글이나 보통 문단이 될 뿐 실패하지 않는다. 12 단보다 깊은 컨테이너나 강조의 중첩은 글로 쓴다. 링크, 강조, 코드의 닫는 표를 찾는 일은 글의 바이트마다 16 바이트의 예산으로 치르고, 예산이 다하면 남은 표는 글이 된다. 그래서 닫히지 않은 표뿐인 글도 크기에 비례하는 시간에 읽는다.

16.12.1 HTML 쓰기

(3) s b md.html 은 Markdown 글 s 의 HTML 을 버퍼 b 에 덧붙이고, s b md.inline 은 블록 없이 한 줄이나 한 문단만의 HTML 을 덧붙인다. 자리가 모자라면 err.full 로 실패한다(버퍼는 그대로). 자리는 HTML 자체에 더해, 인용이나 목록 항목을 쓰는 동안 그 복사본을 버퍼 끝에 둘 만큼, 곧 블록이 든 단마다 글보다 길지 않은 복사본 하나씩의 바이트가 더 든다. s 는 그 버퍼가 아니다.
