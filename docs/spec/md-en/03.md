# 3 Terms

(1) In this document the following words are used in these senses only. A term defined in a later clause is set in bold where it is defined.

(2) **processor**: an implementation that reads, checks and runs source; the library and the command `pnx` that uses it.

(3) **host**: the C program that embeds a processor. It provides memory, registers words and calls words of scripts.

(4) **state**: one unit of execution of a processor. Everything is inside one block of memory the host gave it. Two states share nothing.

(5) **source**: Pinax text loaded at once, one file or one string. One source is one module (clause 13).

(6) **load**: reading a source, checking it and adding it to a state. When a load refuses, the state is as it was before.

(7) **refusal**: a load not accepting a source. The processor reports the place (line and column) and the reason. No code of a refused source runs.

(8) **word**: an action called by name. Core words, words of standard modules, words a script defines and words a host registers all look the same where they are called.

(9) **signature**: what a word takes from the stack, what it gives, and whether it can fail (9.2).

(10) **stack**: where values pass from word to word. Its depth and the type of each place are fixed at load.

(11) **failure**: a word whose signature has `or fail` reporting that it could not do its work. The caller must handle it at the next token (11.2).

(12) **fault**: something that ends the run on the spot (overflow, division by zero, an index out of range and so on). A script cannot catch it; the host receives it (11.3).

(13) **region**: where the bytes of strings made while running are placed. Each task has one; a mark rewinds it (12.2).

(14) **view**: a string value that points at bytes without copying them; type `str` (7.3).

(15) **task**: a flow of execution that takes turns with others inside one state; it changes only where it yields (clause 14).

(16) **module**: a named collection of words and values: standard modules, host modules, modules written in Pinax (clause 13).

(17) In this document “shall” and “cannot” bind programs. A program that breaks them does not conform; the processor refuses it (what can be known at load) or stops with a fault (what can be known only while running). Each rule says which. “May” is a permission.
