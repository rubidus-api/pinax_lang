# 20 The command pnx

(1) `pnx` is a host that uses this library, and a development tool. It registers all the standard host modules (clause 17).

```text
pnx [--stats] [--lib NAME=PATH]... [--capacity NAME=N]... file.pnx [arguments]
pnx test file.pnx
pnx repl
pnx see file.pnx
pnx see --code file.pnx
pnx fmt file.pnx
pnx export-c file.pnx [NAME]
```

## 20.1 Running

(1) `pnx file.pnx arguments…` loads the file and runs its load code. For each module the file uses or names in `set_order` that is not registered, it first loads `MODULE.pnx` from beside the file (13.1, 13.5). The file is loaded as the module named after it without `.pnx`; when that name is not written like a procedure (it begins with a digit or contains `-`), the module has no name.

(2) There are three exit statuses, and the one a program gives with `sh.exit` (17.5).

| **Status** | **When** |
|---|---|
| 0 | the load code ran to its end; for `pnx test`, every test passed |
| 1 | a refusal: `file:line:column: reason` on standard error; a fault: `file:line: kind` and the locals of the procedure; for `pnx test`, a test failed |
| 2 | the command line is wrong (the usage is shown), the file cannot be read, a library of `--lib` cannot be opened, a `--capacity` is not `NAME=N` |

(3) `--lib NAME=PATH` opens the shared library at `PATH` so that the resolver finds its functions for `extern … from "NAME"` (clause 18). It finds only the functions that library defines (not those it imports). Without `--lib`, every `extern` is refused.

(3c) `pnx see --code file.pnx` loads the file without running it and lists the instructions of its procedures, one to a line: the address in the procedure, the name of the instruction and its fields, and the second word of an instruction that has one. It is for reading the code the compiler makes (how many instructions a turn of a loop costs); the format is not stable.

(3b) `--stats` writes one line to standard error after the run, the highest use of a state as `pinax_stats_get` gives it (19.10): `pnx: stats: N instructions; highest use: int slots A, str slots B, region R bytes, handles H, call depth D; block U of B bytes (P percent)`. Standard output and the exit status are unchanged. It is how to read what a script needs from a real input.

(3a) `--capacity NAME=N` gives the capacity a source writes `host` (8 (4a), 19.4 (1d)), for a run, `pnx test`, `pnx see`, `pnx export-c` and `pnx repl`. A plain `NAME` is a declaration of the file, `MODULE.NAME` one of a module it uses. `N` is 1 to 231 − 1, and at most 16 are given. Without it, a source that writes `host` is refused at load, with the name of the capacity.

(3b) What the script writes with `io.print` and `io.println` is kept in a buffer and written when the buffer is full, before `io.eprint` and `clock.sleep`, before `io.read_line` asks the system for more of standard input, and when the run ends or faults. So standard output and standard error come out in the order the script wrote them, and a prompt shows before the program waits for a line. Except in `pnx repl`, `io.read_line` reads standard input ahead; a line already read ahead is given without writing. A host that embeds the library writes and reads both without a buffer.

## 20.2 Tests

#### Syntax

```ebnf
test = "test" NAME "do" { body } "end" ;
```

(1) `test NAME do … end` defines a **test**: a procedure that takes and gives nothing. Tests do not run at load. `pnx test file.pnx` runs the tests of the file in order, writes `ok` or `FAIL` for each, and exits with 0 when all pass, 1 otherwise. A fault inside a test (a false `assert` included) is that test’s failure.

`20-test.pnx`

```pinax
use str .
def middle s str gives str do s 1 str.skip 1 str.skip_last end
test middle_trims_both_ends do
  "[abc]" middle "abc" eq assert
end
test middle_of_two_is_empty do
  "ab" middle str.is_empty assert
end
```

*Test run*

```text
$ pnx test 20-test.pnx
ok   middle_trims_both_ends
ok   middle_of_two_is_empty
2 tests, 0 failed
```

`20-test-fail.pnx`

```pinax
def twice n int gives int do n 2 mul end
test doubles do 21 twice 42 eq assert end
test wrong do 21 twice 43 eq assert end
```

*test-fail*

```text
$ pnx test 20-test-fail.pnx
ok   doubles
FAIL wrong (failed)
2 tests, 1 failed
```

## 20.3 Sessions

(1) `pnx repl` reads lines from standard input and runs them one at a time (`pinax_eval` of 19.4). After each line it writes the session stack on standard output, the deepest value first, when it is not empty. A line can use what earlier lines defined and the values they left (19.4 (2a)). A line that ends inside a definition or a block is read together with the next. A line that is refused or ends with a fault leaves the stack as it was. The end of a line, Enter, is a dot (10.8): what the line wrote is on the screen before the prompt comes back.

(2) There are tool procedures only for sessions: `list_words` (the procedures defined), `stack` (the types on the stack there), `clear` (at the start of a line: the line starts from an empty stack), `see` (the stack after every line of the definitions that follow), `redefine def …` (the same as `def …` for a procedure that exists, (2a)). `get_order` (13.5 (3a)) tells the search order, in a session and in a file.

(2a) `def NAME …` with the name of a procedure an earlier line of the session defined redefines it. With the same signature, every procedure that calls it calls the new one. With another signature the new procedure takes the name; the procedures compiled before keep calling the old body, which no longer has a name, and `pnx repl` names them (“2 procedures still call the old sq: quad, cube”). One procedure is redefined in a line, and none while a task is alive. A procedure of a module loaded from a file is not redefined in the session: edit the file and load it again.

`20-repl.pnx`

```pinax
use str .
3 4
mul
def sq n int gives int do n n mul end
sq
"x" 3 str.repeat
1 0 div
clear
2 sq
```

*Session*

```text
$ pnx repl
3 4
12
12
144
144 "xxx"
error: line 1: div_zero
4
```

## 20.4 Showing the stack, and formatting

(1) `pnx see file.pnx` shows, for every line of a definition, the stack (as types) where that line ends.

`20-see.pnx`

```pinax
use str .
def tally s str gives n int, longest int do
  0 to n
  0 to longest
  s str.words do to w
    n 1 add to n
    w str.len
    longest max to longest
  end each
  n longest
end
```

*Listing*

```text
$ pnx see 20-see.pnx
    3    0 to n                                         | (empty)
    4    0 to longest                                   | (empty)
    5    s str.words do to w                            | (empty)
    6      n 1 add to n                                 | (empty)
    7      w str.len                                    | int
    8      longest max to longest                       | (empty)
    9    end each                                       | (empty)
   10    n longest                                      | int int
```

(1a) When the source is refused, `pnx see` shows the lines before the place of the refusal, gives the diagnostic, and exits with 1.

`20-see-refused.pnx`

```pinax
def f n int gives int do
  n 1 add
  n
end
```

*Listing, then the refusal*

```text
$ pnx see 20-see-refused.pnx
    2    n 1 add                                        | int
    3    n                                              | int int
20-see-refused.pnx:4:1: the stack does not hold exactly the results of the signature here
```

(1b) `pnx see --checks file.pnx` loads the file as `pnx file.pnx` does (the code outside definitions runs), then shows, per procedure, the run-time checks the loader proved cannot fire: the procedure’s number of checks and of proven ones, and for each proven instruction its line, the instruction and the reason. A proof changes nothing a program does; the checks still run.

`20-see-checks.pnx`

```pinax
use io .
use str .
const days 7
array rain int days
record city
  name str 8
  people int
end
list cities city 4
def wettest gives int do                      rem the index of the largest cell
  0 to best
  0 rain len range do to i
    i rain idx  best rain idx  gt if i to best end
  end each
  best
end
def people_of i int gives int do i cities idx city.people end
assign rain (3, 0, 12, 7, 0, 1, 2)
wettest str.to_str io.println
```

*Output, then the checks*

```text
$ pnx see --checks 20-see-checks.pnx

  line 13: AGET: the index lies below the capacity of the array

  line 17: FGET: the row passed this table's check before
```

(1c) `pnx see --effects file.pnx` loads the file without running it and shows, for each procedure of the file, what it may do beyond its stack and locals (`pinax_word_effects`, 19.5 (5)): the globals it reads and writes, the host modules it reaches and whether it reads or writes through them, “anything (a C function)” for `extern`, “may yield” and “may fail”; “none” for a procedure that uses only its stack and locals.

`20-see-effects.pnx`

```pinax
use io .
global total int
def sq n int gives int do n n mul end
def add_up n int do total n add set total end
def report do args "total " total sq . cat io.println end
def ask gives line str or fail do io.read_line or_fail end
```

*The effects of each procedure*

```text
$ pnx see --effects 20-see-effects.pnx
sq: none
add_up: reads total; writes total
report: reads total; io writes
ask: io reads; may fail
```

(2) `pnx fmt file.pnx` writes the text with only indentation and spaces changed to standard output. Tokens, line breaks and remarks stay where they are. Formatting the result again changes nothing.

`20-fmt.pnx`

```pinax
use io .
def sign n int gives r int do
n 0 gt if
1
   else   
n 0 lt if -1 else 0 end
end
end
```

*Formatted*

```text
$ pnx fmt 20-fmt.pnx
use io .
def sign n int gives r int do
  n 0 gt if
    1
  else
    n 0 lt if -1 else 0 end
  end
end
```

(3) `pnx export-c file.pnx [NAME]` loads the file as `pnx file.pnx` does but runs none of its code, and writes the program’s code as C to standard output: a file that defines the table `NAME` (`pnx_native` when left out) for `pinax_native_attach` (19.11). Tool output, such as that of `get_order`, goes to standard error.
