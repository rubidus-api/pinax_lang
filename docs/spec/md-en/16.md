# 16 Standard modules

(1) The standard modules come with the processor. They are opened with `use MODULE` and written `MODULE.WORD` (13.1). Words of standard modules cannot reach outside without the host — they use no files, clocks or environment.

(2) Words of standard modules make no new storage. Their results are one of:

- a view of the bytes they were given; nothing is copied;
- a view of new bytes written in the region (12.2);
- bytes appended to a buffer the caller gave. Such words end in `_into` or take a buffer, and fail with `err.full` when there is not enough room.

## 16.1 str — strings

(1) The module `str` works on strings as bytes. Byte positions count from 0. Only the words that work on characters (`chars` `char_count` `is_utf8`) read UTF-8. Changing case (`upper` `lower`) changes ASCII only.

(2) Where a separator or a part to look for is taken (`sep`, `part`), a `str` or a single character (`int`, 6.5) may be given.

### 16.1.1 Looking and cutting

(3) All results are views of the string given.

| **Word** | **Signature** | **Meaning** |
|---|---|---|
| `len` `is_empty` | `(str gives int)` `(str gives bool)` | the number of bytes; is it empty |
| `take` `skip` | `(s str, n int gives str)` | the first `n` bytes; what follows them; when short, what there is |
| `take_last` `skip_last` | `(s str, n int gives str)` | the last `n` bytes; what comes before them |
| `slice` | `(s str, start int, n int gives str)` | `n` bytes from `start`; out of range is the fault `range` |
| `trim` `trim_left` `trim_right` | `(str gives str)` | the view without white space (space, tab, CR, LF) at the ends |
| `cut` | `(s str, sep gives str, str)` | before and after the first `sep`; without `sep`, `s` and the empty text |
| `try_cut` | `(s str, sep gives str, str or fail)` | like `cut`, but `err.not_found` without `sep` |
| `span` | `(s str, class int gives str, str)` | the leading bytes of that class, and the rest |

(4) The classes of `span` are the constants `str.digit` `str.alpha` `str.alnum` `str.space` `str.upper_case` `str.lower_case` `str.hex_digit` `str.punct` (ASCII).

`16-str-views.pnx`

```pinax
use io
use str
word show (label str, s str) cat (label, " [", s, "]") io.println end
word demo ()
  "  key = value  " to line
  "trim" line str.trim show
  "trim_left" line str.trim_left show
  "take 5" "hello, world" 5 str.take show
  "skip 7" "hello, world" 7 str.skip show
  "take_last 5" "hello, world" 5 str.take_last show
  "skip_last 7" "hello, world" 7 str.skip_last show
  "take 99" "short" 99 str.take show                 rem n beyond the end: what is there
  "slice 7 3" "hello, world" 7 3 str.slice show
  "key = value" " = " str.cut to (k, v)
  "cut, before" k show
  "cut, after" v show
  "a=b=c" '=' str.cut to (k2, v2)                    rem the separator may be a character
  "cut at a char" v2 show
  "2026-10-15" str.digit str.span to (year, rest)
  "span digits" year show
  "span rest" rest show
end
demo
```

### 16.1.3 Making new text

(6) The results are new bytes written in the region; when the region is used up it is the fault `full` (12.2). The words that read numbers can fail.

| **Word** | **Signature** | **Meaning** |
|---|---|---|
| `upper` `lower` | `(str gives str)` | ASCII case changed |
| `repeat` | `(s str, n int gives str)` | `n` copies joined; a negative `n` is the fault `range` |
| `replace` | `(s str, old str, new str gives str)` | every `old` replaced by `new` |
| `pad_left` `pad_right` | `(s str, width int gives str)` | filled with spaces to `width` bytes; as it is when longer; a `width` below 0 or from 232 up is the fault `range` |
| `to_str` | `(int gives str)` | decimal text; a `dec(N)` with its `N` digits after the point (7.5) |
| `to_dec` | `(s str, N gives dec(N) or fail)` | read a decimal: a sign, digits, and a point with at most `N` digits after it (`N` a constant); more digits, or anything else, `err.format` |
| `to_int` | `(str gives int or fail)` | read as decimal: one sign and digits only (no spaces); otherwise, or beyond 64 bits, `err.format` |
| `to_int_base` | `(s str, base int gives int or fail)` | read in base 2–36; another `base` is the fault `range` |

### 16.1.4 Stems and writing into buffers

(7) Words that make stems (10.6):

- `s sep str.split` — the pieces between `sep` s, empty ones included;
- `s str.words` — the pieces between white space, no empty ones;
- `s str.lines` — the lines, without their LF or CR LF;
- `s str.bytes` — the bytes ( `int` );
- `s str.chars` — one view ( `str` ) for each UTF-8 character.

(8) Words that write into a buffer:

- `sep buf STEM str.join_into` — appends the pieces of the stem joined by `sep` ( `or fail` ). The stem goes last, since the word right after a stem shall take it;
- `s old new buf str.replace_into` — appends the text with replacements and gives their number ( `gives n int or fail` ).

`16-str-stems.pnx`

```pinax
"" io.println

"가a!" str.chars do (c str) cat ("<", c, " ", c str.len, ">") io.print end each
"" io.println
buffer out 64

out contents io.println
out clear
word swap_dashes () "a-b-c" "-" "+" out str.replace_into or_else (e) 0 end to n  cat (out contents, " (", n, " replaced)") io.println end
```


## 16.2 fmt — numbers as text

(1) `cat` puts an `int` in decimal (9.8). Other forms are made into a `str` by the words of the module `fmt`. There is no small language of formats (such as `%08x`). Results are written in the region.

| **Word** | **Signature** | **Meaning** |
|---|---|---|
| `hex` `bin` | `(int gives str)` | hexadecimal (lower case), binary; a negative number as 64-bit two’s complement |
| `hex_pad` | `(n int, width int gives str)` | hexadecimal filled with leading zeros to `width` digits |
| `zero_pad` | `(n int, width int gives str)` | decimal filled with leading zeros to `width`; the sign takes a place |
| `append_hex` | `(n int, buf or fail)` | appends the hexadecimal to a buffer |

Decimal is `str.to_str`; decimal appended to a buffer is `append_int` (15.3). A `width` of `hex_pad` or `zero_pad` below 0 or from 232 up is the fault `range`; when the region is used up it is the fault `full`.


## 16.4 encode — bytes as text

(1) The words of the module `encode` are all `(s str, buf or fail)`. They append the result to the buffer and fail with `err.full` when there is not enough room, or `err.format` when the input has the wrong form.

| **Word** | **Meaning** |

## 16.5 bytes — binary data

(1) The module `bytes` writes numbers and text into a buffer as fixed byte forms, and reads them from bytes. The writing words are `(value, buf or fail)` (`err.full` when there is not enough room; nothing is written). The reading words are `(s str gives value, rest str or fail)` (`err.format` when the bytes run short or have the wrong form).

(2)

| **Word** | **Bytes** |
|---|---|
| `put_u8` `put_u16` `put_u32` `put_u64`  
`put_i8` `put_i16` `put_i32` `put_i64` | an integer of that width, least significant byte first |
| the same names with `_be` | most significant byte first |
| `get_u8` … `get_i64`, `get_u16_be` … | their pairs; `u8` `u16` `u32` read as non-negative; `u64` puts the 64 bits into the `int` as they are (negative when the top bit is set) |
| `put_varint` `get_varint` | LEB128: the value as an unsigned 64-bit number, 7 bits at a time (a negative takes 10 bytes) |
| `put_str` `get_str` | a length (varint), then the bytes |

`16-bytes.pnx`

```pinax

use str

  258 out bytes.put_u16_be or_fail         rem big end first: 01 02
  300 out bytes.put_varint or_fail         rem LEB128: ac 02
  "hi" out bytes.put_str or_fail           rem a varint length, then the bytes

  out contents to s

  s1 bytes.get_u16_be or_fail to (b, s2)
  s2 bytes.get_varint or_fail to (c, s3)
  s3 bytes.get_str or_fail to (d, s4)

end
demo or_else (e) e err_text io.println end
```

### 16.5.1 Records

(3) `row buf bytes.pack` appends one row of a record (8.8) to a buffer, field by field in order (`or fail`). `s row bytes.unpack` reads the fields from bytes into the row and gives the rest (`gives str or fail`). `row bytes.packed_size` is the number of bytes `pack` would write.

(4) The bytes of a field: an integer width as that width (most significant byte first when the record has `big_endian`, least significant first otherwise), `int` as 8 bytes, `bool` as 1 byte, `varint` as LEB128, `str(N)` as a length (varint) and the bytes, a field holding a row as the number it holds (varint).

(5) When `pack` fails the buffer goes back to the length it had before the call. `unpack` writes into the row only when every field can be read; when it fails the row is unchanged.

`16-bytes-pack.pnx`

```pinax

use bytes
use encode
use str
record item
  id u16
  name str(8)
  delta varint
end
record wire
  big_endian
  id u16
  count u32
end
array items item 2
array wires wire 1
buffer out 64
buffer hex 128
word dump () out contents hex encode.hex_encode or_else (e) end  hex contents io.println  hex clear end
word demo (or fail)
  0 items idx to a
  513 a to item.id  "pinax" a to item.name  -3 a to item.delta
  a out bytes.pack or_fail
  dump
  cat ("packed_size ", a bytes.packed_size, ", written ", out contents str.len) io.println
  1 items idx to b
  out contents b bytes.unpack or_fail to rest
  cat (b item.id, " ", b item.name, " ", b item.delta, ", rest ", rest str.len) io.println
  "\x01\x02\x05" b bytes.unpack or_else (e) cat ("short input: ", e err_text) io.println "" end drop
  cat ("the row is unchanged: ", b item.name) io.println
  out clear
  0 wires idx to w
  258 w to wire.id  7 w to wire.count
  w out bytes.pack or_fail
  dump
end
demo or_else (e) e err_text io.println end
```

## 16.6 ptn — small patterns

(1) The module `ptn` finds and replaces text with **pattern**s of the size of Lua’s. It has no alternation (`|`), no repetition of groups and no back references; `rex` (16.7) takes the larger grammar.

### 16.6.1 The text of a pattern

(2) A pattern is a sequence of the items below, matched byte by byte.

| **Item** | **Matches** |
|---|---|
| an ordinary character | that byte |
| `.` | any byte |
| `%a` `%d` `%l` `%u` `%s` `%w` `%x` `%p` `%c` | letters, digits, lower case, upper case, white space, letters or digits, hexadecimal digits, punctuation, control characters (ASCII); in upper case, everything else |
| `%` and a character that is not a letter or digit | that byte itself (`%.` `%%` `%(`) |
| `[…]` `[^…]` | a set and its complement, with `a-z` ranges and `%` classes inside; a `]` right after `[` or `[^` is a member |
| `*` `+` `-` `?` after an item | zero or more (longest), one or more (longest), zero or more (shortest), zero or one |
| `( … )` | a capture; up to nine |
| `^` first, `$` last | anchored at the start, at the end of the text |

`16-ptn-classes.pnx`

```pinax
use io
use ptn
"a1 B2_c3!" "%a" "." ptn.replace io.println     rem letters
"a1 B2_c3!" "%d" "." ptn.replace io.println     rem digits
"a1 B2_c3!" "%W" "." ptn.replace io.println     rem not letter or digit
"a1 B2_c3!" "[%u_]" "." ptn.replace io.println  rem a set: upper case or _
"aaab" "a-b" "<%0>" ptn.replace io.println      rem - is the shortest repetition
```

### 16.6.2 Words

(3)

| **Word** | **Signature** | **Meaning** |
|---|---|---|
| `is_match` | `(s str, pat gives bool)` | is there a match anywhere |
| `match` | `(s str, pat gives str or fail)` | a view of the first match; `err.not_found` when none |
| `capture` | `(n int gives str)` | capture `n` (1–9) of the last `match`; 0 is the whole match |
| `matches` | stem | the matches in order, each search starting where the last ended |
| `replace` | `(s str, pat, rep str gives str)` | new text with every match replaced by `rep`; in `rep`, `%0`–`%9` are captures and `%%` is `%` |

(4) A pattern that begins with `^` is tried at the start only, so `matches` and `replace` match at most once.

(5) The last match `capture` reads belongs to each run (task) separately; another `match` changes it. A run the host starts begins with no match: the match of an earlier run is not seen, since its captures are views of text that run matched, which may be gone.

`16-ptn.pnx`

## 16.7 rex — regular expressions

(1) The module `rex` finds and replaces with **regular expression**s. Its matching never goes back, so the time it takes is bounded by the length of the text times the size of the pattern. Write patterns as raw strings (6.5): in an ordinary string `"\d"` is refused as an unknown escape, and `"\b"` becomes a backspace.

(2) In a source that has `use rex` the type name `regex` is visible. A `regex` value is a pattern program that cannot be changed once made. It is used only in locals, arguments and results.

### 16.7.1 The text of a pattern

(3)

| **Form** | **Meaning** |
|---|---|
| a character | its bytes; a multi-byte character, its byte sequence |
| `.` | one UTF-8 character; without `(?s)` not a line break |
| `[abc]` `[a-z]` `[^…]` | a set; ranges are ASCII; a complemented set takes one UTF-8 character |
| `\d` `\w` `\s` `\D` `\W` `\S` | digits, word characters, white space and their complements (ASCII) |
| `*` `+` `?` `{n}` `{n,}` `{n,m}` | repetition (longest); with `?` after it, shortest |
| `a\|b` | alternation; the left first |
| `( … )` `(?: … )` | a group that captures, one that does not |
| `^` `$` | the start and end of the text; with `(?m)`, of each line |
| `\b` `\B` | a word boundary and its complement (ASCII) |
| `\n` `\t` `\r` `\f` `\v` `\0` `\xNN` | that byte |
| `\` and any other character | that character (`\.` `\*` `\\`) |
| `\zs` `\ze` | the match is narrowed to start, end here; the whole pattern must still match |
| `(?i)` `(?m)` `(?s)` | at the very start of a pattern only: ignore case (ASCII), anchors per line, `.` also matches a line break |

There are no back references, lookaround, Unicode properties or named groups.

(4) A pattern that repeats a body able to match the empty text (such as `(a*)*`) may give other captures than Perl or Python.

### 16.7.2 Words

(5) `re` is a `regex` value. “The match” is the range narrowed by `\zs` and `\ze`.

| **Word** | **Signature** | **Meaning** |
|---|---|---|
| `rx` | `(pat gives regex)` | makes the program at load; `pat` is a literal or a `const` |
| `compile` | `(pat str gives regex or fail)` | makes it while running; a malformed pattern is `err.format`; the program lies in the region |
| `is_match` | `(s str, re gives bool)` | is there a match |
| `match` | `(s str, re gives str or fail)` | the first match; `err.not_found` when none |
| `cut_match` | `(s str, re gives str, str, str or fail)` | what is before the first match, the match, and what is after |
| `matches` | stem | the matches in order; the block takes the whole match and one `str` parameter per group |
| `split` | stem | the pieces between the matches |
| `with_match` | `(s str, re, block or fail)` | runs the block once with the first match; `err.not_found` when none |
| `replace` | `(s str, re, rep str gives str)` | new text with every match replaced; in `rep`, `\0`–`\9` are groups |
| `replace_into` | `(s str, re, rep str, buf gives int or fail)` | appends the replaced text to a buffer and gives the number of replacements |
| `replace_by` | `(s str, re, buf, block gives int or fail)` | appends to a buffer, each match replaced by the text the block gives |

(6) When `matches`, `split` and `replace` search again from the next place, they still see the whole text, so `^` and `\b` know the bytes before that place.

`16-rex.pnx`

```pinax

  end each

  cat ("sum ", "id=7, x=20; name=kim, n=3" total) io.println

  "key: value" r":\s*" rex.rx rex.cut_match or_else (e) "" "" "" end to (before, m, after)
  cat ("[", before, "|", m, "|", after, "]") io.println
  "from 2026-10-13 to 2026-11-02" r"(\d{4})-(\d{2})-(\d{2})" rex.rx r"\3/\2/\1" rex.replace io.println
  "a , b;c ,d" r"\s*[,;]\s*" rex.rx rex.split do (part str) cat ("<", part, ">") io.print end each
  "" io.println
  "가나다" r"." rex.rx rex.matches do (ch str) cat ("<", ch, ">") io.print end each   rem . is one UTF-8 character
  "" io.println
  "foobar" r"foo\zsbar" rex.rx rex.match or_else (e) "?" end io.println              rem \zs: the match starts here
  "Hello" r"(?i)HELLO" rex.rx rex.is_match yes io.println
end

```

## 16.8 json — JSON

(1) The module `json` reads and writes JSON (RFC 8259) text in one direction, without building a tree: it reads one token at a time and writes straight into a buffer.

### 16.8.1 Reading

(2) `s json.next` reads the first token of `s` and gives `(kind int, value str, rest str)` (`or fail`). At the end it fails with `err.not_found`; on something that is not a token, with `err.format`. White space, commas and colons between tokens are passed over. The structure of the grammar — matching brackets, where commas go — is not checked.

(3) `kind` is one of the constants below. The `value` of a string is its text without the quotes; when it has escapes, they are decoded into text written in the region. The `value` of a number is its text as written.

| **Constant** | **Token** |
|---|---|
| `json.object` `json.object_end` | `{` `}` |
| `json.array` `json.array_end` | `[` `]` |
| `json.key` | a string followed by a colon |
| `json.string` | any other string |
| `json.number` | a number |
| `json.boolean` `json.null` | `true` `false`, `null` |

(4) `s json.skip` passes over one value (with everything inside, for an object or array) and gives the rest (`gives str or fail`).

`16-json-read.pnx`

```pinax
use io
use json
word kind_name (k int gives str)                    rem the kinds are constants of json
  k json.key eq if "key" return end
  k json.string eq if "string" return end
  k json.number eq if "number" return end
  k json.boolean eq if "boolean" return end
  k json.null eq if "null" return end
  k json.object eq k json.array eq or if "open" return end
  "close"
end
word tokens (s str)
  s to rest
  loop
    rest json.next or_else (e) break end to (kind, value, rest)
    cat (kind kind_name, " ", value) io.println
  end
end
text END
{"name": "kim", "tags": [1, -2.5e3, true, null], "note": "café"}
END
tokens
```

*Output*

```text

key name
string kim
key tags
open [
number 1
number -2.5e3
boolean true
null null
close ]

string café
close }
```

## 16.9 csv — CSV

(1) The module `csv` reads and writes CSV in the form of RFC 4180: fields are separated by commas; a field that holds a comma, a quote or a line break is quoted, and quotes inside it are doubled.

(2) `s csv.fields` is a stem (10.6) of the fields of one line. A quoted field is given without its quotes and with doubled quotes made single. An unclosed quote gives the rest of the text as the last field (a stem cannot report a failure).

(3) The writing words append to a buffer (`or fail`, `err.full` when there is not enough room). `s buf csv.put`, `n buf csv.put_int`, `d buf csv.put_dec` and `b buf csv.put_bool` append one field (with the comma it needs); `buf csv.end_line` ends the line. Booleans are written `true` and `false`.

(4) `row buf csv.pack` appends one row of a record as one line. `s row csv.unpack` reads one line into the fields in order and gives what follows the line. The row is written only when every field is right (`err.format`). A `dec(N)` field is read and written as in `json` (16.8).
