# 10 Control

#### Syntax

```ebnf
control = "if" { body } [ "else" { body } ] "end"
        | "loop" { body } "end"
        | "match" { branch } [ "otherwise" { body } "end" ] "end" ;
branch  = "when" case-value { case-value } "do" { body } "end" ;
leave   = ( "break" | "continue" ) [ INT ] "." | "return" ;
block   = "do" { "to" NAME } { body } "end"
        | "def" effect "do" { body } "end"       (* a block value, 10.5 *)
        | "ref" NAME ;
```

(1) `end` closes the innermost open construct. The words that open one are `def` `forward` `extern` `test` `record` `do` `if` `loop` `match` `when` `otherwise` `or_else` `defer`. (`forward` and `extern` are closed by the `end` after their signature, and so is `type NAME proc … end`.) (A `text` literal and a `note` remark close on their own tag, 6.3, 6.5.)

(2) At load a processor compares the stacks of all paths. Where paths meet again, the stack shall be the same whichever path was taken. A **leaving branch** — one that ends with `return`, `fail`, `break` or a loop that never ends — is not compared.

## 10.1 Branches

(1) `condition if body end` takes the `bool` on top and runs the body when it is true. `condition if body elsebody end` runs the `else` body when it is false.

(2) The body of an `if` without `else` shall leave the stack as it found it. With `else`, the two bodies shall leave the same stack.

`10-if.pnx`

```pinax
use io .
def sign n int gives str do n 0 lt if "negative" else n 0 eq if "zero" else "positive" end end end
-5 sign io.println
0 sign io.println
def warn n int do n 100 gt if "big" io.println end end      rem no else: the branch leaves the stack as it was
500 warn
```

*Output*

```text
$ pnx 10-if.pnx
negative
zero
big
```

#### Constraints

(3) Two branches that leave different stacks are refused.

`10-if-unequal.pnx`


## 10.2 Loops

(1) `loop body end` repeats its body. Inside it, these statements leave the loop:

- `break .` — leaves the loop and goes on after its `end` ;
- `continue .` — skips the rest of the turn and starts the next one;
- `break N .` and `continue N .` — do it to the `N` th loop counted from the innermost ( `N` is an integer literal of 1 or more, 1 when left out); the loops in between are left at once.

A condition is written with `if`: `x 0 eq if break . end`. A statement ends with a period. Each may be used any number of times, directly in the body of the loop or inside a branch in it (`if` `else` `match` `or_else`).

(2) One turn shall leave the stack as it found it, and at every place where the loop is left the stack shall be as it was when the loop was entered. A result of a loop is kept in a local.

`10-loop.pnx`

```pinax
use io .
use str .
def digits n int gives int do            rem how many decimal digits
  1 to count_
  loop
    n 10 div to n
    n 0 eq if break . end
    count_ 1 add to count_
  end
  count_
end
12345 digits str.to_str io.println
def first_square_over limit int gives int do
  1 to i
  loop
    i i mul limit gt if break . end
    i 1 add to i
  end
  i
end
50 first_square_over str.to_str io.println
```

*Output*

```text
$ pnx 10-loop.pnx
5
8
```

(3) A loop has no name. To leave an outer loop, count: `break 2 .` leaves two loops at once.

`10-loop-named.pnx`

```pinax
use io .
use str .
def find_pair target int gives str do      rem the first a, b in 1..9 with a*b = target
  1 to a
  0 to b
  loop
    1 to b
    loop
      a b mul target eq if break 2 . end       rem leaves both loops at once
      b 1 add to b
      b 9 gt if break . end
    end
    a 1 add to a
    a 9 gt if "none" return end
  end
  args a " x " b . cat
end
42 find_pair io.println
```

*Output*

```text
$ pnx 10-loop-named.pnx

```

(4) A loop with no `break` that leaves it never ends. A loop that never ends counts as a leaving branch, so a procedure does not need results after it. A `break .` of an inner loop does not count as leaving the outer one, but a `break 2 .` written in the inner loop does.

`10-forever.pnx`


```text

```

## 10.3 Choosing

(1) `value match when values… do body end … otherwise body end end` takes the `int`, narrow integer (7.6), `err` or `str` on top, compares it with the values of the branches and runs the body of the first equal one. A branch starts with `when`. The values of a branch are literals, `const`s of this source, error codes (`err.range`), or a constant or failure code another module exports (`module.NAME`, 8.14); several values stand after `when` one after another (no commas, no parentheses), and the `do` after them opens the body. When no branch matches, the `otherwise` body runs. Every branch shall leave the same stack.

`10-case.pnx`

```pinax
use io .
const quit_code 9
def describe cmd str gives str do
  cmd match
    when "add" do "adds a line" end
    when "rm" "del" do "deletes a line" end
    otherwise "unknown command" end
  end
end
def level n int gives str do
  n match
    when 0 do "off" end
    when 1 do "low" end
    when quit_code do "quit" end
    otherwise "high" end
  end
end
"del" describe io.println
"mv" describe io.println
9 level io.println
```

*Output*

```text
$ pnx 10-case.pnx
deletes a line
unknown command
quit
```

## 10.5 Blocks

(1) `do … end` is a **block**. A block is given to a combining word only (there is no `do … end` standing by itself); a block value is written with `def` (`def signature do … end`, (2a)). A block is used in two ways.

- An **inline block** — a block given directly to a combining word (10.6). It is expanded in place, so it can read and store the locals around it, and a `return` inside it leaves the word around it.
- A **block value** — `def signature do … end` stored in a local, or given to a parameter of a `proc … end` type (7.4). It becomes a nameless procedure, called with `call` . It does not see the locals around it (it captures nothing); it sees globals.

(2) An inline block takes the values the rail yields (and the number of `each_index`) into locals with `to NAME`, written one after another right after `do`. The names are taken from the top down: in `do to i to s … end each_index` `s` is the element and `i` the number (the element is put first, so `i` is on top). The signature of a block value is that of a procedure definition, and its names become locals.

`10-inline-locals.pnx`

```pinax
use io .
use str .
def total_over limit int gives int do
  0 to acc
  1 10 range do to i i limit gt if acc i add to acc end end each   rem the block sees acc and limit
  acc
end
5 total_over str.to_str io.println
```

*Output*

```text
$ pnx 10-inline-locals.pnx
30
```

`10-value-block.pnx`


(2a) `ref NAME` gives a procedure defined with `def`, of this source or exported by a module in use (`ref by_len`, `ref geo.area`), as a value: its type is `proc` with the procedure’s signature, and `call` calls it. Any other word is given in a block with the block’s signature; inputs given as types only stay on the stack (9.2 (2)), so the block’s body is the word alone: `def str, str gives bool do str.starts_with end`.

`10-word-value.pnx`

```pinax

def demo do
  ref by_len to order                          rem the word by_len itself: word (str, str gives bool)
  args "shorter: " order "pear" "fig" shorter . cat io.println
  def str, str gives bool do str.starts_with end to starts    rem a word of the language, with its signature
  "banana" "ban" starts call if "starts with ban" io.println end
end
demo
```

*Output*

```text
$ pnx 10-word-value.pnx
```

## 10.6 Rails and combining words

(1) A **rail** yields values one after another. A rail is not a value: it cannot be stored, and the combining word right after it shall take it. Together they make one loop. These make rails:

| **Rail** | **Elements** |
|---|---|
| the name of an array or list | the cells’ values (rows, for records); a list up to its length. Queues, buffers and indexes are not rails |
| the name of a pool | its live rows, in the order of their slots; for `each` only (8.9 (3a)) |
| `lo hi range` | the `int`s from `lo` up to but not including `hi` |
| `s sep str.split`, `s str.lines`, `s str.words`, `s str.chars` | `str` views (16.1); `chars` one UTF-8 character each |
| `s str.bytes` | `u8`: the bytes (16.1) |
| `s pat ptn.matches`, `s re rex.matches`, `s re rex.split` | the parts matched (16.6, 16.7) |
| `s csv.fields` | the fields (16.9) |

(2) The combining words are below; the “block” column is what the block takes and gives.

| **Word** | **Block** | **Result** |
|---|---|---|
| `each` | `(T)` | none |
| `each_index` | `(T, i int)` | none |
| `fold` | `(acc U, T gives U)` | `U`; the first value goes before the rail: `0 xs do … end fold` |
| `count` | `(T gives bool)` | `int` |
| `any` `all` | `(T gives bool)` | `bool`; stops early once the answer is known |
| `first` | `(T gives bool)` | `T or fail`; `err.not_found` when none |
| `sum` | none | `int` (of a rail of `dec N`, a `dec N`); an overflow is the fault `overflow` |
| `minimum` `maximum` | none | `int or fail` (`dec N` likewise); `err.not_found` for an empty rail |
| `map_into` | `(T gives U)` | a destination after it; `or fail` |
| `filter_into` | `(T gives bool)` | a destination after it; `or fail` |
| `n times` | `()` | none; no rail, `n` times |

(1a) An **adapter** takes a rail and gives a rail. `skip N` drops the first N elements, `head N` keeps the first N, `step N` takes every N-th element (the first one first), and `rev` walks from the last to the first. They apply in the order written and however many there are, the loop is one: `scores skip 2 head 3` is the third to the fifth, `scores head 3 skip 1` the second and the third. `N` is code that leaves one `int`; it ends at a comma, at `do`, at the next adapter and before `sum`, `minimum` or `maximum`. It is worked out once, before the loop. A negative `N` (a `step` of less than 1) is the fault `range`. Adapters are for rails of known length (`range`, an array, a list, `str.bytes`); `step` comes last; a rail takes four of them. `each_index` does not count along an adapted rail yet. `each`, `fold`, `count`, `any`, `all`, `first`, `map_into`, `filter_into`, `sum`, `minimum` and `maximum` take them.

`10-rail-adapters.pnx`

```pinax
use io .
use str .
array scores int 8
assign scores (10, 20, 30, 40, 50, 60, 70, 80)
def show n int do " " io.print n str.to_str io.print end
0 10 range step 3 do to i i show end each "" io.println          rem 0 3 6 9
scores skip 2 head 3 do to s s show end each "" io.println       rem the third to the fifth
scores head 3 skip 1 do to s s show end each "" io.println       rem the second and the third
scores rev head 3 do to s s show end each "" io.println          rem from the last
0 20 range skip 2 3 add, head 4 step 2 do to i i show end each "" io.println   rem N may be code, ended by a comma
scores skip 1 head 3 sum show "" io.println                      rem 20 + 30 + 40
```

*Output*

```text
$ pnx 10-rail-adapters.pnx

 5 7
```


(1b) `filter`, `map`, `skip_while` and `head_while` take the block written right before them (`do to s s 4 gt end filter`). The block takes the element and gives a `bool` (`filter` keeps the elements for which it is true, `skip_while` drops them while it is true, `head_while` ends the walk at the first for which it is false), or, for `map`, a value of the same type that takes the element’s place. They run inside the loop, once for each element and in the order written, and never for an element an earlier one dropped; so there is one loop, no storage and no call. A block adapter works on any rail, of known length or not (`str.words`, `str.lines`, …). `skip`, `head`, `step` and `rev` come before them in a chain. The name the block gives the element may be the one the final block uses.

`10-rail-block-adapters.pnx`

```pinax
use io .
use str .
array scores int 8
assign scores (3, 9, 4, 7, 1, 8, 2, 6)
def show n int do " " io.print n str.to_str io.print end
scores do to s s 4 gt end filter do to s s show end each "" io.println            rem 9 7 8 6
scores do to s s 10 mul end map do to s s show end each "" io.println             rem every element times ten
scores do to s s 5 lt end skip_while do to s s show end each "" io.println        rem from the first that is not below 5
scores do to s s 8 lt end head_while do to s s show end each "" io.println        rem until the first that is not below 8
scores do to s s 4 gt end filter do to s s 100 mul end map sum show "" io.println  rem 3000
"one two three four" str.words do to w w str.len 3 gt end filter do to w w io.println end each
```

*Output*

(3) `map_into` and `filter_into` make no new storage; they write into the destination. A list destination is pushed onto and nothing is given. An array destination is written from cell 0, and the number of cells written is given (`gives n int or fail`). When the destination is full, they fail with `err.full`; what was written stays. The destination may be a collection parameter (9.9).

`10-map-into.pnx`

```pinax
use io .
use str .
array xs int 4
assign xs (1, 2, 3, 4)
list squares int 4
array evens int 4
def go or fail do
  xs do to x x x mul end squares map_into or_fail
  xs do to x x 2 mod 0 eq end evens filter_into or_fail to n
  args "squares " 3 squares idx ", evens written " n . cat io.println
end
go or_else to e e err_text io.println end
```

*Output*

```text
$ pnx 10-map-into.pnx
squares 16, evens written 2
```

(4) A rail and its combining word make one loop, and in the block of `each`, `each_index` or `times`, `break .` leaves it and `continue .` goes to the next element: the rail stops and the code after the combining word runs. The rules of leaving a loop hold: the stack is as it was when the block began (10.2 (2)), and the block’s deferred code runs (10.7). A `break .` in a `loop` inside the block leaves that loop. `break N .` and `continue N .` count such blocks and `loop`s alike as levels (10.2 (1)); the operands of the inner blocks leave with them. The blocks of the other combining words, which give a result made from every element, are not left early, and are not crossed.

`10-leave-each.pnx`

```pinax
use io .
use str .
def until_blank s str do
  s str.lines do to line
    line str.len 0 eq if break . end
    args "> " line . cat io.println
  end each
  "done" io.println
end
"first\nsecond\n\nnot read" until_blank
```

*Output*

```text
$ pnx 10-leave-each.pnx
> first
> second
done
```

## 10.7 Deferred code

#### Syntax

```ebnf
defer = "defer" { body } "end" ;
```

(1) `defer CODE end` writes code that runs when the enclosing block is left. The block is a word’s body, a loop’s body (at every turn) or the `do` block of a combining word (at every run). The code runs on every way out of that block: the block’s `end`, the end of a turn, `break`, `continue`, `return`, `or_return`, `or_fail` and `fail`. Several run in the reverse of the order they are written. They do not run when a fault ends the run (the state closes the handles then, 19.6).

`10-defer.pnx`

```pinax
use io .
use str .
buffer trace 256
def say s str do s trace append or_else to e end end
rem Every way out of a block runs its defers, the last written first.
def step n int or fail do
  "open " say
  defer "close " say end
  defer "flush " say end
  n 0 lt if err.range fail end
  "work " say
end
1 step or_else to e end
-1 step or_else to e "(failed) " say end
trace contents str.trim io.println
```

*Output*

```text
$ pnx 10-defer.pnx
open work flush close open flush close (failed)
```

(2) When deferred code gives an owned value (`m release`, `f file.close`), the defer takes that value over. It counts as given on every way out of the block, so no failure path needs code of its own to close it. Inside the block the value can still be lent.

`10-defer-owned.pnx`

```pinax
use io .
use str .
buffer report 4096
rem A mark taken back at the end of every turn, also when append fails.
def build or fail do
  1 50 range do to i
    mark to m
    defer m release end
    args "row " i ": " i i mul "\n" . cat report append or_fail
  end each
end
build or_else to e args "full: " e err_text . cat io.println end
args "report: " report len " bytes" . cat io.println
```

*Output*

```text
$ pnx 10-defer-owned.pnx
report: 585 bytes
```

#### Constraints

(3) `defer` is written right in a word’s body, a loop’s body or a `do` block. In a branch of `if`, `match` or `or_else`, or outside a definition, it is refused.

`10-defer-branch.pnx`

```pinax
def f c bool do
  c if defer end end
end
```

*Refused*

```text
$ pnx 10-defer-branch.pnx
10-defer-branch.pnx:2:8: defer is written right in a word's body, a loop's body or a do block, not in a branch
```

(4) Deferred code leaves the stack as it found it and leaves nothing on it. It cannot hold `return` `fail` `break` `continue` `to` `set` `loop` `do` `match` `defer`, or `or_fail` `or_return`; a word that can fail is taken with `or_else` inside it.

(5) Giving an owned value that a defer took over, inside the block, is refused.

`10-defer-taken.pnx`

```pinax
def twice gives int do
  mark to m
  defer m release end
  m release
  0
end
```

*Refused*

```text
$ pnx 10-defer-taken.pnx
10-defer-taken.pnx:4:5: a defer gives this owned value when the block is left; here it can only be lent
```

## 10.8 Ends of statements

(1) A comma or a dot written in code (not inside a signature or an `args … .`) ends a **statement**: the code since the last comma or dot. Neither changes the stack, and neither is required: code without them means what it meant before.

(2) A comma waits for nothing: the effects of the statement may still be under way when the next one starts.

(3) A dot is a **barrier**: every effect begun before it is finished before anything after it. The processor’s part is to call the function the host gave with `pinax_on_barrier` (19.4 (3)); the host’s part is to write what its host words hold back (standard output, a file’s writes) and to wait for what they started in the background. The end of the code of a load and the end of a session line are a dot, also when they end with a fault. In a source loaded as data the two mark statements and call nothing.

(4) An effect whose result the statement needs (a read, a command’s output) is done when it is reached. Between two dots, effects on the same resource keep the order of the program; effects on different resources may overlap. This edition runs every effect in the order of the program; the overlap is the freedom a later edition may use.

`10-statements.pnx`

```pinax
use io .
def show n int do
  args "square: " n n mul . cat io.println .
end
"start" io.println ,
3 show ,
4 show .
```

*Output*

```text
$ pnx 10-statements.pnx
start
square: 9
square: 16
```
