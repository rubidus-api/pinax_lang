# 8 Declarations

## 8.1 General

#### Syntax

```ebnf
declaration = [ "export" ] ( [ "bound" ] bindable | decl ) ;
bindable    = "global" NAME type
            | "array"  NAME type size
            | "buffer" NAME size ;
decl        = "const"  NAME literal
            | "list"   NAME type size
            | "queue"  NAME type size
            | "pool"   NAME NAME size
            | "record" NAME { field | "big_endian" } "end"
            | "type"   NAME base
            | "index"  NAME NAME PATH
            | "tasks"  NAME size [ size [ size ] ]
            | "extern" c-name "(" effect ")" "from" STRING [ "as" NAME ]
            | "test"   NAME { body } "end" ;
size        = INT | NAME ;                         (* NAME: a const *)
```

(1) A **declaration** makes a name and what it stands for (a value, storage, a type). Declarations are written only outside definitions, at the outermost level of a source.

(2) A processor reads a source once, from top to bottom. A name shall be declared before the place where it is used. The exceptions are a word that calls itself, and `forward` (8.11).

(3) Within one module a name cannot be made twice, not even for different kinds of things. The names of core words and types cannot be made again either.

(4) A capacity (`size`) is a positive integer literal or a `const` of one. Capacities are fixed at load and do not change while running. All storage is placed inside the state’s block at load.

(5) Globals, cells of arrays, slots of lists, queues and pools, buffers and fields of records start at zero (7 (3)).

#### Constraints

(6) Making a name that exists already is refused.

`08-name-twice.pnx`

```pinax
global total int
const total 5
```

*Refused*

```text
$ pnx 08-name-twice.pnx
08-name-twice.pnx:2:7: this name is already defined
```

(7) Using a name before its declaration is refused.

`08-use-before.pnx`

```pinax
use str
word show (gives s str) total str.to_str end
global total int
```

*Refused*

```text
$ pnx 08-use-before.pnx
08-use-before.pnx:2:25: this name is not declared before this place
```

## 8.2 Constants

(1) `const NAME literal` makes a **constant**. Its type is the literal’s. A constant has no storage: its value goes where it is used. Constants can be capacities, `case` values and `row` values.

#### Constraints

(2) Nothing can be stored into a constant. Inside a definition `v to CONST` would make a new local of the same name and is refused by the rule against hiding names (9.5); outside a definition it is refused as a store into a name that is not a global.

`08-const-store.pnx`

```pinax
const limit 3
word raise () 4 to limit end
```

*Refused*

```text
$ pnx 08-const-store.pnx
08-const-store.pnx:2:20: this name is already visible here; a new name may not hide it
```

## 8.3 Globals

(1) `global NAME type` makes a **global** that holds one value. The type is `int`, `bool`, `str(N)`, a declared type, a row type (the name of a table) or a handle type; not `str` (7.3).

(2) A global is read by writing its name and stored with `to NAME`. Its value stays as long as the state does — after a word’s run ends, and across later loads.

`08-const-global.pnx`

```pinax
use io
use str
const limit 3
const greeting "hello"
global hits int
global last str(16)
global seen bool
hits str.to_str io.println           rem a global starts at zero
limit to hits
greeting to last
true to seen
cat (last, " ", hits, " ", seen) io.println
```

*Output*

```text
$ pnx 08-const-global.pnx
0
hello 3 true
```

## 8.4 Arrays

#### Syntax

```ebnf
assign-item = "assign" NAME "(" value { "," value } ")" ;
```

(1) `array NAME type capacity` makes an **array** with that many cells. An array is always full: `len` is its capacity. The element type is `int`, `bool`, `str(N)`, a declared type or the name of a record.

(2) `i ARRAY idx` reads cell `i`; `v i to ARRAY` stores into cell `i`. Numbers count from 0. For an array of records `idx` gives a row (8.8), not a value.

(3) `assign ARRAY (value, …)` fills an array from cell 0, outside definitions. With fewer values than cells the rest stay as they are. Assigning the same array again starts from cell 0 again. It may be used in a data load (13.4).

(4) The name of an array used as a stem yields its cells from 0 in order (10.6).

`08-array.pnx`

```pinax
use io
use str
array primes int 6
assign primes (2, 3, 5, 7)                rem cells 4 and 5 stay 0
11 4 to primes                            rem v i to array: store into cell i
primes do (p int) p str.to_str io.print " " io.print end each
"" io.println
cat ("len ", primes len, ", cell 2 is ", 2 primes idx) io.println
```

*Output*

```text
$ pnx 08-array.pnx
2 3 5 7 11 0 
len 6, cell 2 is 5
```

#### Constraints

(5) More values in `assign` than the array has cells is refused.

`08-assign-many.pnx`

```pinax
array small int 2
assign small (1, 2, 3)
```

*Refused*

```text
$ pnx 08-assign-many.pnx
08-assign-many.pnx:2:21: assign has more values than the array has cells
```

#### Faults

(6) An index below 0, or equal to or above the capacity, is the fault `range`.

`08-array-range.pnx`

```pinax
use io
array primes int 4
"reading cell 4 of 4" io.println
4 primes idx drop
```

*Fault*

```text
$ pnx 08-array-range.pnx
reading cell 4 of 4
08-array-range.pnx:4: index out of range
```

## 8.5 Lists

(1) `list NAME type capacity` makes a **list** whose length grows from 0 up to its capacity. Its cells are read and stored like an array’s, but only indexes below the length may be used.

(2) `v LIST push` adds one value at the end; `LIST pop` takes the last one off and gives it. Both can fail (`or fail`): a `push` into a full list fails with `err.full`, a `pop` from an empty list with `err.range`. A list of records gets an empty row at the end with `LIST add_row`, which gives that row. `LIST clear` sets the length to 0.

`08-list.pnx`

```pinax
use io
use str
list stack int 3
word fill (or fail)
  1 stack push or_fail
  2 stack push or_fail
end
fill or_else (e) "fill failed" io.println end
cat ("len ", stack len, " of ", stack capacity) io.println
stack pop or_else (e) -1 end str.to_str io.println
cat ("len ", stack len) io.println
```

*Output*

```text
$ pnx 08-list.pnx
len 2 of 3
2
len 1
```

`08-list-full.pnx`

```pinax
use io
list two int 2
1 two push or_else (e) end
2 two push or_else (e) end
3 two push or_else (e) cat ("third push failed: ", e err_text) io.println end
```

*Output*

```text
$ pnx 08-list-full.pnx
third push failed: full
```

(2a) `n LIST truncate` cuts the length to `n`, for lists of integers, of text and of records alike. It takes back a row added with `add_row` whose values turn out to be wrong.

`08-list-truncate.pnx`

```pinax
use io
record city
  name str(16)
  people int
end
list cities city 4
rem Add a row, and take it back when its values turn out wrong.
word add_city (name str, people int or fail)
  cities len to before
  cities add_row or_fail to c
  name c to city.name
  people 0 lt if before cities truncate err.format fail end
  people c to city.people
end
"Seoul" 9411000 add_city or_else (e) end
"Nowhere" -1 add_city or_else (e) cat ("refused: ", e err_text) io.println end
cat (cities len, " rows") io.println
```

*Output*

```text
$ pnx 08-list-truncate.pnx
refused: format
1 rows
```

#### Constraints

(2b) A list of records whose rows are kept elsewhere cannot be truncated. It is refused when the same source has a field or a global that holds its rows, a row of it named with `row`, or an index of it (8.10): once a new row takes the place cut off, they would point at the wrong row. A row held in a local is checked when it is used (fault `range`).

`08-list-truncate-kept.pnx`

```pinax
record city
  name str(16)
end
list cities city 4
index by_name cities city.name
word forget () 0 cities truncate end
```

*Refused*

```text
$ pnx 08-list-truncate-kept.pnx
08-list-truncate-kept.pnx:6:25: this list's rows are kept by a field, a global, a named row or an index; it cannot be truncated
```

#### Faults

(3) An index past the length is the fault `range`, even when it is below the capacity. So is a number for `truncate` larger than the length, or below zero.

`08-list-past-len.pnx`

```pinax
list items int 8
1 items push or_else (e) end
1 items idx drop                          rem the list holds one value: index 1 is past it
```

*Fault*

```text
$ pnx 08-list-past-len.pnx
08-list-past-len.pnx:3: index out of range
```

#### Diagnostics

| **Condition** | **Message** |
|---|---|
| `truncate` on a list whose rows are kept | `this list's rows are kept by a field, a global, a named row or an index; it cannot be truncated` |

## 8.6 Queues

(1) `queue NAME type capacity` makes a **queue**: what goes in first comes out first. The element type is `int`, `bool` or `err`. `v QUEUE put` puts a value at the back, `QUEUE take` takes the front one off and gives it, and `QUEUE peek` gives the front one without taking it. All three can fail: putting into a full queue is `err.full`, taking from an empty one `err.range`.

`08-queue.pnx`

```pinax
use io
use str
queue jobs int 4
word show (gives s str or fail) jobs take or_fail str.to_str end
10 jobs put or_else (e) end
20 jobs put or_else (e) end
jobs peek or_else (e) 0 end str.to_str io.println
show or_else (e) "?" end io.println
show or_else (e) "?" end io.println
show or_else (e) cat ("empty: ", e err_text) end io.println
```

*Output*

```text
$ pnx 08-queue.pnx
10
10
20
empty: range
```

## 8.7 Buffers

(1) `buffer NAME capacity` makes a **buffer** of that many bytes: a sequence of bytes that can be changed, for building text piece by piece.

(2) `s BUF append`, `n BUF append_int` (decimal) and `b BUF append_byte` add at the end; when there is not enough room they fail with `err.full` and add nothing. `BUF contents` gives a `str` view of what it holds now. `n BUF truncate` cuts the length to `n`. `BUF clear` sets the length to 0.

`08-buffer.pnx`

```pinax
use io
buffer out 32
word build (or fail)
  "x=" out append or_fail
  42 out append_int or_fail
  '!' out append_byte or_fail
end
build or_else (e) "full" io.println end
out contents io.println
2 out truncate
out contents io.println
```

*Output*

```text
$ pnx 08-buffer.pnx
x=42!
x=
```

(3) The view `contents` gives points at the buffer’s bytes: when the buffer changes, so do the bytes the view sees.

## 8.8 Records and rows

#### Syntax

```ebnf
record   = "record" NAME { field | "big_endian" } "end" ;
field    = NAME width ;
width    = "u8" | "u16" | "u32" | "u64" | "i8" | "i16" | "i32" | "i64"
         | "int" | "bool" | "varint" | "str" "(" size ")" | NAME ;   (* NAME: a table *)
row-item = [ "export" ] "row" NAME [ NAME ] "(" value { "," value } ")" ;
value    = literal | NAME ;                         (* NAME: a const, a row name, none *)
```

(1) `record NAME … end` makes a **record** type, a sequence of fields, each with a width. An integer field reads as `int`, a `bool` field as `bool`, a `str(N)` field as a `str` view. A field whose type is the name of a table holds a row of that table.

(2) Records are not handled as values. One declares an array, list or pool of records (a **table**) and handles its **row**s. A row’s type is named after its table. A row holds a number within the table, and every use checks its range (and, for a pool, its generation, 8.9).

(3) Fields are written as the path `RECORD.FIELD`: `row RECORD.FIELD` reads, `v row to RECORD.FIELD` stores.

(4) `row TABLE (value, …)` adds one row to a list, outside definitions. Values go in field order; trailing fields may be left out (they are zero). `row TABLE NAME (…)` names the row; the name stands for the row in later `row` values and in code.

`08-record.pnx`

```pinax
use io
record user
  name str(16)
  age u8
  admin bool
end
list users user 8
row users ("kim", 30, true)
row users lee ("lee", 25)                  rem a named row; the fields left out stay zero
word show (u users) cat (u user.name, " ", u user.age, " ", u user.admin) io.println end
users do (u users) u show end each
26 lee to user.age                         rem v row to record.field
lee show
```

*Output*

```text
$ pnx 08-record.pnx
kim 30 true
lee 25 false
lee 26 false
```

(5) A field or global that holds a row starts as “none”. `row is_none` asks whether it is none, `TABLE none` gives the none row of that table, and `row row_index` gives the row’s number.

(6) `big_endian` sets only the byte order that `bytes.pack` and `bytes.unpack` of 16.5 use. It does not change the layout in memory.

#### Constraints

(7) The values of `row` shall match the fields in order and type.

`08-row-types.pnx`

```pinax
record user
  name str(16)
  age u8
end
list users user 8
row users (30, "kim")
```

*Refused*

```text
$ pnx 08-row-types.pnx
08-row-types.pnx:6:12: a value has another type than its field
```

#### Faults

(8) Storing a value that does not fit a narrow integer field is the fault `overflow`; it is not cut (mask it with `bit_and` first to store part of it). Reading or storing a field of the none row is the fault `range`.

`08-record-narrow.pnx`

```pinax
record pixel
  level u8
end
array image pixel 4
300 0 image idx to pixel.level            rem 300 does not fit in u8
```

*Fault*

```text
$ pnx 08-record-narrow.pnx
08-record-narrow.pnx:5: integer overflow
```

## 8.9 Pools

(1) `pool NAME RECORD capacity` makes a **pool** of rows that are taken and given back. `POOL alloc` takes a free row (`or fail`, `err.full` when none is left); `row POOL free` gives it back; `row POOL is_alive` asks whether the row is still alive.

(2) A row of a pool holds a **generation** besides its number. Giving a row back changes the generation of its slot, so a row used after it was given back is noticed — even when another row has taken the slot since.

(3) The row `alloc` gives is an `owned` value (12.4). On every path it shall be stored exactly once into a field or global, or given to `free`. Once stored, the generation check guards it.

`08-pool.pnx`

```pinax
use io
record node
  value int
end
pool nodes node 2
global kept nodes
word demo (or fail)
  nodes alloc or_fail to a                 rem an owned row: it must be stored or freed
  7 a to node.value
  a to kept                                rem stored: the global holds the row now
  cat ("value ", kept node.value, ", alive: ", kept nodes is_alive) io.println
  kept nodes free
  cat ("alive after free: ", kept nodes is_alive) io.println
end
demo or_else (e) "no room" io.println end
```

*Output*

```text
$ pnx 08-pool.pnx
value 7, alive: true
alive after free: false
```

#### Constraints

(4) A path on which a taken row is neither stored nor given back is refused.

`08-pool-leak.pnx`

```pinax
record node
  value int
end
pool nodes node 2
word leak (or fail)
  nodes alloc or_fail to a
  7 a to node.value
end
```

*Refused*

```text
$ pnx 08-pool-leak.pnx
08-pool-leak.pnx:8:1: an owned value in a local is not given on every path (close, free or store it)
```

#### Faults

(5) Using a row that was given back is the fault `stale`. `pnx` shows the locals of the word below the fault.

`08-pool-stale.pnx`

```pinax
record node
  value int
end
pool nodes node 2
global keep nodes
word demo (or fail)
  nodes alloc or_fail to a
  a to keep                                 rem stored: the row is handed over
  keep nodes free
  keep node.value drop                      rem the row was given back: stale
end
demo or_else (e) end
```

*Fault*

```text
$ pnx 08-pool-stale.pnx
08-pool-stale.pnx:10: a row or handle was used after it was given back
  a nodes = 4294967297
```

## 8.10 Indexes

(1) `index NAME TABLE RECORD.FIELD` makes an **index** that finds rows of a table of records by one field. The key field is `int` or `str(N)`. An index is a hash table of fixed size, matched to the table’s capacity, that holds only row numbers; the data stay in the table.

(2) `key INDEX lookup` gives the row with that key (`or fail`, `err.not_found` when there is none). `row INDEX insert` puts a row in (`or fail`; it fails when the key is there already) and `row INDEX remove` takes it out. To change a key field, remove the row, change it and insert it again.

(3) Rows written with `row` at load are in the index. Rows added while running with `add_row` are found only after `insert`.

`08-index.pnx`

```pinax
use io
use str
record user
  name str(16)
  age u8
end
list users user 8
index by_name users user.name
row users ("kim", 30)
row users ("lee", 25)
word find_age (name str gives age int or fail) name by_name lookup or_fail user.age end
"lee" find_age or_else (e) -1 end str.to_str io.println
"park" find_age or_else (e) -1 end str.to_str io.println
```

*Output*

```text
$ pnx 08-index.pnx
25
-1
```

`08-index-insert.pnx`

```pinax
use io
use str
record user
  name str(16)
  age int
end
list users user 4
index by_name users user.name
word add_user (name str, age int, indexed bool or fail)
  users add_row or_fail to r
  name r to user.name
  age r to user.age
  indexed if r by_name insert or_fail end  rem a row added while running is indexed by insert
end
word age_of (name str gives int or fail) name by_name lookup or_fail user.age end
"kim" 30 true add_user or_else (e) end
"lee" 25 false add_user or_else (e) end
"kim" age_of or_else (e) -1 end str.to_str io.println
"lee" age_of or_else (e) -1 end str.to_str io.println     rem not inserted: not found
```

*Output*

```text
$ pnx 08-index-insert.pnx
30
-1
```

(4) The hash is keyed (SipHash-2-4); the host gives the key (19.2). A host that indexes text from outside should give a random key: whoever knows the key can pile up collisions and make lookups slow.

## 8.11 Forward declarations

#### Syntax

```ebnf
forward = "forward" ( "array" | "list" | "pool" ) NAME
        | "forward" "word" NAME "(" effect ")" ;
```

(1) `forward list NAME` announces a table declared further on. It is for a record that holds rows of the table that holds it. The name of an announced table may be used only where a type goes. `forward word` is in 9.7.

`08-forward.pnx`

```pinax
use io
use str
forward list nodes                         rem the record below points into this list
record node
  value int
  next nodes
end
list nodes node 4
row nodes b (2)
row nodes a (1, b)
a node.next node.value str.to_str io.println
a node.next node.next is_none if "the chain ends at b" io.println end
```

*Output*

```text
$ pnx 08-forward.pnx
2
the chain ends at b
```

#### Constraints

(2) An announced table shall be declared in the same module with the same kind.

`08-forward-missing.pnx`

```pinax
forward list nodes
record node
  value int
end
```

*Refused*

```text
$ pnx 08-forward-missing.pnx
08-forward-missing.pnx:5:1: a table announced by forward is never declared
```

## 8.12 Bound storage

(1) `global`, `array` and `buffer` with `bound` in front get their storage from the host. Scripts use them like other globals. Until the host binds them they use room inside the state. 19.7 says how to bind.

#### Diagnostics

| **Condition** | **Message** |
|---|---|
| A name that exists already | `this name is already defined` |
| A name used before its declaration | `this name is not declared before this place` |
| `to` outside a definition into a name that is not a global | ``outside a definition `to` stores into a declared global, not a new local`` |
| More `assign` values than cells | `assign has more values than the array has cells` |
| A `row` value unlike its field | `a value has another type than its field` |
| A path that does not hand over an `owned` row | `an owned value in a local is not given on every path (close, free or store it)` |
| An announced table that is never declared | `a table announced by forward is never declared` |
