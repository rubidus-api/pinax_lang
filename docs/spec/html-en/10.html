10 Control

Syntax
control = "if" { body } [ "else" { body } ] "end"
        | "loop" { body } "end"
        | "match" { branch } [ "otherwise" { body } "end" ] "end" ;
branch  = "when" case-value { case-value } "do" { body } "end" ;
leave   = ( "break" | "continue" ) [ INT ] "." | "return" ;
block   = "do" { "to" NAME } { body } "end"
        | "def" effect "do" { body } "end"       (* a block value, 10.5 *)
        | "ref" NAME ;

(1) end closes the innermost open construct. The procedures that open one are def forward extern test record do if loop match when otherwise or_else defer. (forward and extern are closed by the end after their signature, and so is type NAME proc … end.) (A text literal and a note remark close on their own tag, 6.3, 6.5.)

(2) At load a processor compares the stacks of all paths. Where paths meet again, the stack shall be the same whichever path was taken. A leaving branch — one that ends with return, fail, break or a loop that never ends — is not compared.

10.1 Branches

(1) condition if body end takes the bool on top and runs the body when it is true. condition if body else
body end runs the else body when it is false.

(2) The body of an if without else shall leave the stack as it found it. With else, the two bodies shall leave the same stack.

use io .

10.2 Loops

(1) loop body end repeats its body. Inside it, these statements leave the loop:

  • break . — leaves the loop and goes on after its end;
  • continue . — skips the rest of the turn and starts the next one;
  • break N . and continue N . — do it to the Nth loop counted from the innermost (N is an integer literal of 1 or more, 1 when left out); the loops in between are left at once.

A condition is written with if: x 0 eq if break . end. A statement ends with a period. Each may be used any number of times, directly in the body of the loop or inside a branch in it (if else match or_else).

(2) One turn shall leave the stack as it found it, and at every place where the loop is left the stack shall be as it was when the loop was entered. A result of a loop is kept in a local.

10.3 Choosing

(1) value match when values… do body end … otherwise body end end takes the int, narrow integer (7.6), err or str on top, compares it with the values of the branches and runs the body of the first equal one. A branch starts with when. The values of a branch are literals, consts of this source, error codes (err.range), or a constant or failure code another module exports (module.NAME, 8.14); several values stand after when one after another (no commas, no parentheses), and the do after them opens the body. When no branch matches, the otherwise body runs. Every branch shall leave the same stack.

10-case.pnx

use io .
const quit_code 9
def describe cmd str gives str do
  cmd match
    when "add" do "adds a line" end
    when "rm" "del" do "deletes a line" end
    otherwise "unknown command" end
  end
end
def level n int gives str do
  n match
    when 0 do "off" end
    when 1 do "low" end
    when quit_code do "quit" end
    otherwise "high" end
  end
end
"del" describe io.println
"mv" describe io.println
9 level io.println

10.5 Blocks

(1) do … end is a block. A block is given to a combining procedure only (there is no do … end standing by itself); a block value is written with def (def signature do … end, (2a)). A block is used in two ways.

  • An inline block — a block given directly to a combining procedure (10.6). It is expanded in place, so it can read and store the locals around it, and a return inside it leaves the procedure around it.
  • A block value — def signature do … end stored in a local, or given to a parameter of a proc … end type (7.4). It becomes a nameless procedure, called with call. It does not see the locals around it (it captures nothing); it sees globals.

(2) An inline block takes the values the rail yields (and the number of each_index) into locals with to NAME, written one after another right after do. The names are taken from the top down: in do to i to s … end each_index s is the element and i the number (the element is put first, so i is on top). The signature of a block value is that of a procedure definition, and its names become locals.

(2a) ref NAME gives a procedure defined with def, of this source or exported by a module in use (ref by_len, ref geo.area), as a value: its type is proc with the procedure’s signature, and call calls it. Any other procedure is given in a block with the block’s signature; inputs given as types only stay on the stack (9.2 (2)), so the block’s body is the procedure alone: def str, str gives bool do str.starts_with end.

(2b) A value of a proc type may also be the cell of an array or a list, a field of a record (so a row of a table or of a pool) or a global (array ops Op 3, ref plus 0 set ops, 3 4 0 ops idx call). It is kept as the number of the procedure plus one, so that a cell nothing was written to holds none: is_none asks it, and calling none is the fault range. A cell cannot hold a procedure of another signature (the refusal is at the write). Such cells are not ordered, summed, compared or used as the key of an index. A container saved before this (version 5 or older) is refused when loaded.

10.6 Rails and combining procedures

(1) A rail yields values one after another. A rail is not a value: it cannot be stored, and the combining procedure right after it shall take it. Together they make one loop. A rail is a closed rail when its length is known before the walk and the element at any place can be read (range, an array, a list, str.bytes), and an open rail when it is not: the pieces are taken one after another from a source and the walk is made once (str.split, str.lines, str.words, str.chars, ptn.matches, rex.matches, rex.split, csv.fields, a pool). A rail is evaluated lazily: the loop takes one element at a time, in the order of the walk, and the blocks of the adapters run only for the elements that reach them. A walk that ends early (head, head_while, first, any, break) reads and evaluates nothing more, and nothing is stored between the stages. These make rails:

RailElements
the name of an array or listthe cells’ values (rows, for records); a list up to its length. Queues, buffers and indexes are not rails
the name of a poolits live rows, in the order of their slots; for each only (8.9 (3a))
lo hi rangethe ints from lo up to but not including hi
s sep str.split, s str.lines, s str.words, s str.charsstr views (16.1); chars one UTF-8 character each
s str.bytesu8: the bytes (16.1)
s pat ptn.matches, s re rex.matches, s re rex.splitthe parts matched (16.6, 16.7)
s csv.fieldsthe fields (16.9)

(2) The combining procedures are below; the “block” column is what the block takes and gives.

(1a) An adapter takes a rail and gives a rail. skip N drops the first N elements, head N keeps the first N, step N takes every N-th element (the first one first), and rev walks from the last to the first. They apply in the order written and however many there are, the loop is one: scores skip 2 head 3 is the third to the fifth, scores head 3 skip 1 the second and the third. N is code that leaves one int; it ends at a comma, at do, at the next adapter and before sum, minimum or maximum. It is worked out once, before the loop. A negative N (a step of less than 1) is the fault range. step and rev need a closed rail. skip and head also work on an open rail, where they count the pieces as they come; step comes last; a rail takes sixteen of them. each_index does not count along an adapted rail yet. each, fold, count, any, all, first, map_into, filter_into, sum, minimum and maximum take them.

(1b) filter, map, skip_while and head_while take the block written right before them (do to s s 4 gt end filter). The block takes the element and gives a bool (filter keeps the elements for which it is true, skip_while drops them while it is true, head_while ends the walk at the first for which it is false), or, for map, a value of the same type that takes the element’s place. They run inside the loop, once for each element and in the order written, and never for an element an earlier one dropped; so there is one loop, no storage and no call. A block adapter works on any rail, closed or open (str.words, str.lines, …). On a closed rail skip, head, step and rev come before them in a chain; on an open rail they may stand anywhere, and count the pieces that reach them. The name the block gives the element may be the one the final block uses. The block gives a value and leaves no loop: break and continue in it are refused at load (a loop of its own inside the block may use them); drop an element with filter, end the walk with head_while.

(1e) A rail may give several values at a turn (zip, json.items, json.members, toml.items, md.blocks); the block of each binds as many names as the rail gives, the last pushed first, and skip and head apply to it but the adapters with a block do not. Some rails can fail while they are walked (the rails of json, toml, md and sqlite.rows): the text may be damaged after some good elements, the engine may fail. The failure ends the loop and is the failure of the procedure each, so it is taken as every failure is: each is followed by or_fail, or_return or or_else. The end of the elements is not a failure. The rows of a book of sheet need no rail of their own: 0 g sheet.rows range and 0 g sheet.cols range walk their numbers.

(4) A rail and its combining procedure make one loop, and in the block of each, each_index or times, break . leaves it and continue . goes to the next element: the rail stops and the code after the combining procedure runs. The rules of leaving a loop hold: the stack is as it was when the block began (10.2 (2)), and the block’s deferred code runs (10.7). A break . in a loop inside the block leaves that loop. break N . and continue N . count such blocks and loops alike as levels (10.2 (1)); the operands of the inner blocks leave with them. The blocks of the other combining procedures, which give a result made from every element, are not left early, and are not crossed.

10.7 Deferred code

Syntax
defer = "defer" { body } "end" ;

(1) defer CODE end writes code that runs when the enclosing block is left. The block is a procedure’s body, a loop’s body (at every turn) or the do block of a combining procedure (at every run). The code runs on every way out of that block: the block’s end, the end of a turn, break, continue, return, or_return, or_fail and fail. Several run in the reverse of the order they are written. They do not run when a fault ends the run (the state closes the handles then, 19.6).

10-defer.pnx

use io .
use str .
buffer trace 256
def say s str do s trace append or_else to e end end
rem Every way out of a block runs its defers, the last written first.
def step n int or fail do
  "open " say
  defer "close " say end
  defer "flush " say end
  n 0 lt if err.range fail end
  "work " say
end
1 step or_else to e end
-1 step or_else to e "(failed) " say end
trace contents str.trim io.println

Output

$ pnx 10-defer.pnx

(2) When deferred code gives an owned value (m release, f file.close), the defer takes that value over. It counts as given on every way out of the block, so no failure path needs code of its own to close it. Inside the block the value can still be lent.

10.8 Ends of statements

(1) A comma or a dot written in code (not inside a signature or an args … .) ends a statement: the code since the last comma or dot. Neither changes the stack, and neither is required: code without them means what it meant before.

(2) A comma waits for nothing: the effects of the statement may still be under way when the next one starts.

(3) A dot is a barrier: every effect begun before it is finished before anything after it. The processor’s part is to call the function the host gave with pinax_on_barrier (19.4 (3)); the host’s part is to write what its host procedures hold back (standard output, a file’s writes) and to wait for what they started in the background. The end of the code of a load and the end of a session line are a dot, also when they end with a fault. In a source loaded as data the two mark statements and call nothing.

(4) An effect whose result the statement needs (a read, a command’s output) is done when it is reached. Between two dots, effects on the same resource keep the order of the program; effects on different resources may overlap. This edition runs every effect in the order of the program; the overlap is the freedom a later edition may use.
