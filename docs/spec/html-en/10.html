10 Control

Syntax
control = "if" { body } [ "else" { body } ] "end"
        | "loop" [ "(" NAME ")" ] { body } "end"
        | "case" { branch } [ "otherwise" { body } "end" ] "end" ;
branch  = values "of" { body } "end" ;
values  = case-value | "(" case-value { "," case-value } ")" ;
leave   = ( "while" | "until" | "break" ) [ "(" NAME ")" ] | "return" ;
block   = "do" [ "(" effect ")" ] { body } "end" ;

(1) end closes the innermost open construct. The words that open one are word test record do if loop case of otherwise or_else defer. (A text literal and a note remark close on their own tag, 6.3, 6.5.)

(2) At load a processor compares the stacks of all paths. Where paths meet again, the stack shall be the same whichever path was taken. A leaving branch — one that ends with return, fail, break or a loop that never ends — is not compared.

10.1 Branches

(1) condition if body end takes the bool on top and runs the body when it is true. condition if body else
body end runs the else body when it is false.

(2) The body of an if without else shall leave the stack as it found it. With else, the two bodies shall leave the same stack.

10-if.pnx

use io
word sign (n int gives str) n 0 lt if "negative" else n 0 eq if "zero" else "positive" end end end
-5 sign io.println
0 sign io.println
word warn (n int) n 100 gt if "big" io.println end end      rem no else: the branch leaves the stack as it was
500 warn

Output

$ pnx 10-if.pnx
negative
zero
big
Constraints

(3) Two branches that leave different stacks are refused.

10-if-unequal.pnx

word f (n int gives int) n 0 lt if 1 2 else 3 end end

Refused

$ pnx 10-if-unequal.pnx
10-if-unequal.pnx:1:47: the two branches of this if leave different stacks

10.2 Loops

(1) loop body end repeats its body. Inside it, these words leave the loop:

  • condition while — leaves when the condition is false;
  • condition until — leaves when the condition is true;
  • break — leaves without a condition.

Each may be used any number of times, directly in the body of the loop or inside a branch in it (if else case or_else). They leave the innermost loop.

(2) One turn shall leave the stack as it found it, and at every place where the loop is left the stack shall be as it was when the loop was entered. A result of a loop is kept in a local.

10-loop.pnx

use io
use str
word digits (n int gives int)            rem how many decimal digits
  1 to count_
  loop
    n 10 div to n
    n 0 eq until
    count_ 1 add to count_
  end
  count_
end
12345 digits str.to_str io.println
word first_square_over (limit int gives int)
  1 to i
  loop
    i i mul limit gt if break end
    i 1 add to i
  end
  i
end
50 first_square_over str.to_str io.println

Output

$ pnx 10-loop.pnx
5
8

(3) loop (NAME) names a loop. while (NAME), until (NAME) and break (NAME) leave everything up to that loop at once. The name is visible only inside the loop’s body and is not a value. It follows the rule against hiding (9.5).

10-loop-named.pnx

use io
use str
word find_pair (target int gives str)      rem the first a, b in 1..9 with a*b = target
  1 to a
  0 to b
  loop (rows)
    1 to b
    loop
      a b mul target eq until (rows)       rem leaves both loops at once
      b 1 add to b
      b 9 gt until
    end
    a 1 add to a
    a 9 gt if "none" return end
  end
  cat (a, " x ", b)
end
42 find_pair io.println

Output

$ pnx 10-loop-named.pnx
6 x 7

(4) A loop with no while, until or break that leaves it never ends. A loop that never ends counts as a leaving branch, so a word does not need results after it. An until of an inner loop does not count as leaving the outer one, but an until (outer name) written in the inner loop does.

10-forever.pnx

use io
use str
word first_multiple (n int, k int gives int)     rem a loop with no exit counts as leaving
  loop
    n k mod 0 eq if n return end
    n 1 add to n
  end
end
100 7 first_multiple str.to_str io.println

Output

$ pnx 10-forever.pnx
105

(5) A turn that changes the stack is refused.

10.3 Choosing

(1) value case branches… end takes the int, narrow integer (7.6), err or str on top, compares it with the values of the branches and runs the body of the first equal one. The values of a branch are literals or consts of this source; several values go in parentheses with commas. When no branch matches, the otherwise body runs. Every branch shall leave the same stack.

10-case.pnx

use io
const quit_code 9
word describe (cmd str gives str)
  cmd case
    "add" of "adds a line" end
    ("rm", "del") of "deletes a line" end
    otherwise "unknown command" end
  end
end
word level (n int gives str)
  n case
    0 of "off" end
    1 of "low" end
    quit_code of "quit" end
    otherwise "high" end
  end
end
"del" describe io.println
"mv" describe io.println
9 level io.println

Output

$ pnx 10-case.pnx
deletes a line
unknown command
quit
Constraints

(2) The same value in two branches is refused.

10-case-twice.pnx

Refused

10.4 Returning

(1) return ends the word on the spot. The stack there shall match the results (9.2 (4)).

Constraints

(2) return is used only inside a definition (a word, a block value, a test). In code outside definitions it is refused.

10-return-outside.pnx

use io
"start" io.println
return

Refused

$ pnx 10-return-outside.pnx
10-return-outside.pnx:3:1: return belongs inside a definition

10.5 Blocks

(1) do … end is a block. A block is used in two ways; the form is the same, and what takes the block decides.

  • An inline block — a block given directly to a combining word (10.6). It is expanded in place, so it can read and store the locals around it, and a return inside it leaves the word around it.
  • A block value — a block stored in a local, or given to a parameter of type word (signature). It becomes a nameless word, called with call. It does not see the locals around it (it captures nothing); it sees globals.

(2) A signature may follow do; its names become locals of the block, as in a word definition. When what takes the block fixes its effect, the signature may be left out.

10-inline-locals.pnx

use io
use str
word total_over (limit int gives int)
  0 to acc
  1 10 range do (i int) i limit gt if acc i add to acc end end each   rem the block sees acc and limit
  acc
end
5 total_over str.to_str io.println

Output

$ pnx 10-inline-locals.pnx
30

10.6 Stems and combining words

(1) A stem yields values one after another. A stem is not a value: it cannot be stored, and the combining word right after it shall take it. Together they make one loop. These make stems:

(3) map_into and filter_into make no new storage; they write into the destination. A list destination is pushed onto and nothing is given. An array destination is written from cell 0, and the number of cells written is given (gives n int or fail). When the destination is full, they fail with err.full; what was written stays. The destination may be a collection parameter (9.9).

10-map-into.pnx

use io
use str
array xs int 4
assign xs (1, 2, 3, 4)
list squares int 4
array evens int 4
word go (or fail)
  xs do (x int gives int) x x mul end squares map_into or_fail
  xs do (x int gives bool) x 2 mod 0 eq end evens filter_into or_fail to n
  cat ("squares ", 3 squares idx, ", evens written ", n) io.println
end
go or_else (e) e err_text io.println end

Output

$ pnx 10-map-into.pnx
squares 16, evens written 2

10.7 Deferred code

Syntax
defer = "defer" { body } "end" ;

(1) defer CODE end writes code that runs when the enclosing block is left. The block is a word’s body, a loop’s body (at every turn) or the do block of a combining word (at every run). The code runs on every way out of that block: the block’s end, the end of a turn, break, a while or until that leaves the loop, return, or_return, or_fail and fail. Several run in the reverse of the order they are written. They do not run when a fault ends the run (the state closes the handles then, 19.6).

10-defer.pnx

use io
use str
buffer trace 256
word say (s str) s trace append or_else (e) end end
rem Every way out of a block runs its defers, the last written first.
word step (n int or fail)
  "open " say
  defer "close " say end
  defer "flush " say end
  n 0 lt if err.range fail end
  "work " say
end
1 step or_else (e) end
-1 step or_else (e) "(failed) " say end
trace contents str.trim io.println

Output

$ pnx 10-defer.pnx
open work flush close open flush close (failed)

(2) When deferred code gives an owned value (m release, f file.close), the defer takes that value over. It counts as given on every way out of the block, so no failure path needs code of its own to close it. Inside the block the value can still be lent.

10-defer-owned.pnx

use io
use str
buffer report 4096
rem A mark taken back at the end of every turn, also when append fails.
word build (or fail)
  1 50 range do (i int)
    mark to m
    defer m release end
    cat ("row ", i, ": ", i i mul, "\n") report append or_fail
  end each
end
build or_else (e) cat ("full: ", e err_text) io.println end
cat ("report: ", report len, " bytes") io.println

Output

$ pnx 10-defer-owned.pnx
report: 585 bytes
Constraints

(3) defer is written right in a word’s body, a loop’s body or a do block. In a branch of if, case or or_else, or outside a definition, it is refused.

10-defer-branch.pnx

word f (c bool)
  c if defer end end
end

Refused

$ pnx 10-defer-branch.pnx
10-defer-branch.pnx:2:8: defer is written right in a word's body, a loop's body or a do block, not in a branch

(4) Deferred code leaves the stack as it found it and leaves nothing on it. It cannot hold return fail break while until to set loop do case defer, or or_fail or_return; a word that can fail is taken with or_else inside it.

(5) Giving an owned value that a defer took over, inside the block, is refused.

word twice (gives int)
  mark to m
  defer m release end
  m release
  0
end

Refused
