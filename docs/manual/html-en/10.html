9 Owned values and the region

Builds on: Chapter 5 (the region, mark/release), chapter 7 (rows of pools), chapter 8 (failures).

Questions this chapter answers

  • How does the processor make sure that something like an open file gets closed?
  • How does it know a file is closed on the paths of failures too?
  • How does a loop that makes much text spare the region?

9.1 Values that must be handed over

The signature of file.open_read is (path str gives owned file or fail). owned means the value is an owned value. Whoever receives it shall hand it over exactly once on every path: give it to a word that takes it owned (file.close), store it in a global, or return it as an owned result. It can be lent any number of times to words that take it without owned (file.write, file.read_line).

09-copy-file.pnx

use io
use file
rem Copy a file line by line. Both files are owned: each must be closed on every path.
word copy_lines (source str, target str gives n int or fail)
  source file.open_read or_fail to src
  target file.open_write or_else (e) src file.close e fail end to dst
  0 to n
  loop
    src file.read_line or_else (e) break end to line
    cat (line, "\n") dst file.write or_else (e) src file.close dst file.close e fail end
    n 1 add to n
  end
  src file.close
  dst file.close
  n
end
word setup (or fail)
  "in.txt" file.open_write or_fail to f
  "one\ntwo\nthree\n" f file.write or_else (e) f file.close e fail end
  f file.close
end
setup or_else (e) end
word main () cat ("copied ", "in.txt" "out.txt" copy_lines or_else (e) -1 end, " lines") io.println end
main

Output

$ pnx 09-copy-file.pnx
copied 3 lines

copy_lines has two files and four ways out. When the second file does not open, it closes the first and fails. When writing fails, it closes both and fails. The processor follows all these paths at load, and refuses if any one of them does not close.

09-forgot-close.pnx

use file
word first_line (path str gives str or fail)
  path file.open_read or_fail to f
  f file.read_line or_fail
end

Refused

$ pnx 09-forgot-close.pnx
09-forgot-close.pnx:4:20: an owned value in a local is not given on every path (close, free or store it)

This word leaves through or_fail when read_line fails, and on that path it does not close f; it does not close it on the path of success either. The processor points at where f was made.

09-close-twice.pnx

use file
word f (path str or fail)
  path file.open_read or_fail to h
  h file.close
  h file.close
end

Refused

$ pnx 09-close-twice.pnx
09-close-twice.pnx:5:3: this local gave its owned value away; it holds nothing to read

Q&A

Q. What happens to open files on a fault?

A. The handles a run that ends with a fault opened are closed by the processor. So the owned check looks only at paths that are not faults.

Common mistake: Keeping a dup of it is handy

An owned value cannot be doubled with dup or dropped with drop. Doubled, it would be closed twice; dropped, never. Put it into a local and lend it by name.

9.2 Sparing the region

cat writes new text into the region. The region has a fixed size, so a loop that keeps making text gives the region back in every turn with mark and release. It gives it back on the way out through a failure too — what mark gives is an owned value as well.

09-region-loop.pnx

use io
use str
rem Make a long report in a small region: each turn gives its bytes back.
buffer report 4096
word build (or fail)
  1 200 range do (i int)
    mark to m
    cat ("row ", i, ": ", i i mul, "\n") report append or_else (e) m release e fail end
    m release
  end each
end
build or_else (e) cat ("full: ", e err_text) io.println end
cat ("report: ", report len, " bytes") io.println

Output

$ pnx 09-region-loop.pnx
report: 2735 bytes

Bytes appended to a buffer are copied into it, so they survive giving the region back.

Summary

  • An owned value is handed over exactly once on every path; lending is allowed any number of times (standard 12.4).
  • It is handed over on the paths of failures (or_fail or_return) and at return too (11.2).
  • owned values cannot be duped or dropped (12.4).
  • On a fault the processor closes the handles (11.3).
  • Loops give the region back with mark/release (12.2).
