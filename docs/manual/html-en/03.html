2 Values and the stack

Builds on: Chapter 1 (the order of code, pnx).

Questions this chapter answers

  • What values does Pinax have?
  • How does the stack move, and when does the processor check it?
  • What happens when an integer overflows?

2.1 Computing on the stack

02-stack.pnx

use io
use str
2 3 add 4 mul str.to_str io.println          rem (2 + 3) * 4
2 3 4 mul add str.to_str io.println          rem 2 + 3 * 4
10 3 sub str.to_str io.println               rem the first value is on the left: 10 - 3
10 3 swap sub str.to_str io.println          rem swap turns it round: 3 - 10

Output

$ pnx 02-stack.pnx
20
14
7
-7

Follow 2 3 add 4 mul step by step. 2 and 3 go on; add takes both off and puts 5 on; 4 goes on; mul takes both off and puts 20 on. Without parentheses, the order of the computation is the order of the text.

For words where order matters, such as subtraction and division, the value put on first is on the left: 10 3 sub is 10−3. swap exchanges the top two values. The only words that rearrange the stack are the five dup drop swap over nip. When you need more, give the values names (chapter 4).

2.2 Types of values

02-values.pnx

use io
use str
use fmt
42 str.to_str io.println
-7 str.to_str io.println
0xff str.to_str io.println                   rem 255
1_000_000 str.to_str io.println
'A' str.to_str io.println                    rem a character is its number
3 4 lt if "3 < 4 is true" else "false" end io.println
"a string" str.len str.to_str io.println
255 fmt.hex io.println

Output

$ pnx 02-values.pnx
42
-7
255
1000000
65
3 < 4 is true
8
ff

This book mostly uses four types:

  • int — 64-bit integers, written in decimal, hexadecimal (0xff) or binary (0b101), with underscores between digits if you like. A character 'A' is the int that is its number.
  • bool — true and false; comparison words (lt eq …) give them and if takes them.
  • str — strings; chapter 5 covers them.
  • err — the reason for a failure; see chapter 8.

Q&A

Q. Do int and bool convert into each other?

A. No. 1 is not true, and you cannot add to true. Only a bool goes where a condition goes, and only an int into arithmetic.

2.3 The processor knows the stack in advance

At load the processor knows, at every place of a body, how many values are on the stack and of what types. So the two programs below are refused before they run.

02-types-mixed.pnx

use io
"3" 4 add drop

Refused

$ pnx 02-types-mixed.pnx
02-types-mixed.pnx:2:7: this word takes two int values, or two of the same declared type

02-stack-short.pnx

use io
use str
5 add str.to_str io.println

Refused

$ pnx 02-stack-short.pnx
02-stack-short.pnx:3:3: the stack does not hold enough values for this word

Common mistake: The depth of the stack may change as a program runs

Languages like Forth allow words that leave a different number of values depending on what happens. Pinax does not. At every place the depth and types of the stack are one and fixed. So the two branches of an if leave the same stack, and one turn of a loop leaves the stack as it was (chapter 4).

2.4 Overflow is a fault

02-overflow.pnx

use io
use str
word double (n int gives int) n 2 mul end
4611686018427387903 double str.to_str io.println
4611686018427387904 double str.to_str io.println

Fault

$ pnx 02-overflow.pnx
9223372036854775806
02-overflow.pnx:3: integer overflow
  n int = 4611686018427387904

A result beyond the range of int does not quietly wrap around. The run stops on the spot and the processor reports a fault. pnx shows the line of the fault and the locals of the word. For arithmetic that wraps use wrap_mul, for arithmetic that stops at the edge sat_mul, and to receive overflow as a failure chk_mul.

Summary

  • The value put on first is on the left: 10 3 sub is 7 (standard 9.3).
  • The stack words are dup drop swap over nip only (9.3).
  • Types are checked at load; int and bool do not mix (7.1, 7.2).
  • Integer overflow and division by zero are faults; other arithmetic words exist (7.1, 15.1).
