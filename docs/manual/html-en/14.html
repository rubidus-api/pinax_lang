13 Tasks

Builds on: Chapter 4 (blocks), chapter 6 (queues), chapter 8 (faults).

Questions this chapter answers

  • How does one state take turns at several jobs?
  • When do tasks change, and how do they pass data?
  • What happens when one task has a fault?

13.1 Taking turns

A task is a flow of execution inside one state. It is not a thread: tasks change only where a task yields on its own. So nothing comes in between two yields, and no locks are needed.

tasks NAME count declares a task group, block GROUP spawn makes a task, and GROUP run_all runs them until all have ended.

13-turns.pnx

use io
tasks workers 2
word count_to (name str, n int)
  1 to i
  loop
    i n gt until
    cat (name, " ", i) io.println
    yield or_return                         rem give the other task a turn
    i 1 add to i
  end
end
global who int
word demo ()
  do "ping" 3 count_to end workers spawn or_else (e) return end drop
  do "pong" 2 count_to end workers spawn or_else (e) return end drop
  workers run_all
end
demo

Output

$ pnx 13-turns.pnx
ping 1
pong 1
ping 2
pong 2
ping 3

13.2 Linking with queues

Tasks pass data through declared storage, most often queues. When a queue is full or empty, a task yields and waits for its next turn.

13-pipeline.pnx

use io
rem Three stages linked by queues: numbers -> squares -> total.
tasks stages 3
queue numbers int 2
queue squares int 2
global total int
word send (v int, q int)                      rem put v into queue q (1 or 2), yielding while it is full
  loop
    true to ok
    q 1 eq if v numbers put or_else (e) false to ok end else v squares put or_else (e) false to ok end end
    ok until
    yield or_return
  end
end
word produce () 1 6 range do (i int) i 1 send end each  -1 1 send end
word square ()
  loop
    numbers take or_else (e) yield or_return 0 end to n
    n 0 lt if -1 2 send return end
    n 0 gt if n n mul 2 send end
  end
end
word add_up ()
  loop
    squares take or_else (e) yield or_return 0 end to n
    n 0 lt if return end
    total n add set total
  end
end
word demo ()
  do produce end stages spawn or_else (e) return end drop
  do square end stages spawn or_else (e) return end drop
  do add_up end stages spawn or_else (e) return end drop
  stages run_all
  cat ("1 + 4 + 9 + 16 + 25 = ", total) io.println
end
demo

Output

$ pnx 13-pipeline.pnx
1 + 4 + 9 + 16 + 25 = 55

Each of the three stages is a task, and the queues hold only two values each. The stages wait for each other and take turns. The end is announced by sending -1.

Common mistake: The block of spawn sees the locals around it

The block given to spawn is a block value and does not see the locals around it, because the task may live on after that word has ended. To give a task values, use globals or queues, or — as in the examples above — call a word inside the block with literals.

13-no-locals.pnx

tasks workers 2
word start (n int) do n drop end workers spawn or_else (e) return end drop end

Refused

$ pnx 13-no-locals.pnx
13-no-locals.pnx:2:23: this name is not declared before this place

13.3 Faults and cancelling

A fault in one task ends the whole run — the other tasks stop too. The state remains and takes the next run.

13-fault.pnx

use io
tasks workers 2
global zero int
word demo ()
  do "the healthy task starts" io.println yield or_return "and never finishes" io.println end workers spawn or_else (e) return end drop
  do 1 zero div drop end workers spawn or_else (e) return end drop
  workers run_all
end
demo

Fault

$ pnx 13-fault.pnx
the healthy task starts
13-fault.pnx:6: division by zero

TASK cancel makes that task’s next yield fail with cancelled. The task takes the failure with or_else, tidies up and ends. Cancelling does not stop a task by force.

Summary

  • Tasks change only where they yield (standard 14.2).
  • spawn makes a task from a block that takes and gives nothing; run_all runs them (14.1).
  • Tasks share data through globals and queues; blocks do not see the locals around them (14.3).
  • A fault in a task ends the whole run (14.3).
