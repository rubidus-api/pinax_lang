# 7 레코드, 풀, 찾아보기

> **먼저 알아야 할 것**: 6장(컬렉션), 5장(저장된 글).
>
> **이 장이 답하는 물음**
>
> - 필드가 여럿인 자료는 어떻게 담는가?
> - 포인터 없이 나무나 목록 같은 연결된 자료는 어떻게 만드는가?
> - 이름으로 줄을 찾으려면?

## 7.1 레코드와 줄

`record … end` 는 필드의 나열이다. 필드마다 폭을 적는다(`u8` `u16` `i32` `int` `bool` `str(N)` …). 레코드는 값으로 돌아다니지 않는다. 레코드를 원소로 하는 목록(또는 배열, 풀)을 선언하고, 그 한 칸인 **줄**을 다룬다. 줄의 타입은 표의 이름이다.

`07-records.pnx`

```pinax
use io
record book
  title str(32)
  year u16
  pages u16
end
list shelf book 8
row shelf ("The C Programming Language", 1978, 228)
row shelf ("Thinking Forth", 1984, 300)
row shelf lua ("Programming in Lua", 2003)          rem a named row; pages left out: 0
word show (b shelf) cat (b book.year, " ", b book.title, ", ", b book.pages, " pages") io.println end
shelf do (b shelf) b show end each
2016 lua to book.year                               rem value, row, to record.field
388 lua to book.pages
lua show
```

*출력*

```text
$ pnx 07-records.pnx
1978 The C Programming Language, 228 pages
1984 Thinking Forth, 300 pages
2003 Programming in Lua, 0 pages
2016 Programming in Lua, 388 pages
```

필드는 `레코드.필드` 로 적는다: `b book.year` 는 읽기, `2016 lua to book.year` 는 넣기다. `row` 는 정의 밖에서 목록에 줄을 더하고, 이름을 붙일 수도 있다. 돌면서 줄을 더하는 것은 `add_row` 다.

`07-add-row.pnx`

```pinax
use io
record point
  x i32
  y i32
end
list path point 4
word add_point (x int, y int or fail)
  path add_row or_fail to p                         rem a new, zeroed row at the end
  x p to point.x
  y p to point.y
end
word walk (or fail) 0 0 add_point or_fail  3 4 add_point or_fail  6 0 add_point or_fail end
walk or_else (e) e err_text io.println end
path do (p path) cat ("(", p point.x, ", ", p point.y, ")") io.print end each
"" io.println
```

*출력*

```text
$ pnx 07-add-row.pnx
(0, 0)(3, 4)(6, 0)
```

줄을 다루는 낱말을 주석과 함께 한 번에 보자. `add_row` 가 준 `r` 은 표 안의 번호이고, 필드에 넣는 꼴은 `값 줄 to레코드.필드` 다. 읽는 꼴은 `줄 레코드.필드` 이고, 줄 하나를 내려 필드의 값을 올린다.

`07-row-steps.pnx`

```pinax
use io
record item
  name str(12)                         rem stored text: 12 bytes inside the row
  price int
end
list cart item 4                       rem a table: room for 4 rows of item
word add_item (n str, p int or fail)
  cart add_row or_fail to r            rem a new row at the end; r is its number in the table
  n r to item.name                     rem value, row, to record.field: store a field
  p r to item.price
end
word total (gives int)
  0 to acc
  cart do (r cart) acc r item.price add to acc end each   rem each row of the table in turn
  acc
end
word main ()
  "pencil" 120 add_item or_else (e) end
  "eraser" 80 add_item or_else (e) end
  1 cart idx to second                 rem the row with number 1
  cat (second item.name, " costs ", second item.price) io.println
  cat ("total ", total) io.println
end
main
```

*출력*

```text
$ pnx 07-row-steps.pnx
eraser costs 80
total 200
```

| **토큰** | **그 뒤의 스택** | **일어난 일** |
|---|---|---|
| `cart add_row` | `1` | 새 줄을 끝에 더하고 그 번호를 올린다(실패할 수 있어 뒤에 `or_fail`). |
| `to r` | `—` | 번호를 `r` 에 담는다. |
| `n r` | `"eraser" 1` | 넣을 값과 줄. |
| `to item.name` | `—` | 줄 1 의 `name` 필드에 넣는다. 둘 다 내려간다. |
| `r item.price` | `80` | 줄 하나를 내리고 그 줄의 `price` 를 올린다. |

> **문답**
>
> **물음. 줄은 레코드의 주소인가?**
>
> 답. 아니다. 줄은 표 안의 **번호**다. 쓸 때마다 범위를 검사한다. 그래서 줄을 잘못 들고 있어도 메모리를 망가뜨리지 못하고, 기껏해야 결함으로 멈춘다.

## 7.2 줄로 잇기

레코드의 필드가 표의 이름을 타입으로 가지면 그 표의 줄을 담는다. 처음 값은 “없음” 이고 `is_none` 으로 묻는다. 이렇게 포인터 없이 나무를 만든다. 레코드가 자기를 담을 표를 가리키므로, 표를 `forward` 로 먼저 알린다.

`07-tree.pnx`

```pinax
use io
use str
rem A binary search tree in a pool: rows point to rows by number, never by address.
forward pool nodes
record node
  key int
  left nodes
  right nodes
end
pool nodes node 16
global root nodes
word put_key (k int or fail)
  nodes alloc or_fail to n
  k n to node.key
  root is_none if n set root return end
  root to at
  loop
    k at node.key lt if
      at node.left is_none if n at to node.left return end
      at node.left to at
    else
      at node.right is_none if n at to node.right return end
      at node.right to at
    end
  end
end
word show (t nodes)                                  rem in order: left, self, right
  t is_none if return end
  t node.left show
  t node.key str.to_str io.print " " io.print
  t node.right show
end
word build (or fail) 50 put_key or_fail 30 put_key or_fail 70 put_key or_fail 20 put_key or_fail 40 put_key or_fail end
build or_else (e) e err_text io.println end
root show
"" io.println
```

*출력*

```text
$ pnx 07-tree.pnx
20 30 40 50 70 
```

“없음” 줄의 필드를 읽거나 넣으면 결함이다. 줄을 따라갈 때는 `is_none` 으로 먼저 묻는다(위 `show` 의 첫 줄처럼).

`07-none-field.pnx`

```pinax
use io
forward list nodes
record node
  value int
  next nodes                           rem a row of nodes, or none
end
list nodes node 4
row nodes last (3)                     rem its next is none: nothing was given
last node.next node.value drop         rem reading a field of none ends the run
```

*결함으로 멈춤*

```text
$ pnx 07-none-field.pnx
07-none-field.pnx:9: index out of range
```

## 7.3 풀: 얻고 돌려주기

`pool` 은 줄을 얻고(`alloc`) 돌려주는(`free`) 표다. `alloc` 이 준 줄은 **한 번만 쓰는 값**이다. 모든 경로에서 정확히 한 번, 필드나 전역에 넣거나 `free` 에 줘야 한다. 처리기가 적재 때 그것을 검사한다.

`07-pool-leak.pnx`

```pinax
record node
  key int
end
pool nodes node 4
word new_node (k int or fail)
  nodes alloc or_fail to n
  k n to node.key
end
```

*거절*

```text
$ pnx 07-pool-leak.pnx
07-pool-leak.pnx:8:1: an owned value in a local is not given on every path (close, free or store it)
```

풀의 줄은 번호와 함께 세대를 담는다. 돌려준 줄을 다시 쓰면 — 그 사이 그 칸을 누가 다시 얻었더라도 — 결함으로 멈춘다.

`07-stale.pnx`

```pinax
use io
record node
  key int
end
pool nodes node 4
global keep nodes
word demo (or fail)
  nodes alloc or_fail to n
  n set keep
  keep nodes free
  "the row is given back" io.println
  keep node.key drop
end
demo or_else (e) end
```

*결함으로 멈춤*

```text
$ pnx 07-stale.pnx
the row is given back
07-stale.pnx:12: a row or handle was used after it was given back
  n nodes = 4294967297
```

## 7.4 찾아보기

`index 이름 표 레코드.필드` 는 한 필드로 줄을 찾는 해시 표다. `lookup` 이 키로 줄을 찾는다(없으면 `not_found` 로 실패). `row` 로 적은 줄은 처음부터 들어 있다.

`07-index.pnx`

```pinax
use io
record user
  name str(16)
  age u8
end
list users user 8
index by_name users user.name
row users ("kim", 30)
row users ("lee", 25)
word register (name str, age int or fail)
  users add_row or_fail to u
  name u to user.name
  age u to user.age
  u by_name insert or_fail                          rem without this, lookup does not see it
end
word age_of (name str gives int or fail) name by_name lookup or_fail user.age end
"park" 41 register or_else (e) e err_text io.println end
"kim" 31 register or_else (e) cat ("kim again: ", e err_text) io.println end
word show (name str) cat (name, ": ", name age_of or_else (e) -1 end) io.println end
"lee" show
"park" show
"choi" show
```

*출력*

```text
$ pnx 07-index.pnx
kim again: failed
lee: 25
park: 41
choi: -1
```

> **흔한 오해: add_row 한 줄은 찾아보기에도 들어간다**
>
> 들어가지 않는다. 돌면서 더한 줄은 `insert` 해야 `lookup` 이 찾는다. 위 예의 `register` 가 그렇게 한다. 같은 키가 이미 있으면 `insert` 는 실패하고, `add_row` 로 더한 줄은 목록에 남는다 — 키를 먼저 `lookup` 해 보고 더하는 것이 깔끔하다.

> **정리**
>
> - 레코드는 표의 줄로 다룬다. 필드는 `레코드.필드` 로 읽고 넣는다(표준 8.8).
> - 줄은 번호이고, 쓸 때마다 검사된다. 없음 줄의 필드는 결함이다(8.8).
> - 풀의 줄은 한 번 넘겨야 하고, 돌려준 줄은 결함이다(8.9, 12.4).
> - 찾아보기는 `row` 의 줄을 담고, 돌면서 더한 줄은 `insert` 한다(8.10).
