# 8 Failures and faults

> **Builds on**: Chapter 3 (`or fail` in signatures), chapter 6 (a failing `push`).
>
> **Questions this chapter answers**
>
> - What does Pinax do when something goes wrong? With no exceptions, how is it handled?
> - Can a failure be passed over unhandled?
> - What is a fault, and how does it differ from a failure?

## 8.1 Two kinds of wrong

Pinax tells two kinds of wrong apart.

- A **failure** is something expected now and then: text that is not a number, a full list, a missing key. A word that can fail has `or fail` in its signature, and the caller handles it **right there** .
- A **fault** means the program is wrong: an overflow, a division by zero, an index out of range. The run stops on the spot, and the host receives it. A script has no way to catch a fault.

With no exceptions, an error never skips several words and gets caught somewhere unexpected.

## 8.2 Three words that handle a failure

Right after a word that can fail comes one **guard**:

- `or_fail` — this word fails too, for the same reason; its signature needs `or fail` as well;
- `or_return` — this word ends quietly;
- `or_else … end` — makes a value in its place; `or_else (e) … end` takes the reason.

`08-parse.pnx`

```pinax
use io
use str
rem Read "name,score" lines; a bad line is reported, not fatal.
word parse (line str gives name str, score int or fail)
  line "," str.try_cut or_fail to (n, s)              rem no comma: fail the same way
  s str.trim str.to_int or_fail to v                  rem not a number: fail
  v 0 lt v 100 gt or if err.range fail end            rem our own rule: 0..100
  n str.trim v
end
word report (line str)
  line parse or_else (e) cat ("skipped \"", line, "\": ", e err_text) io.println return end to (name, score)
  cat (name, " scored ", score) io.println
end
text END
kim, 91
lee 77
park, ninety
choi, 140
END
str.lines do (l str) l report end each
```

*Output*

```text
$ pnx 08-parse.pnx
kim scored 91
skipped "lee 77": not_found
skipped "park, ninety": format
skipped "choi, 140": range
```

`parse` can fail in three places and passes each on with `or_fail`. Its own rule (0 to 100) fails with `err.range fail`. `report` takes the failure with `or_else (e)`, reports it with its reason, and skips the line.

`08-or-return.pnx`

```pinax
use io
list seen int 3
word note_it (n int)
  n seen push or_return                              rem full: quietly do nothing
  cat ("noted ", n) io.println
end
1 note_it 2 note_it 3 note_it 4 note_it
```

*Output*

```text
$ pnx 08-or-return.pnx
noted 1
noted 2
noted 3
```

`08-guard-missing.pnx`

```pinax
use str
word twice (s str gives int) s str.to_int 2 mul end
```

*Refused*

```text
$ pnx 08-guard-missing.pnx
08-guard-missing.pnx:2:43: a word that can fail is followed by or_fail, or_return or or_else
```

> **Common mistake: Using or_fail at the outermost level of a file**
>
> Code outside definitions counts as having no 
> `or fail`
>  signature, so neither 
> `or_fail`
>  nor 
> `or_return`
>  nor 
> `return`
>  can be used there. Put the work into a word, and take its failure with 
> `or_else`
>  at the outer level.
> `08-load-code-or-fail.pnx`
>
> ```pinax
> use io
> use str
> "42" str.to_int or_fail str.to_str io.println
> ```
>
> *Refused*
>
> ```text
> $ pnx 08-load-code-or-fail.pnx
> 08-load-code-or-fail.pnx:3:17: or_fail passes the failure on, so this word needs `or fail` in its signature
> ```

## 8.3 Faults

`08-fault.pnx`

```pinax
use io
use str
word average (total int, n int gives int) total n div end
cat ("average of 10 over 4: ", 10 4 average) io.println
cat ("average of nothing: ", 0 0 average) io.println
```

*Fault*

```text
$ pnx 08-fault.pnx
average of 10 over 4: 2
08-fault.pnx:3: division by zero
  total int = 0
  n int = 0
```

`pnx` shows the kind of the fault, its line and the locals of the word. What a run that ends with a fault made in the region is rewound, and handles such as files it opened are closed by the processor.

Where a fault could happen and you want a failure instead, use the `chk_` words.

`08-chk.pnx`

```pinax
use io
word safe_average (total int, n int gives int or fail) total n chk_div or_fail end
word show () cat ("10/4: ", 10 4 safe_average or_else (e) -1 end, ", 0/0: ", 0 0 safe_average or_else (e) -1 end) io.println end
show
```

*Output*

```text
$ pnx 08-chk.pnx
10/4: 2, 0/0: -1
```

`assert` makes a fault when it is false. It writes down a promise the caller must keep.

`08-assert.pnx`

```pinax
use io
word percent (part int, whole int gives int)
  whole 0 gt assert                                  rem a promise the caller must keep
  part 100 mul whole div
end
cat ("3 of 4: ", 3 4 percent, "%") io.println
cat ("3 of 0: ", 3 0 percent, "%") io.println
```

*Fault*

```text
$ pnx 08-assert.pnx
3 of 4: 75%
08-assert.pnx:3: failed
  part int = 3
  whole int = 0
```

> **Q&A**
>
> **Q. How do I decide what is a failure and what is a fault?**
>
> A. What happens because of data from outside (user input, files, the network) is a failure. What goes away only by fixing the program (a miscomputed index, a broken promise) is a fault.

> **Summary**
>
> - After a word that can fail comes `or_fail` , `or_return` or `or_else` (standard 11.2).
> - `or_fail` and `fail` only inside an `or fail` signature; outside definitions only `or_else` (11.2).
> - A fault stops the run, and the processor closes the handles the run opened (11.3).
> - To receive overflow and division by zero as failures, use the `chk_` words (15.1).
