# 7 Records, pools, indexes

> **Builds on**: Chapter 6 (collections), chapter 5 (stored text).
>
> **Questions this chapter answers**
>
> - How are data with several fields held?
> - How are linked data such as trees and lists built without pointers?
> - How do I find a row by its name?

## 7.1 Records and rows

`record … end` is a sequence of fields, each with a width (`u8` `u16` `i32` `int` `bool` `str(N)` …). Records do not travel as values. You declare a list (or array, or pool) of records and handle its **rows**. A row’s type is named after its table.

`07-records.pnx`

```pinax
use io
record book
  title str(32)
  year u16
  pages u16
end
list shelf book 8
row shelf ("The C Programming Language", 1978, 228)
row shelf ("Thinking Forth", 1984, 300)
row shelf lua ("Programming in Lua", 2003)          rem a named row; pages left out: 0
word show (b shelf) cat (b book.year, " ", b book.title, ", ", b book.pages, " pages") io.println end
shelf do (b shelf) b show end each
2016 lua to book.year                               rem value, row, to record.field
388 lua to book.pages
lua show
```

*Output*

```text
$ pnx 07-records.pnx
1978 The C Programming Language, 228 pages
1984 Thinking Forth, 300 pages
2003 Programming in Lua, 0 pages
2016 Programming in Lua, 388 pages
```

Fields are written `RECORD.FIELD`: `b book.year` reads, `2016 lua to book.year` stores. `row` adds a row to a list outside definitions, and can name it. Adding rows while running is `add_row`.

`07-add-row.pnx`

```pinax
use io
record point
  x i32
  y i32
end
list path point 4
word add_point (x int, y int or fail)
  path add_row or_fail to p                         rem a new, zeroed row at the end
  x p to point.x
  y p to point.y
end
word walk (or fail) 0 0 add_point or_fail  3 4 add_point or_fail  6 0 add_point or_fail end
walk or_else (e) e err_text io.println end
path do (p path) cat ("(", p point.x, ", ", p point.y, ")") io.print end each
"" io.println
```

*Output*

```text
$ pnx 07-add-row.pnx
(0, 0)(3, 4)(6, 0)
```

> **Q&A**
>
> **Q. Is a row the address of a record?**
>
> A. No. A row is a **number** within its table, and its range is checked on every use. So holding the wrong row cannot damage memory; at worst it stops with a fault.

## 7.2 Linking by rows

A field whose type is the name of a table holds a row of that table. It starts as “none”, asked with `is_none`. That is how a tree is built without pointers. Since the record refers to the table that holds it, the table is announced first with `forward`.

`07-tree.pnx`

```pinax
use io
use str
rem A binary search tree in a pool: rows point to rows by number, never by address.
forward pool nodes
record node
  key int
  left nodes
  right nodes
end
pool nodes node 16
global root nodes
word put_key (k int or fail)
  nodes alloc or_fail to n
  k n to node.key
  root is_none if n set root return end
  root to at
  loop
    k at node.key lt if
      at node.left is_none if n at to node.left return end
      at node.left to at
    else
      at node.right is_none if n at to node.right return end
      at node.right to at
    end
  end
end
word show (t nodes)                                  rem in order: left, self, right
  t is_none if return end
  t node.left show
  t node.key str.to_str io.print " " io.print
  t node.right show
end
word build (or fail) 50 put_key or_fail 30 put_key or_fail 70 put_key or_fail 20 put_key or_fail 40 put_key or_fail end
build or_else (e) e err_text io.println end
root show
"" io.println
```

*Output*

```text
$ pnx 07-tree.pnx
20 30 40 50 70 
```

## 7.3 Pools: taking and giving back

A `pool` is a table whose rows are taken (`alloc`) and given back (`free`). The row `alloc` gives is an **owned value**: on every path it shall be stored into a field or global, or given to `free`, exactly once. The processor checks this at load.

`07-pool-leak.pnx`

```pinax
record node
  key int
end
pool nodes node 4
word new_node (k int or fail)
  nodes alloc or_fail to n
  k n to node.key
end
```

*Refused*

```text
$ pnx 07-pool-leak.pnx
07-pool-leak.pnx:8:1: an owned value in a local is not given on every path (close, free or store it)
```

A row of a pool carries a generation besides its number. Using a row that was given back — even when someone has taken that slot again since — stops with a fault.

`07-stale.pnx`

```pinax
use io
record node
  key int
end
pool nodes node 4
global keep nodes
word demo (or fail)
  nodes alloc or_fail to n
  n set keep
  keep nodes free
  "the row is given back" io.println
  keep node.key drop
end
demo or_else (e) end
```

*Fault*

```text
$ pnx 07-stale.pnx
the row is given back
07-stale.pnx:12: a row or handle was used after it was given back
  n nodes = 4294967297
```

## 7.4 Indexes

`index NAME TABLE RECORD.FIELD` is a hash table that finds rows by one field. `lookup` finds the row of a key (failing with `not_found` when there is none). Rows written with `row` are in it from the start.

`07-index.pnx`

```pinax
use io
record user
  name str(16)
  age u8
end
list users user 8
index by_name users user.name
row users ("kim", 30)
row users ("lee", 25)
word register (name str, age int or fail)
  users add_row or_fail to u
  name u to user.name
  age u to user.age
  u by_name insert or_fail                          rem without this, lookup does not see it
end
word age_of (name str gives int or fail) name by_name lookup or_fail user.age end
"park" 41 register or_else (e) e err_text io.println end
"kim" 31 register or_else (e) cat ("kim again: ", e err_text) io.println end
word show (name str) cat (name, ": ", name age_of or_else (e) -1 end) io.println end
"lee" show
"park" show
"choi" show
```

*Output*

```text
$ pnx 07-index.pnx
kim again: failed
lee: 25
park: 41
choi: -1
```

> **Common mistake: A row added with add_row is in the index too**
>
> It is not. A row added while running is found by `lookup` only after `insert`, as `register` above does. When the key is there already, `insert` fails and the row added with `add_row` stays in the list — so it is cleaner to `lookup` the key first and add after.

> **Summary**
>
> - Records are handled as rows of tables; fields are read and stored as `RECORD.FIELD` (standard 8.8).
> - A row is a number checked on every use; a field of the none row is a fault (8.8).
> - A row of a pool is handed over once; a row given back is a fault (8.9, 12.4).
> - An index holds the rows of `row` ; rows added while running are `insert` ed (8.10).
