## 15.1 Tests

`test NAME … end` defines a test: a word that takes and gives nothing, and does not run at load. `pnx test FILE` runs the tests in order. A false `assert` makes that test fail.

`15-test.pnx`

```pinax
use str
word initials (name str gives str)
  name str.trim " " str.cut to (given, family)
  cat (given 1 str.take, family str.trim 1 str.take) str.upper
end
test two_names "grace hopper" initials "GH" eq assert end
test spaces_around "  ada lovelace " initials "AL" eq assert end
test one_name "plato" initials "P" eq assert end
```

*Test run*

```text
$ pnx test 15-test.pnx
ok   two_names
ok   spaces_around
ok   one_name
3 tests, 0 failed
```

`15-test-fail.pnx`

```pinax
word clamp_percent (n int gives int) n 0 100 clamp end
test inside 50 clamp_percent 50 eq assert end
test above 150 clamp_percent 100 eq assert end
test wrong -5 clamp_percent -5 eq assert end
```

*test-fail*

```text
$ pnx test 15-test-fail.pnx
ok   inside
ok   above
FAIL wrong (failed)
3 tests, 1 failed
```

`clamp` raises a negative to 0, so the test `wrong` writes down a wrong expectation. When a test fails, `pnx` exits with 1.

> **Common mistake: Writing just the comparison makes a test**
>
> `21 double 42 eq` only leaves a `bool`; it checks nothing. A test takes and gives nothing, so a test that leaves a value is refused. End it with `assert`.
>
> `15-test-leaves.pnx`
>
> ```pinax
> word double (n int gives int) n 2 mul end
> test doubles 21 double 42 eq end
> ```
>
> *Refused*
>
> ```text
> $ pnx 15-test-leaves.pnx
> 15-test-leaves.pnx:2:30: the stack does not hold exactly the results of the signature here
> ```

## 15.2 Sessions

`pnx repl` reads and runs one line at a time and shows what each line leaves. Later lines use the definitions of earlier ones. A line that is refused or ends with a fault leaves nothing behind.

`15-repl.pnx`

```pinax
use str
2 3 add
word cube (n int gives int) n n mul n mul end
4 cube
"pinax" str.upper
1 0 div
cube cube
```

*Session*

```text
$ pnx repl
5
64
"PINAX"
error: line 1: div_zero
```

The last line, `cube cube`, was refused because the stack was empty. The message of a refusal goes to standard error, so it is not in the output above.

A line that declares a word or a global is loaded again with the whole program so far, and the copy before it stays in the memory block. So a long session uses a little more of the block with each such line. A line that only computes values uses none. When three quarters of the block are used, `pnx` says so once on standard error. Start a long session with a larger block through `PNX_BLOCK_KB` (the default is 16384, that is 16 MiB).

What each line leaves on the stack, followed. The values left at the end of a line are what is shown; the next line starts from an empty stack again.

| **Token** | **Stack after it** | **What happened** |
|---|---|---|
| `2 3 add` | `5` | Shows the value left, `5`. |
| `word cube … end` | `—` | A definition leaves no value. |
| `4 cube` | `64` | Uses the definition of the line before. |
| `1 0 div` | `—` | A line that ends with a fault leaves nothing. |
| `cube cube` | `—` | Refused: no `int` to take from an empty stack. |

## 15.3 Seeing the stack, and formatting

`pnx see` shows, for each line of a definition, the stack where that line ends. Use it when the stack is not what you think.

`15-see.pnx`

```pinax
word mean (a int, b int, c int gives int)
  a b add
  c add
  3 div
end
```

*Listing*

```text
$ pnx see 15-see.pnx
    2    a b add                                        | int
    3    c add                                          | int
    4    3 div                                          | int
```

Right of the line number is the code of that line; right of `|` is the stack where the line ends, the bottom on the left and the top on the right — as in the trace tables of this book. It is most useful when standard modules or `cat` make the stack hard to follow.

`pnx see` also works on a source it refuses. It shows the stack after each line up to the place of the refusal, then gives the message. So what is left on the stack can be seen before the message is read.

`15-see-wrong.pnx`

```pinax
word price_label (cents int gives str)
  cents 100 div
  "won" swap
  cat (cents, " cents")
end
```

*Listing, then the refusal*

```text
$ pnx see 15-see-wrong.pnx
    2    cents 100 div                                  | int
    3    "won" swap                                     | str int
    4    cat (cents, " cents")                          | str int str
15-see-wrong.pnx:5:1: the stack does not hold exactly the results of the signature here
```

The signature promised one `str`, but the stack after the last line is `str int str`. The `swap` of line 3 sent `"won"` down, and the result of line 2 (an `int`) was used by nothing. Removing lines 2 and 3 leaves only the result of `cat`.

`pnx fmt` changes only indentation and spaces. Tokens, the places of lines and remarks stay as they are.

`15-fmt.pnx`

```pinax
use io
word fizz (n int gives str)
n 15 mod 0 eq if "FizzBuzz" return end
   n 3 mod 0 eq if "Fizz" return end
n 5 mod 0 eq if "Buzz" else cat (n) end
end
```

*Formatted*

```text
$ pnx fmt 15-fmt.pnx
use io
word fizz (n int gives str)
  n 15 mod 0 eq if "FizzBuzz" return end
  n 3 mod 0 eq if "Fizz" return end
  n 5 mod 0 eq if "Buzz" else cat (n) end
end
```

> **Q&A**
>
> **Q. Do tests go in a file of their own, or beside the words?**
>
> A. Either. `pnx test FILE` loads the file and then runs only the tests in it. Beside the words, a test is in sight when the word is changed. When there are many, a test file of its own brings the module in with `use`.

> **Q&A**
>
> **Q. Why does the stack of `pnx see` show types only, and no values?**
>
> A. `see` loads and does not run. At load the processor knows the depth and types of the stack, nothing more; values exist only when the program runs. To see values, run a line at a time in `pnx repl`.

> **Summary**
>
> - `test … end` and `pnx test` ; a failed test makes the exit status 1 (standard 20.2).
> - `pnx repl` shows what each line leaves (20.3).
> - `pnx see` shows the stack after each line; on a refused source, up to the place, then the message (20.4).
> - `pnx fmt` changes only indentation and spaces (20.4).
