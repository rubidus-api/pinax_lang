# 15 Tools

> **Builds on**: Chapter 1 (`pnx`), chapter 3 (words).
>
> **Questions this chapter answers**
>
> - What do I use to test words?

## 15.1 Tests

`test NAME … end` defines a test: a word that takes and gives nothing, and does not run at load. `pnx test FILE` runs the tests in order. A false `assert` makes that test fail.

`15-test.pnx`

```pinax
use str
word initials (name str gives str)
  name str.trim " " str.cut to (given, family)
  cat (given 1 str.take, family str.trim 1 str.take) str.upper
end
test two_names "grace hopper" initials "GH" eq assert end
test spaces_around "  ada lovelace " initials "AL" eq assert end
test one_name "plato" initials "P" eq assert end
```

*Test run*

```text
$ pnx test 15-test.pnx
ok   two_names
ok   spaces_around
ok   one_name
3 tests, 0 failed
```

`15-test-fail.pnx`

```pinax
word clamp_percent (n int gives int) n 0 100 clamp end
test inside 50 clamp_percent 50 eq assert end
test above 150 clamp_percent 100 eq assert end
test wrong -5 clamp_percent -5 eq assert end
```

*test-fail*

```text
$ pnx test 15-test-fail.pnx
ok   inside
ok   above
FAIL wrong (failed)
3 tests, 1 failed
```

`clamp` raises a negative to 0, so the test `wrong` writes down a wrong expectation. When a test fails, `pnx` exits with 1.

> **Common mistake: Writing just the comparison makes a test**
>
> `21 double 42 eq` only leaves a `bool`; it checks nothing. A test takes and gives nothing, so a test that leaves a value is refused. End it with `assert`.
>
> `15-test-leaves.pnx`
>
> ```pinax
> word double (n int gives int) n 2 mul end
> test doubles 21 double 42 eq end
> ```
>
> *Refused*
>
> ```text
> $ pnx 15-test-leaves.pnx
> 15-test-leaves.pnx:2:30: the stack does not hold exactly the results of the signature here
> ```

## 15.2 Sessions

`pnx repl` reads and runs one line at a time and shows what each line leaves. Later lines use the definitions of earlier ones. A line that is refused or ends with a fault leaves nothing behind.

`15-repl.pnx`

```pinax
use str
2 3 add
word cube (n int gives int) n n mul n mul end
4 cube
"pinax" str.upper
1 0 div
cube cube
```

*Session*

```text
$ pnx repl
5
64
"PINAX"
error: line 1: div_zero
```

The last line, `cube cube`, was refused because the stack was empty. The message of a refusal goes to standard error, so it is not in the output above.

## 15.3 Seeing the stack, and formatting

`pnx see` shows, for each line of a definition, the stack where that line ends. Use it when the stack is not what you think.

`15-see.pnx`

```pinax
word mean (a int, b int, c int gives int)
  a b add
  c add
  3 div
end
```

*Listing*

```text
$ pnx see 15-see.pnx
    2    a b add                                        | int
    3    c add                                          | int
    4    3 div                                          | int
```

`pnx fmt` changes only indentation and spaces. Tokens, the places of lines and remarks stay as they are.

`15-fmt.pnx`

```pinax
use io
word fizz (n int gives str)
n 15 mod 0 eq if "FizzBuzz" return end
   n 3 mod 0 eq if "Fizz" return end
n 5 mod 0 eq if "Buzz" else cat (n) end
end
```

*Formatted*

```text
$ pnx fmt 15-fmt.pnx
use io
word fizz (n int gives str)
  n 15 mod 0 eq if "FizzBuzz" return end
  n 3 mod 0 eq if "Fizz" return end
  n 5 mod 0 eq if "Buzz" else cat (n) end
end
```

> **Summary**
>
> - `test … end` and `pnx test` ; a failed test makes the exit status 1 (standard 20.2).
> - `pnx repl` shows what each line leaves (20.3).
> - `pnx see` shows the stack of each line, `pnx fmt` makes indentation even (20.4).
