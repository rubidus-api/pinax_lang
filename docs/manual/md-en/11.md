# 10 Modules and data files

> **Builds on**: Chapter 1 (`use`), chapter 3 (signatures).
>
> **Questions this chapter answers**
>
> - How is a program split into several files?
> - What does a module show, and what does it hide?
> - How are settings read without running code?

## 10.1 Making a module

One file is one module, named after the file without `.pnx`. What is to be seen outside is marked `export`.

`money.pnx`

```pinax
rem A small module: amounts are cents, kept apart from plain numbers.
export type cents int
def pad2 n int gives str do n 10 lt if args "0" n . cat else args n . cat end end
export def of_won won int gives cents do won 100 mul cents end
export def show c cents gives str do args c raw 100 div "." c raw 100 mod pad2 . cat end
```

`cents` is a **declared type** over `int`: represented as an integer, it does not mix with `int`. `raw` takes the underlying integer out. Multiplying or dividing `cents` by an integer gives `cents` (`c 3 mul`): scaling keeps the unit. Only the division in `show`, which needs plain integers, uses `raw`.

## 10.2 Using a module

After `use money .`, its procedures are written as paths such as `money.of_won`; the exported type `cents` is written by its name alone. When `money` is not a registered module, `pnx` first loads `money.pnx` from beside the program.

`10-use.pnx`

```pinax
use io .
use money .
def total a cents, b cents gives cents do a b add end
args "total " 12 money.of_won 3 money.of_won total money.show . cat io.println
```

*Output*

```text
$ pnx 10-use.pnx
total 15.00
```

`10-use-as.pnx`

```pinax
use io .
use money as m .
args "price " 7 m.of_won m.show . cat io.println
```

*Output*

```text
$ pnx 10-use-as.pnx
price 7.00
```

`pad2`, not exported, is not seen outside.

`10-private.pnx`

```pinax
use money .
5 money.pad2 drop
```

*Refused*

```text
$ pnx 10-private.pnx
10-private.pnx:2:3: the module exports nothing of this name
```

Besides procedures, a module can export constants, globals, types and records. They are used like this.

| **Exported** | **Read or call** | **Note** |
|---|---|---|
| procedure | `module.procedure` | the signature is the same as inside the module |
| constant (`const`) | `module.name` |  |
| global (`global` and collections) | `module.name` | stored with `value set module.name` |
| type, record, row type of a table | the name alone | written without a path, like `cents` |

The module `tally` below exports a constant, a global and a procedure. Changing the global is usually the job of the module’s own procedure (`bump`), but it can also be stored from outside with `set tally.hits`.

`tally.pnx`

```pinax
rem A module that keeps a count: an exported constant, an exported global and a word.
export const limit 3
export global hits int
export def bump gives bool do          rem true while hits is still under the limit
  hits limit lt if hits 1 add set hits true else false end
end
```

`10-tally.pnx`

```pinax
use io .
use tally .
def try_once do
  tally.bump if "counted" else "limit reached" end io.println
end
try_once try_once try_once try_once                 rem the fourth time the limit is reached
args "hits " tally.hits " of " tally.limit . cat io.println   rem read an exported global and constant
0 set tally.hits                                    rem an exported global is written with set module.name
args "hits after reset " tally.hits . cat io.println
```

*Output*

```text
$ pnx 10-tally.pnx
counted
counted
counted
limit reached
hits 3 of 3
hits after reset 0
```

A module that `use` cannot find is refused at load. `pnx` looks at the standard and host modules first, then for `NAME.pnx` beside the program file.

`10-unknown-module.pnx`

```pinax
use maths .                                           rem no maths.pnx beside the program, no such module
```

*Refused*

```text
$ pnx 10-unknown-module.pnx
10-unknown-module.pnx:1:5: no module of this name is registered or loaded
```

> **Q&A**
>
> **Q. Who decides a module’s name?**
>
> A. Whoever loads it. `pnx` uses the file name without `.pnx`, and a C host gives the name to `pinax_load`. So there is no line in the file that names its module. Two modules of the same name cannot be in one state together.

> **Common mistake: cents is just an integer, so it can be added to one**
>
> Adding `cents` and `int` is refused. Only two values of the same declared type are added and subtracted; the types are kept apart to stop numbers of different units from being mixed.
>
> `10-mixed.pnx`
>
> ```pinax
> use money .
> 12 money.of_won 3 add drop
> ```
>
> *Refused*
>
> ```text
> $ pnx 10-mixed.pnx
> 10-mixed.pnx:2:19: a declared type is added to and subtracted from its own type, and multiplied, divided or taken modulo by an int; for other arithmetic take raw
> ```

## 10.3 Bare names from modules

A script that calls the same modules all the time, a shell script above all, can name them in a search order with `set_order`. Then their procedures are written bare.

`10-order.pnx`

```pinax
set_order io str .
"pinax" upper println
"a,b,c" "," "+" replace println
```

*Output*

```text
$ pnx 10-order.pnx
PINAX
a+b+c
```

The order is only a last resort. A bare name is first a local, then a name of the source, then a core procedure; only then are the modules of the order asked, left to right. So `len` stays the core procedure even with `str` in the order, and the `str` procedure is written `str.len`. `set_order .` empties the order again. A path works with or without it.

> **Q&A**
>
> **Q. How do I add one module without naming the others again?**
>
> A. Inside `set_order`, `get_order` stands for the order as it is: `set_order get_order str .` puts `str` behind it, `set_order str get_order .` in front. Alone, `get_order` shows the order. It speaks while the file is checked, so its line comes before anything the file prints.
>
> `10-order-add.pnx`
>
> ```pinax
> set_order io .
> set_order get_order str .
> get_order
> "pinax" lower println
> ```
>
> *Output*
>
> ```text
> $ pnx 10-order-add.pnx
> order: (io, str)
> pinax
> ```

> **Q&A**
>
> **Q. Why is it `set_order io str .` and not `io str set_order`?**
>
> A. What a procedure takes when it runs comes before it, on the stack: `2 3 add`. What a procedure reads when it is compiled comes after it: the signature of `def`, the name of `to`, the modules of `set_order` (ended by a period). A module is not a value, so the list could not be on the stack.

## 10.4 Data files

A host can read a source by **data load**. A data load accepts declarations and values only, and refuses procedure definitions, calls and control. So reading an untrusted settings file cannot run any code.

`10-data.c`

```c
#include "pinax.h"
#include <stdio.h>
#include <string.h>

/* A settings file the host reads as data: declarations and values, no code. */
static const char settings[] =
    "global port int\n"
    "global name str 16\n"
    "8080 set port\n"
    "\"edge\" set name\n";
static const char hostile[] = "def boom do end\n";

int main(void) {
    static unsigned char block[1 << 20];
    pinax_config config = {.struct_size = sizeof config};
    pinax_state *st;
    if (pinax_open((pinax_mem){block, sizeof block}, &config, &st) != PINAX_OK)
        return 1;
    if (pinax_load(st, "settings", (pinax_str){(const unsigned char *)settings, strlen(settings)}, PINAX_LOAD_DATA) != PINAX_OK)
        return 1;
    pinax_global g;
    pinax_global_find(st, "port", &g);
    printf("port: %lld\n", (long long)*(const int64_t *)g.ptr);
    if (pinax_load(st, "hostile", (pinax_str){(const unsigned char *)hostile, strlen(hostile)}, PINAX_LOAD_DATA) != PINAX_OK) {
        pinax_str why = pinax_error_text(st);
        printf("refused: %.*s\n", (int)why.len, (const char *)why.ptr);
    }
    pinax_close(st);
    return 0;
}
```

*Output*

```text
$ ./10-data
port: 8080
refused: a data source defines no procedures and uses no modules
```

`pnx` does not do data loads; they are the host’s business (chapter 14).

## 10.5 Modules the host lends

`io` `file` `clock` `random` `env` are not standard modules but **host modules**: they are not part of the language, and exist only when the host registers them (chapter 14). `pnx` registers all five. So the host decides the ways to files, the clock and the environment — a script that is not trusted is given no `file`.

`10-host-modules.pnx`

```pinax
rem run: args alpha beta
use io .
use str .
use env .
use random .
use clock .
def demo do
  args "arguments: " env.arg_count . cat io.println             rem 0 is the program file
  1 env.arg or_else to e "?" end io.println
  "PINAX_NO_SUCH_VARIABLE" env.getenv or_else to e args "getenv failed: " e err_text . cat end io.println
  7 random.seed                                             rem the same seed, the same numbers
  args 10 random.random_below " " 10 random.random_below " " 10 random.random_below . cat io.println
  clock.monotonic_ns to a
  clock.monotonic_ns to b
  args "the clock does not go back: " b a lt not . cat io.println
end
demo
```

*Output*

```text
$ pnx 10-host-modules.pnx
arguments: 1
?
getenv failed: not_found
7 2 8
the clock does not go back: true
```

`env.arg_count` and `env.arg` are the arguments of the command line (0 is the program file); `env.getenv` reads an environment variable. After `random.seed`, `random.random_below` gives the same numbers for the same seed, which suits tests. `clock.monotonic_ns` never goes back, so it measures how long something took; `clock.now_ms` is the calendar time, and `clock.sleep` pauses for that many milliseconds. `random.random` is a 64-bit random number without a range (not for cryptography).

| **Token** | **Stack after it** | **What happened** |
|---|---|---|
| `1` | `1` | Which argument. |
| `env.arg` | `"alpha"` | That argument; a number past the last fails. |
| `or_else to e "?" end` | `"alpha"` | Skipped on success. On failure `"?"` takes the place. |
| `io.println` | `—` | Prints it. |

> **Q&A**
>
> **Q. May a module file use `io.println`?**
>
> A. Yes, with `use io .` in the module too. But when the host that loads the module has not registered `io`, the module is refused. A module meant for many hosts is better off returning results than depending on a host module.

## 10.6 A map written as a module

A table that finds a value by a text key is made with a pool and an index (`index`), as in chapter 7; that is the default. But a pool and an index cannot be parameters of a procedure (standard 9.9), so doing the same thing to several maps means writing the procedures again for each. An array can be a parameter: a map written as a module over an array of records serves several maps with one set of procedures. `kvmap` below is such a module. It is not part of the language: copy it beside the program.

`kvmap.pnx`

```pinax
rem kvmap: a map from text (up to 24 bytes) to int over an array of records the program declares (array m entry N)
rem and passes to every procedure. The start slot is the FNV-1a hash of the key modulo N, probing is linear, and a
rem deleted slot is a tombstone that a later store takes again. Keep N well above the number of keys.
use hash .
use str .

export const key_room 24
const empty 0
const live 1
const gone 2

export record entry
  key str key_room
  value int
  state int
end

def start m array entry, k str gives int do k hash.fnv1a raw m capacity u_mod end

rem the slot of k, or -1
def slot_of m array entry, k str gives int do
  m k start to i
  0 to tries
  loop
    tries m capacity lt not if break . end
    i m idx to r
    r entry.state empty eq if -1 return end
    r entry.state live eq if r entry.key k eq if i return end end
    i 1 add m capacity mod to i
    tries 1 add to tries
  end
  -1
end

rem k takes the value v: err.range when k is longer than key_room, err.full when every slot is live
export def store m array entry, k str, v int or fail do
  k str.len key_room gt if err.range fail end
  m k slot_of to at
  at 0 ge if v at m idx to entry.value return end
  m k start to i
  0 to tries
  loop
    tries m capacity lt not if break . end
    i m idx to r
    r entry.state live eq not if
      k r to entry.key  v r to entry.value  live r to entry.state
      return
    end
    i 1 add m capacity mod to i
    tries 1 add to tries
  end
  err.full fail
end

rem the value of k: err.not_found when it is not there
export def fetch m array entry, k str gives int or fail do
  m k slot_of to at
  at 0 lt if err.not_found fail end
  at m idx entry.value
end

export def holds m array entry, k str gives bool do m k slot_of 0 ge end

rem k is taken out; false when it was not there
export def forget m array entry, k str gives bool do
  m k slot_of to at
  at 0 lt if false return end
  at m idx to r
  gone r to entry.state  "" r to entry.key
  true
end

export def size m array entry gives int do
  0 to n
  m do to r r entry.state live eq if n 1 add to n end end each
  n
end

export def wipe m array entry do
  m do to r empty r to entry.state  "" r to entry.key end each
end

rem the numbers of the live slots put in l, for walking or for sort_by: err.full when l has too little room
export def live_slots m array entry, l list int or fail do
  0 l truncate
  0 m capacity range do to i
    i m idx entry.state live eq if i l push or_fail end
  end each
end
```

`10-kvmap.pnx`

```pinax
use io .
use str .
use kvmap .
array fruit entry 16                       rem two maps of one entry: the same procedures serve both
array veg entry 16
list order int 16
def count_into m array entry, line str do
  line str.words do to w
    m w kvmap.fetch or_else to e 0 end 1 add to c        rem a missing key counts from 0
    m w c kvmap.store or_else to e args "no room for " w . cat io.println end
  end each
end
def show title str, m array entry do
  m order kvmap.live_slots or_else to e return end
  order m sort_by_desc entry.value
  title io.print
  order do to i i m idx to r args " " r entry.key "=" r entry.value . cat io.print end each
  "" io.println
end
fruit "pear fig pear plum pear fig" count_into
veg "leek kale leek" count_into
"fruit:" fruit show
"veg:" veg show
args "fig " fruit "fig" kvmap.holds ", gone " fruit "fig" kvmap.forget ", now " fruit "fig" kvmap.holds . cat io.println
```

*Output*

```text
$ pnx 10-kvmap.pnx
fruit: pear=3 fig=2 plum=1
veg: leek=2 kale=1
fig true, gone true, now false
```

The program declares a map with `array NAME entry N` and passes that name to every procedure. `store` gives a key its value; `fetch` finds the value (failing with `not_found` when the key is not there); `holds` asks whether a key is there; `forget` takes a key out; `size` gives the number of keys; `wipe` takes them all out. `live_slots` puts the numbers of the live slots in a list; sorting that list with `sort_by` walks the map in the order of its keys or values.

|  | **`kvmap`** | **A pool and an index** |
|---|---|---|
| Passed to a procedure | yes: the map is an array | no |
| Several maps | one set of procedures | the procedures again for each map |
| Keys and values | text up to 24 bytes and one `int` | any record |
| Speed | about twice the time (measured with 50 000 keys) | the core’s hash table |
| Room | well above the number of keys; it slows as it fills | the number of keys |

> **Q&A**
>
> **Q. Why are the names not `put` and `get`?**
>
> A. `put`, `get`, `has`, `count`, `clear`, `remove`, `lookup` and `drop` are procedures of the language, and a module written in Pinax cannot define those names again (standard 9.5). So the module uses `store`, `fetch`, `holds` and `forget`.

> **Common mistake: kvmap is a standard module**
>
> It is not. It is an example file of this manual: `use kvmap .` finds it only as `kvmap.pnx` beside the program. For other key lengths or value types, change the copy. When no map is passed around, use a pool and an index.

> **Summary**
>
> - One file is one module, and only what is `export` ed is seen outside (standard 13.1, 13.2).
> - After `use MODULE [as ALIAS] .` its parts are written `MODULE.NAME` (13.1).
> - Procedures, constants and globals are used by path, types and records by name alone; an exported global is stored with `set module.name` (13.2).
> - Values of a declared type are added and subtracted only with the same type (7.4).
> - A data load accepts declarations and values only (13.4).
> - A pool and an index are not parameters; a map passed to procedures is a module over an array ( `kvmap` ) (9.9).
