# 4 Locals and flow

> **Builds on**: Chapter 3 (signatures, named inputs).
>
> **Questions this chapter answers**
>
> - When is a local made, and how far is it visible?

## 4.1 Locals

In a body, `to NAME` puts the top value into that name. The first time a name is used, a local of the value’s type is made; there is no separate line that declares it.

`04-locals.pnx`

```pinax
use io .
def describe a int, b int, c int gives str do
  a b add c add to total
  total 3 div to mean
  a b max c max to top
  args "total " total ", mean " mean ", largest " top . cat
end
3 9 6 describe io.println
```

*Output*

```text
$ pnx 04-locals.pnx
total 18, mean 6, largest 9
```

`to` **takes** the top value off the stack and keeps it in the name. Using the name puts the value back on. Instead of holding values on the stack for long, keep them in names and take them out when needed.

| **Token** | **Stack after it** | **What happened** |
|---|---|---|
| `a b add` | `12` | `a` is 3, `b` is 9. |
| `c add` | `18` | `c` is 6. |
| `to total` | `—` | Takes 18 off and keeps it in a new local `total`. The stack is empty. |
| `total 3 div` | `6` | Using `total` puts 18 on; it is divided by 3. |
| `to mean` | `—` | Keeps 6 in `mean`. |

A local is visible from where it is first stored to the end of the branch, loop or block around it. A name first made inside a branch cannot be read outside it: coming by the other branch, it would hold no value.

`04-scope.pnx`

```pinax
use io .
def f n int gives int do
  n 0 gt if n 2 mul to doubled end
  doubled
end
```

*Refused*

```text
$ pnx 04-scope.pnx
04-scope.pnx:4:3: this name is not declared before this place
```

A global is stored with `set`, not `to`; `to` stores only into locals.

`04-store-global.pnx`

```pinax
use io .
global total int
def add_to_total n int do total n add set total end     rem set: a global is written with set
3 add_to_total
4 add_to_total
args "total " total . cat io.println
```

*Output*

```text
$ pnx 04-store-global.pnx
total 7
```

> **Common mistake: Storing into a global with to total**
>
> `to` with the name of a global is refused, and the message names `set`. A global cannot be hidden, so no local of that name can be made; the rule also keeps a `to` meant to make a local from changing a global silently.
>
> `04-store-global-bare.pnx`
>
> ```pinax
> global total int
> def add_to_total n int do total n add to total end
> ```
>
> *Refused*
>
> ```text
> $ pnx 04-store-global-bare.pnx
> 04-store-global-bare.pnx:2:42: this name is a global; a global is written with set: value set name
> ```

## 4.2 Branches

`condition if … else … end` looks at the `bool` on top and runs one side. Both branches shall leave the same stack; a branch that leaves with `return` does not need to match.

`04-if.pnx`

```pinax
use io .
def grade score int gives str do
  score 90 ge if "A" return end
  score 80 ge if "B" return end
  score 70 ge if "C" else "F" end
end
95 grade io.println
82 grade io.println
40 grade io.println
```

*Output*

```text
$ pnx 04-if.pnx
A
B
F
```

`if` **takes** the `bool` off the top and chooses the way. The two branches have to leave the same stack because the code after `end` does not know which branch it came from. Whichever way it came, the stack must be the same for the processor to check what follows.

`04-sign.pnx`

```pinax
use io .
def sign n int gives str do
  n 0 lt if                     rem lt leaves a bool; if takes it off the stack
    "negative"                  rem this way leaves one str
  else
    n 0 eq if "zero" else "positive" end   rem and so does this way, whichever inner way it takes
  end                           rem both ways meet here with one str on the stack
end
-4 sign io.println
0 sign io.println
9 sign io.println
```

*Output*

```text
$ pnx 04-sign.pnx
negative
zero
positive
```

| **Token** | **Stack after it** | **What happened** |
|---|---|---|
| `n 0 lt` | `true` | With `n` at −4 the comparison leaves `true`. |
| `if` | `—` | Takes the `bool` off and goes to the first branch. |
| `"negative"` | `"negative"` | This branch leaves one `str`. |
| `end` | `"negative"` | The `else` branch also leaves one `str`, so the two ways agree. |

An `if` without `else` shall leave the stack as it was. Leaving out the `else` of an `if` that leaves a value is refused.

`04-if-unequal.pnx`

```pinax
use io .
def label n int gives str do n 0 lt if "negative" end end
```

*Refused*

```text
$ pnx 04-if-unequal.pnx
04-if-unequal.pnx:2:51: an if without else must leave the stack as it found it
```

## 4.3 Loops

`loop … end` repeats. Inside it, `break .` leaves the loop and `continue .` goes on to the next turn. A condition is written with `if`: `i n gt if break . end`. One turn shall leave the stack as it found it — so the values a loop makes are gathered in locals.

`04-loop.pnx`

```pinax
use io .
def collatz n int gives int do              rem steps to reach 1
  0 to steps
  loop
    n 1 eq if break . end
    n 2 mod 0 eq if n 2 div else n 3 mul 1 add end to n
    steps 1 add to steps
  end
  steps
end
args "27 takes " 27 collatz " steps" . cat io.println
```

*Output*

```text
$ pnx 04-loop.pnx
27 takes 111 steps
```

One turn leaves the stack as it found it for the same reason. The head of the loop sees the stack both when the loop is first entered and when a turn comes back, and both must be the same. If each turn piled up one more value, the processor, which cannot know how many turns there will be, could not fix the depth of the stack. So the values a loop makes are gathered in locals.

`04-loop-sum.pnx`

```pinax
use io .
use str .
def sum_to n int gives int do
  0 to total                    rem what the loop builds lives in locals, not on the stack
  1 to i
  loop
    i n gt if break . end                rem leave once i passes n
    total i add to total        rem the stack is empty again at the end of the turn
    i 1 add to i
  end
  total
end
10 sum_to str.to_str io.println
```

*Output*

```text
$ pnx 04-loop-sum.pnx
55
```

`04-loop-leaves.pnx`

```pinax
def count_up n int gives int do
  0 to i
  loop
    i n ge if break . end
    i 1 add                     rem a new value each turn, and nothing takes it
  end
  i
end
```

*Refused*

```text
$ pnx 04-loop-leaves.pnx
04-loop-leaves.pnx:6:3: one turn of a loop must leave the stack as it found it
```

`count_up` makes a value with `i 1 add` every turn, and nothing takes it. With `to i` after it the value goes into `i` and the stack is as it was at the start of the turn.

A named loop can be left all at once from an inner loop.

`04-named-loop.pnx`

```pinax
use io .
def is_prime n int gives bool do
  n 2 lt if false return end
  2 to d
  loop
    d d mul n gt if true return end
    n d mod 0 eq if false return end
    d 1 add to d
  end
end
def first_pair target int gives str do       rem the first a < b <= 20, both prime, with a + b = target
  2 to a
  0 to b
  loop
    a 1 add to b
    loop
      b 20 gt if break . end
      a is_prime b is_prime and a b add target eq and if break 2 . end
      b 1 add to b
    end
    a 1 add to a
    a 20 gt if "none" return end
  end
  args a " + " b . cat
end
26 first_pair io.println
```

*Output*

```text
$ pnx 04-named-loop.pnx
7 + 19
```

> **Q&A**
>
> **Q. Can I give the number of loops to leave instead?**
>
> A. No. With a number, wrapping a loop in one more would quietly leave another loop. A name cannot do that.

## 4.4 Choosing

`match` compares an `int` or `str` with the values of its branches. A branch is `when VALUE do … end`; several values for one branch stand after `when` one after another. What to do when nothing matches goes in `otherwise`; with no `otherwise` and no match, it is a fault.

`04-case.pnx`

```pinax
use io .
def day_kind day str gives str do
  day match
    when "sat" "sun" do "weekend" end
    when "mon" "tue" "wed" "thu" "fri" do "weekday" end
    otherwise "not a day" end
  end
end
"sun" day_kind io.println
"wed" day_kind io.println
"xyz" day_kind io.println
```

*Output*

```text
$ pnx 04-case.pnx
weekend
weekday
not a day
```

The values of the branches are literals or `const`s of this source. Constants of modules such as `err.full` or `json.key` cannot be `match` values; compare them with `eq`.

## 4.5 Rails and blocks

A loop over an array or a list is written with a **rail** and a **combining procedure** instead. The name of the array is the rail, and a `do … end` block after it, with a procedure such as `each`, `count` or `fold`, takes it. The block is expanded in place, so it can use the locals around it.

`04-rails.pnx`

```pinax
use io .
use str .
array temps int 7
assign temps (12, 15, 9, 21, 18, 7, 14)
args "sum " temps sum ", above 13: " temps do to t t 13 gt end count . cat io.println
args "max " temps maximum or_else to e 0 end ", min " temps minimum or_else to e 0 end . cat io.println
temps do to i to t args "day " i ": " t . cat io.println end each_index
def spread gives int do 0 temps do to t to acc acc t 10 sub abs add end fold end
args "distance from 10, added up: " spread . cat io.println
```

*Output*

```text
$ pnx 04-rails.pnx
sum 96, above 13: 4
max 21, min 7
day 0: 12
day 1: 15
day 2: 9
day 3: 21
day 4: 18
day 5: 7
day 6: 14
distance from 10, added up: 34
```

`lo hi range` is a rail too (`hi` is not included). `fold` takes a first value before the rail, and its block takes (the value so far, an element) and gives the new value.

The block of `each`, `each_index` or `times` is left early with `break .` (and `continue .` goes to the next element), as a loop is; `do to NAME … end` takes the element into a name. The rail stops and the code after the procedure runs. A search that stops at the first hit is written so.

`04-leave-each.pnx`

```pinax
use io .
array prices int 6
def load_prices do
  0 6 range do to i i 7 mul 3 add i set prices end each
end
def first_over limit int gives r int do
  -1 to found
  prices do to i to p
    p limit gt if i to found break . end
  end each_index
  found
end
load_prices
args "first over 20 at " 20 first_over . cat io.println
args "first over 99 at " 99 first_over . cat io.println
```

*Output*

```text
$ pnx 04-leave-each.pnx
first over 20 at 3
first over 99 at -1
```

A rail is shaped with adapters: `skip N`, `head N`, `step N` and `rev`. They apply in the order written and the loop is still one. An `N` that is an expression ends with a comma.

`04-rail-adapters.pnx`

```pinax
use io .
use str .
array scores int 8
assign scores (10, 20, 30, 40, 50, 60, 70, 80)
def show n int do " " io.print n str.to_str io.print end
0 10 range step 3 do to i i show end each "" io.println          rem 0 3 6 9
scores skip 2 head 3 do to s s show end each "" io.println       rem the third to the fifth
scores head 3 skip 1 do to s s show end each "" io.println       rem the second and the third
scores rev head 3 do to s s show end each "" io.println          rem from the last
0 20 range skip 2 3 add, head 4 step 2 do to i i show end each "" io.println   rem N may be code, ended by a comma
scores skip 1 head 3 sum show "" io.println                      rem 20 + 30 + 40
```

*Output*

```text
$ pnx 04-rail-adapters.pnx
 0 3 6 9
 30 40 50
 20 30
 80 70 60
 5 7
 90
```

`scores skip 2 head 3` is the third to the fifth, `scores head 3 skip 1` the second and the third: the order changes the meaning. `step` and `rev` are for **closed rails** (`range`, an array, a list: the length is known and any place can be read); `skip` and `head` also work on **open rails** (`str.words`, `str.lines` …: the pieces come one after another). `step` comes last.

There are adapters with a block too: `do to s s 4 gt end filter` (keep), `skip_while`, `head_while`, `map` (change to a value of the same type). They run inside the loop for each element and work on open rails too: `scores do to s s 4 gt end filter do to s s 100 mul end map sum`. Two arrays are walked side by side with `xs ys zip do to y to x ... end each`.

## 4.6 Procedures as values

A block that is not given to a combining procedure is written `def signature do … end` and is a **value**: it can be kept in a local, returned, or given to a parameter of a `proc` type (`type NAME proc signature end`), and `call` calls it. Such a block sees no locals around it. To give a procedure of the program as a value, write `ref NAME`: the value is that procedure, with its signature.

`04-word-values.pnx`

```pinax
use io .
use str .
def up a int, b int gives bool do a b lt end
def down a int, b int gives bool do a b gt end
type Proc1 proc int, int gives bool end def best before Proc1, x int, y int gives int do y x before call if y else x end end
def order_named how str gives Proc1 or fail do
  how match
    when "up" do ref up end
    when "down" do ref down end
    otherwise err.not_found fail end
  end
end
def demo or fail do
  "up" order_named or_fail to smallest_first
  "down" order_named or_fail to largest_first
  args "smallest " smallest_first 7 3 best ", largest " largest_first 7 3 best . cat io.println
end
demo or_else to e e err_text io.println end
```

*Output*

```text
$ pnx 04-word-values.pnx
smallest 3, largest 7
```

> **Q&A**
>
> **Q. How is a procedure of the language, such as `str.starts_with`, given as a value?**
>
> A. With the block’s signature written as types only: `def str, str gives bool do str.starts_with end`. Inputs written as types stay on the stack, so the procedure takes them as it is. Without a signature the block takes nothing, and the message shows both forms.

> **Common mistake: A match branch can hold the procedure itself: when "prefix" do str.starts_with end**
>
> A branch runs its procedures; it does not make a value of them. There `str.starts_with` is called, and finds too few values on the stack. Make the value with a block: `when "prefix" do def str, str gives bool do str.starts_with end end`, or `ref NAME` for a procedure of the program.
>
> `04-word-values-branch.pnx`
>
> ```pinax
> use str .
> type Proc1 proc str, str gives bool end def test_named how str gives Proc1 or fail do
>   how match
>     when "prefix" do str.starts_with end
>     otherwise err.not_found fail end
>   end
> end
> ```
>
> *Refused*
>
> ```text
> $ pnx 04-word-values-branch.pnx
> 04-word-values-branch.pnx:4:22: the stack does not hold enough values for this word
> ```

> **Q&A**
>
> **Q. What if the two branches of `if` should leave values of different types?**
>
> A. They cannot. The code after `if` does not know which branch ran, so both leave the same number of values of the same types. When one branch has a value and the other has not, that is a failure (chapter 8) or a row asked with `is_none` (chapter 7).

> **Summary**
>
> - `to NAME` stores into a local, `set NAME` into a global (standard 9.4).
> - A name made inside a branch is not visible outside it (9.4).
> - `to` takes the top value off into a name; using the name puts it back on (9.4).
> - The two branches of `if` and the branches of `match` leave the same stack; one turn of a loop leaves the stack it found (10).
> - Several loops are left at once with a count, `break 2 .` (10.2).
> - Arrays and lists are walked with rails: `each` `each_index` `count` `fold` `sum` … (10.6); the block of `each` , `each_index` or `times` is left with `break` (10.6 (4)).
> - `ref NAME` is the procedure `NAME` as a value; any other procedure is given as `def signature do procedure end` (10.5).
