# 16 Messages you will meet

> **Builds on**: Chapters 1 to 15. A chapter to look things up in.
>
> **Questions this chapter answers**
>
> - The processor refused my program. What does the message mean, and how is it fixed?
> - The program stopped while running. What does the name of the fault mean?

A message has the form `file:line:column: reason`. Lines and columns count from 1, and the column is the byte position in the line. The processor reports the first mistake it meets, so after a fix the next one may show. The messages below are exactly what the processor prints; the chapters in the right column have examples that produce them.

## 16.1 The stack and types

| **Message** | **Meaning and fix** | **Chapter** |
|---|---|---|
| `the stack does not hold enough values for this word` | The word takes more values than the stack holds. Check that the values were put on first, and in the right order. `pnx see` shows the stack after each line. | 2, 15 |
| `values are left on the stack at the end of the source` | A value that nothing took is left when the program ends. Print it, `drop` it, or add the word that was forgotten. | 2 |
| `the stack does not hold exactly the results of the signature here` | What is left when the body of a word ends differs from the results of its signature. Write the results into the signature, or clear what is left. | 3 |
| `this word takes two int values, or two of the same declared type` | An arithmetic word got another type. Text becomes a number with `str.to_int`, a number becomes text with `str.to_str`. | 2 |
| `an if without else must leave the stack as it found it` | An `if` without `else` leaves a value. Add an `else` branch that leaves a value of the same type. | 4 |
| `one turn of a loop must leave the stack as it found it` | One turn of a loop leaves or takes a value. Keep what it makes in a local with `to NAME`. | 4 |
| `inputs are all named or all bare types, not a mix` | A signature mixes named inputs and inputs given as types only. Name them all. | 3 |

## 16.2 Names

| **Message** | **Meaning and fix** | **Chapter** |
|---|---|---|
| `this name is not declared before this place` | The name does not exist, or is used before it is declared. Check the spelling and where it is declared; words that call each other use `forward word`. | 1, 3 |
| `this path names neither a module in use nor a record` | The module of `module.word` was not opened. Write `use module` at the top of the file. | 1, 10 |
| `this name is already visible here; a new name may not hide it` | A visible name (including core words such as `sum`, `count`, `first`) was used for a new name. Choose another. | 3 |
| `outside a definition `+“`to`”+` makes no new local; a global is written with set` | `to` was used outside a definition, where there are no locals. Put the work into a word, or store into a global with `set`. | 4 |
| `this name is a global; a global is written with set: value set name` | A global, or a cell of a global collection, was stored into with `to`. Write `value set name`; a cell is `value i set name`. | 4, 6 |

## 16.3 Failures and owned values

| **Message** | **Meaning and fix** | **Chapter** |
|---|---|---|
| `a word that can fail is followed by or_fail, or_return or or_else` | A word that can fail (`push`, `str.to_int`, a word with `or fail` in its signature) has no guard word after it. Even to ignore the failure, write `or_else (e) end`. | 6, 8 |
| `the body of or_else must leave what the word would have given, or leave the word or the loop` | The body of `or_else` leaves other values than success would. Leave a stand-in of the same type, or leave with `return` or `break`. | 8 |
| `an owned value is kept in a local or given on at once; this word would lose it` | An `owned` value is about to be lost with `drop`, or left on the stack. Keep it in a local and close it at the end (`defer` makes it easy). | 9 |
| `a field holds str(N); a str view lives only in locals, arguments and results` | A view `str` was used for a field or a global. Declare it `str(N)`. | 5 |

## 16.4 When a run stops: faults

A program that loaded can still stop with a **fault** while it runs. `pnx` shows the reason, the line and the locals of the word.

| **Fault** | **What `pnx` says** | **Meaning** |
|---|---|---|
| `overflow` | `integer overflow` | An integer went beyond 64 bits (chapter 2). The `chk_` words give it as a failure. |
| `div_zero` | `division by zero` | Division by 0. |
| `range` | `index out of range` | A cell number outside the length, or a field of the “none” row (chapters 6, 7). |
| `full` | `a declared capacity is used up` | The region or the room of a stored text ran out (chapter 5). |
| `depth` | `call depth limit` | Calls went too deep. Look for a recursion that does not end (chapter 3). |
| `stale` | `a row or handle was used after it was given back` | A pool row given back, or a closed handle, was used (chapters 7, 9). |
| `deadlock` | `deadlock: waiting for a queue that nothing can change` | Every task waits for a queue (chapter 13). |

> **Q&A**
>
> **Q. Can a fault be caught inside the script?**
>
> A. No. A fault points at a place where the program has to be fixed. Where something can go wrong because of data from outside, use a word that gives a failure instead (`chk_mul`, `str.to_int` and so on) and handle it with `or_else` (chapter 8).

> **Summary**
>
> - A refusal reports the first mistake met, with `file:line:column` (standard 4).
> - Mistakes with the stack, names, failures and `owned` values all show before the program runs (standard 4).
> - A fault is a mistake that can only be known while running, and it stops the run (11.3).
