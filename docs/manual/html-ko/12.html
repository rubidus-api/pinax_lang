11 글과 바이트의 형식

먼저 알아야 할 것: 5장(뷰, 버퍼), 7장(레코드), 8장(실패).

이 장이 답하는 물음

  • CSV 나 JSON 을 나무를 만들지 않고 어떻게 읽고 쓰는가?
  • 레코드를 바이트로 보내고 다시 읽으려면?
  • 해시와 Base64 같은 바꾸기는 어디에 있는가?

Pinax 에는 힙이 없으므로 JSON 을 객체의 나무로 읽지 않는다. 대신 한 방향으로 읽는다: 토큰 하나, 필드 하나씩. 쓸 때는 버퍼에 바로 쓴다. 레코드와 맞추는 일은 레코드의 선언에서 만들어진 코드가 한다.

11.1 CSV 와 JSON

csv.unpack 은 한 줄을 읽어 레코드의 필드에 차례로 넣고, json.pack 은 레코드를 필드 이름이 키인 객체로 쓴다.

11-csv-to-json.pnx

use io
use csv
use json
use str
rem Read CSV rows into records, write them out as JSON.
record city
  name str(16)
  people i32
  capital bool
end
list cities city 8
buffer out 512
word read_rows (input str or fail)
  input str.lines do (line str)
    cities len to before
    cities add_row or_fail to c
    line c csv.unpack or_else (e) before cities truncate  cat ("bad row: ", line) io.println  "" end drop
  end each
end
word to_json (or fail)
  out json.begin_array or_fail
  cities do (c cities) c out json.pack or_else (e) end end each
  out json.end_array or_fail
end
text END
Seoul,9411000,true
Busan,3349000,false
Daejeon,lots,false
END
read_rows or_else (e) end
to_json or_else (e) e err_text io.println end
out contents io.println

출력

$ pnx 11-csv-to-json.pnx
bad row: Daejeon,lots,false
[{"name":"Seoul","people":9411000,"capital":true},{"name":"Busan","people":3349000,"capital":false}]

줄을 먼저 더하고 unpack 이 실패하면 before cities truncate 로 그 줄을 되돌린다. truncate 는 목록의 길이를 더하기 전의 길이로 줄인다.

흔한 오해: 레코드 목록에서도 pop 으로 마지막 줄을 뺀다

레코드의 목록에는 pop 이 없다(값의 목록에만 있다). 마지막 줄은 truncate 로 거둔다. 다만 그 목록의 줄을 찾아보기나 필드가 담고 있으면 truncate 도 거절된다. 그때는 줄을 더하기 전에 확인한다.

11-pop-records.pnx

record city
  name str(16)
end
list cities city 4
word undo () cities pop or_else (e) cities none end drop end

거절

$ pnx 11-pop-records.pnx
11-pop-records.pnx:5:21: pop takes from a list of values; a list of records has no pop

JSON 을 토큰으로 읽으면 깊이와 상관없이 필요한 것만 고를 수 있다. json.next 는 토큰의 갈래, 값의 뷰, 나머지를 준다.

11-json-read.pnx

use io
use json
use str
rem Sum every number in a JSON text, at any depth, without building a tree.
word sum_numbers (s str gives int)
  0 to total
  s to rest
  loop
    rest json.next or_else (e) break end to (kind, value, rest)
    kind json.number eq if total value str.to_int or_else (e) 0 end add to total end
  end
  total
end
text END
{"a": 1, "b": [2, 3, {"c": 4}], "d": {"e": [5]}, "f": "6"}
END
sum_numbers str.to_str io.println

출력

$ pnx 11-json-read.pnx
15

json.next 가 주는 셋을 한 토큰씩 보자. s json.next 는 (kind int, value str, rest str) 를 준다: 토큰의 갈래, 그 토큰의 글(뷰), 그리고 그 뒤에 남은 글이다. 남은 글을 다시 json.next 에 주는 것을 되풀이하면 글 전체를 앞에서부터 한 번 훑는다. 글이 끝나면 json.next 가 실패하고, 루프는 그 실패로 끝난다.

11-json-tokens.pnx

use io
use json
rem The tokens of a JSON text, one at a time: what json.next gives for each.
word kind_name (k int gives str)       rem module constants are compared with eq, not case
  k json.object eq if "object" return end
  k json.object_end eq if "object end" return end
  k json.array eq if "array" return end
  k json.array_end eq if "array end" return end
  k json.key eq if "key" return end
  k json.string eq if "string" return end
  k json.number eq if "number" return end
  "other"
end
word show_tokens (s str)
  s to rest
  loop
    rest json.next or_else (e) break end to (kind, value, rest)   rem fails at the end: leave the loop
    cat (kind kind_name, " [", value, "]") io.println
  end
end
"{\"name\": \"Pinax\", \"sizes\": [8, 16]}" show_tokens

출력

$ pnx 11-json-tokens.pnx
object [{]
key [name]
string [Pinax]
key [sizes]
array [[]
number [8]
number [16]
array end []]
object end [}]
토큰그 뒤의 스택일어난 일
rest json.nextjson.object "{" …{ 를 읽었다. 갈래 json.object, 남은 글은 "name": ….
or_else (e) break endjson.object "{" …실패하지 않았으므로 몸을 건너뛴다.
to (kind, value, rest)—셋을 이름에 담는다. 오른쪽 rest 가 맨 위 값을 받는다.

갈래는 json.object 처럼 모듈의 상수이므로 case 가 아니라 eq 로 견준다(4장). 갈래마다 할 일만 고르면 되므로, 깊이가 얼마든 필요한 값만 뽑을 수 있다. 11-json-read.pnx 는 json.number 만 골라 더했다.

관심 없는 값은 json.skip 으로 한 번에 건너뛴다. 객체나 배열이면 그 안 전부를 건너뛰므로 깊이를 셀 필요가 없다. 갈래의 상수는 json.object json.object_end json.array json.array_end json.key json.string json.number json.boolean json.null 이다. 거꾸로 객체 하나를 레코드의 줄에 채우는 것은 json.unpack 이다: 모든 필드가 맞을 때만 줄에 쓰고, 아니면 실패다.

11-json-skip.pnx

use io
use str
use json
record point
  x int
  y int
end
array pts point 1
word demo (or fail)
  "{\"tags\": [1, [2, 3]], \"x\": 4}" json.next or_fail to (k, v, rest)   rem the {
  rest json.next or_fail to (k, v, rest)                                   rem the key tags
  rest json.skip or_fail to rest                                           rem the whole array, however deep
  rest json.next or_fail to (k, v, rest)                                   rem the key x
  rest json.next or_fail to (k, v, rest)                                   rem 4
  cat ("after the skip: ", v, ", a number? ", k json.number eq) io.println
  "{\"x\": 7, \"y\": 9}" 0 pts idx json.unpack or_fail drop
  cat ("unpacked ", 0 pts idx point.x, " ", 0 pts idx point.y) io.println
  "{\"x\": true}" 0 pts idx json.unpack or_else (e) cat ("unpack failed: ", e err_text) io.println "" end drop
end
demo or_else (e) e err_text io.println end

출력

$ pnx 11-json-skip.pnx
after the skip: 4, a number? true
unpacked 7 9
unpack failed: format

CSV 를 쓰는 쪽은 필드 하나씩이다. csv.put 은 글을(쉼표, 따옴표, 줄바꿈이 들어 있으면 따옴표로 싸서), csv.put_int csv.put_dec csv.put_bool 은 수와 참거짓을, csv.end_line 은 줄 끝을 버퍼에 붙인다. 앞에 필요한 쉼표는 낱말이 넣는다. 레코드의 줄 하나를 한 줄로 쓰는 것은 csv.pack 이다.

11-csv-write.pnx

use io
use csv
buffer out 64
word demo (or fail)
  "kim" out csv.put or_fail  3 out csv.put_int or_fail  true out csv.put_bool or_fail  out csv.end_line or_fail
  "a, b" out csv.put or_fail  2.50 out csv.put_dec or_fail  out csv.end_line or_fail
  out contents io.print
end
demo or_else (e) e err_text io.println end

출력

$ pnx 11-csv-write.pnx
kim,3,true
"a, b",2.50

11.2 경로, 설정 파일, Markdown

토큰으로 읽는 것은 흐름에 맞다. 글이 문서이고 값 하나가 필요하면 json.at 이 경로를 받는다: 점으로 이은 이름과 괄호 안의 번호, user.langs[1]. 값의 종류와 글을 주고, 객체나 배열은 적힌 대로 통째로 주므로 다시 물을 수 있다. 없는 값은 err.not_found 이니 기본값은 or_else 에 둔다. json.valid 는 글이 JSON 인지 보고, json.minify 와 json.pretty 는 글을 버퍼에 공백 없이, 또는 값 하나에 한 줄씩 쓴다.

11-json-path.pnx

use io
use json
word main (or fail)
  text END
{"user": {"name": "kim", "langs": ["ko", "en"]}, "visits": 12}
END
  to doc
  "user.name" doc json.at or_fail io.println drop      rem the value at a path
  "user.langs[1]" doc json.at or_fail io.println drop  rem an index in brackets
  "visits" doc json.at or_fail drop json.number eq to is_number
  cat ("visits is a number: ", is_number) io.println
  "user.email" doc json.at or_else (e) cat ("no email: ", e err_text) io.println 0 "" end drop drop
end
main or_else (e) e err_text io.println end

출력

$ pnx 11-json-path.pnx
kim
en
visits is a number: true
no email: not_found

설정 파일의 형식인 TOML 은 모듈 toml 이 같은 방식으로 읽는다: 경로를 준 toml.at(server.ports[1], 둘째 [[backend]] 는 backend[1].url), 또는 머리를 포함해 모든 문장을 차례로 주는 toml.next. 값은 적힌 대로 준다: 문자열은 따옴표를 떼고(이스케이프는 풀어서), 수는 그 글로. toml.check 는 프로그램이 파일을 믿기 전에 문서 전체를 따진다: 두 번 준 키, 두 번 연 표, 64비트에 안 드는 정수, 없는 날짜는 err.format 이다. toml.set 은 경로로 값 하나를 바꾸고(없으면 그 표의 끝에 키를 더하고) toml.remove 는 키를 지운다. 둘 다 결과를 버퍼에 쓰며, 그 밖의 파일 내용은 주석까지 그대로 남는다.

11-toml-config.pnx

use io
use toml
word main (or fail)
  text END
name = "shop"            # the name of the service
[server]
host = "0.0.0.0"
ports = [8080, 8443]
[[backend]]
url = "http://a.local"
[[backend]]
url = "http://b.local"
END
  to conf
  "server.host" conf toml.at or_fail io.println drop
  "server.ports[1]" conf toml.at or_fail io.println drop
  "backend[1].url" conf toml.at or_fail io.println drop
  conf toml.valid to fine
  cat ("valid: ", fine) io.println
end
main or_else (e) e err_text io.println end

출력

$ pnx 11-toml-config.pnx
0.0.0.0
8443
http://b.local
valid: true

Markdown 은 md.html 로 HTML 이 된다: 제목, 문단, 강조, 코드, 링크, 목록, 인용, 표. 글 속의 날 HTML 은 넘기지 않고 javascript: 로 가는 링크는 글로만 쓰므로, 결과를 쪽에 넣어도 안전하다. md.next 는 문서를 블록 하나씩 읽고, md.inline 은 문단으로 싸지 않고 한 줄만 쓴다. 둘 다 CommonMark 의 부분집합이다(표준 16.12 에 적혀 있다).

11-md-html.pnx

use io
use md
buffer page 1024
word main (or fail)
  text END
## Notes

A line with *emphasis*, `code` and a [link](https://example.org).
Raw <b>tags</b> stay text.

1. first
2. second
END
  to doc
  doc page md.html or_fail
  page contents io.println
end
main or_else (e) e err_text io.println end

출력

$ pnx 11-md-html.pnx
<h2>Notes</h2>
<p>A line with <em>emphasis</em>, <code>code</code> and a <a href="https://example.org">link</a>.
Raw &lt;b&gt;tags&lt;/b&gt; stay text.</p>
<ol>
<li>first</li>
<li>second</li>
</ol>

문답

물음. json.at 뒤에 나무가 남는가?

답. 아니다. 호출마다 글을 앞에서부터 원하는 값까지 다시 읽는다. 큰 문서에서 값을 많이 뽑으려면 한 번만 읽는 토큰 낱말이 더 싸다.

11.3 바이트

모듈 bytes 는 정해진 폭과 바이트 순서로 쓰고 읽는다. 레코드에 big_endian 을 적으면 bytes.pack 이 큰 끝부터 쓴다. varint 필드는 작은 수를 적은 바이트로 쓴다.

11-binary.pnx

use io
use bytes
use encode
use hash
use fmt
record header
  big_endian
  magic u32
  version u16
  length varint
end
array headers header 2
buffer wire 32
buffer hex 64
word demo (or fail)
  0 headers idx to h
  0x50494e58 u32 h to header.magic           rem "PINX"
  1 u16 h to header.version
  300 h to header.length
  h wire bytes.pack or_fail
  wire contents hex encode.hex_encode or_fail
  cat ("bytes: ", hex contents, ", crc32: ", wire contents hash.crc32 fmt.hex) io.println
  1 headers idx to back
  wire contents back bytes.unpack or_fail drop
  cat ("read back: version ", back header.version, ", length ", back header.length) io.println
end
demo or_else (e) e err_text io.println end

출력

$ pnx 11-binary.pnx
bytes: 50494e580001ac02, crc32: 31d80bed
read back: version 1, length 300

쓰는 낱말(pack, put_…, encode.…_encode)은 버퍼가 차면 실패한다. 그래서 뒤에 늘 지킴 낱말이 와야 한다.

11-pack-unguarded.pnx

use json
record point
  x int
  y int
end
list points point 2
buffer out 64
word write (p points) p out json.pack end   rem pack fails when the buffer is full: no guard

거절

$ pnx 11-pack-unguarded.pnx
11-pack-unguarded.pnx:8:39: a word that can fail is followed by or_fail, or_return or or_else

문답

물음. 메모리 안의 레코드도 큰 끝으로 놓이는가?

답. 아니다. big_endian 은 pack 과 unpack 이 쓰는 바이트의 차례만 정한다. 메모리 안의 모양은 처리기가 정하고, 스크립트는 그것을 볼 수 없다.

11.4 그 밖의 바꾸기

fmt 는 수를 십육진, 이진, 0 을 채운 모양으로 바꾼다. hash 는 CRC-32, FNV-1a, SipHash 를, encode 는 Base64, 십육진, URL 퍼센트 부호화를 준다. 바꾼 결과를 버퍼에 쓰는 낱말은 버퍼가 차면 실패한다. 자세한 목록은 표준 16절에 있다.

해시는 글을 받아 int 를 준다. hash.crc32 는 검사합으로, hash.fnv1a 와 hash.hash64 는 키를 섞는 데 쓴다. 레코드 한 줄이 bytes.pack 으로 몇 바이트가 되는지는 bytes.packed_size 가 미리 알려 준다 — 버퍼의 자리를 가늠할 때 쓴다.

11-hash.pnx

use io
use fmt
use hash
use bytes
record pair
  a u16
  b int
end
array pairs pair 1
word demo ()
  cat ("crc32 ", "pinax" hash.crc32 fmt.hex, ", fnv1a ", "pinax" hash.fnv1a fmt.hex) io.println
  cat ("a pair packs into ", 0 pairs idx bytes.packed_size, " bytes") io.println
end
demo

출력

$ pnx 11-hash.pnx
crc32 19afea99, fnv1a 131b946615bc7b35
a pair packs into 10 bytes

문답

물음. JSON 으로 쓸 때 들여쓰기나 줄바꿈을 넣을 수 있는가?

답. json 의 쓰는 낱말은 한 줄로 붙인다. 사람이 읽을 모양이 필요하면 그 글을 json.pretty 에 주면 멤버마다 한 줄로 쓴다.

정리

  • json.next 와 csv.fields 는 한 토큰, 한 필드씩 읽는다. 나무를 만들지 않는다(표준 16.8, 16.9).
  • pack 은 버퍼에 쓰고, unpack 은 모두 맞을 때만 줄에 쓴다(16.5, 16.8, 16.9).
  • json.at 과 toml.at 은 경로로 값을 찾고, md.html 은 Markdown 에서 안전한 HTML 을 만든다(16.8, 16.11, 16.12).
  • big_endian 은 바이트 순서만 정한다(16.5).
  • 레코드의 목록에는 pop 이 없다(15.3).
