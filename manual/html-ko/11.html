10 모듈과 자료 파일

먼저 알아야 할 것: 1장(use), 3장(서명).

이 장이 답하는 물음

  • 프로그램을 여러 파일로 나누려면?
  • 모듈은 무엇을 밖에 보이고 무엇을 숨기는가?
  • 설정 파일을 코드 없이 읽으려면?

10.1 모듈 만들기#

파일 하나가 모듈 하나다. 모듈의 이름은 파일 이름에서 .pnx 를 뗀 것이다. 밖에 보일 것에는 export 를 붙인다.

money.pnx

rem A small module: amounts are cents, kept apart from plain numbers.
export type cents int
def pad2 n int gives str do n 10 lt if args "0" n . cat else args n . cat end end
export def of_won won int gives cents do won 100 mul cents end
export def show c cents gives str do args c raw 100 div "." c raw 100 mod pad2 . cat end

cents 는 int 위의 선언한 타입이다. 표현은 정수이지만 int 와 섞이지 않는다. raw 가 바탕의 정수를 꺼낸다. cents 를 정수로 곱하거나 나누면 결과도 cents 다(c 3 mul). 몇 배 해도 단위는 그대로이기 때문이다. 정수가 필요한 show 의 나눗셈만 raw 를 쓴다.

10.2 모듈 쓰기#

use money . 를 쓰면 money.of_won 처럼 경로로 쓴다. 내보낸 타입 cents 는 이름만으로 쓴다. pnx 는 money 가 등록된 모듈이 아니면 프로그램 옆의 money.pnx 를 먼저 적재한다.

10-use.pnx

use io .
use money .
def total a cents, b cents gives cents do a b add end
args "total " 12 money.of_won 3 money.of_won total money.show . cat io.println

출력

$ pnx 10-use.pnx
total 15.00

10-use-as.pnx

use io .
use money as m .
args "price " 7 m.of_won m.show . cat io.println

출력

$ pnx 10-use-as.pnx
price 7.00

내보내지 않은 pad2 는 밖에서 보이지 않는다.

10-private.pnx

use money .
5 money.pad2 drop

거절

$ pnx 10-private.pnx
10-private.pnx:2:3: the module exports nothing of this name

모듈은 프로시저 말고도 상수, 전역, 타입, 레코드를 내보낼 수 있다. 쓰는 꼴은 이렇다.

내보낸 것읽기·부르기비고
프로시저모듈.프로시저서명은 모듈 안과 같다
상수 (const)모듈.이름
전역 (global 과 모음)모듈.이름넣을 때는 값 set 모듈.이름
타입, 레코드, 표의 줄 타입이름만cents 처럼 경로 없이 쓴다

아래 모듈 tally 는 상수 하나, 전역 하나, 프로시저 하나를 내보낸다. 전역을 바꾸는 것은 대개 모듈 자신의 프로시저(bump)이 맡지만, 밖에서도 set tally.hits 로 넣을 수 있다.

tally.pnx

rem A module that keeps a count: an exported constant, an exported global and a word.
export const limit 3
export global hits int
export def bump gives bool do          rem true while hits is still under the limit
  hits limit lt if hits 1 add set hits true else false end
end

10-tally.pnx

use io .
use tally .
def try_once do
  tally.bump if "counted" else "limit reached" end io.println
end
try_once try_once try_once try_once                 rem the fourth time the limit is reached
args "hits " tally.hits " of " tally.limit . cat io.println   rem read an exported global and constant
0 set tally.hits                                    rem an exported global is written with set module.name
args "hits after reset " tally.hits . cat io.println

출력

$ pnx 10-tally.pnx
counted
counted
counted
limit reached
hits 3 of 3
hits after reset 0

use 한 모듈을 찾지 못하면 적재 때 거절된다. pnx 는 표준 모듈과 호스트 모듈을 먼저 보고, 없으면 프로그램 파일 옆의 이름.pnx 를 찾는다.

10-unknown-module.pnx

use maths .                                           rem no maths.pnx beside the program, no such module

거절

$ pnx 10-unknown-module.pnx
10-unknown-module.pnx:1:5: no module of this name is registered or loaded

문답

물음. 모듈의 이름은 누가 정하는가?

답. 적재하는 쪽이다. pnx 는 파일 이름에서 .pnx 를 뗀 것을 쓰고, C 호스트는 pinax_load 에 이름을 준다. 그래서 파일 안에는 모듈의 이름을 적는 줄이 없다. 이름이 같은 모듈 둘은 한 상태에 함께 있지 못한다.

흔한 오해: cents 도 결국 정수니까 더해도 된다

cents 와 int 를 더하면 거절된다. 같은 선언한 타입끼리만 더하고 뺀다. 단위가 다른 수를 섞는 실수를 막으려고 타입을 나눈 것이다.

10-mixed.pnx

use money .
12 money.of_won 3 add drop

거절

$ pnx 10-mixed.pnx
10-mixed.pnx:2:19: a declared type is added to and subtracted from its own type, and multiplied, divided or taken modulo by an int; for other arithmetic take raw

10.3 모듈의 맨 이름#

같은 모듈을 줄곧 부르는 스크립트, 무엇보다 셸 스크립트는 set_order 로 찾는 순서에 그 모듈들을 이름 붙일 수 있다. 그러면 그 모듈의 프로시저를 맨 이름으로 쓴다.

10-order.pnx

set_order io str .
"pinax" upper println
"a,b,c" "," "+" replace println

출력

$ pnx 10-order.pnx
PINAX
a+b+c

순서는 마지막에 쓰인다. 맨 이름은 먼저 지역 변수, 다음은 소스의 이름, 다음은 핵 프로시저이다. 그다음에야 순서의 모듈을 왼쪽부터 찾는다. 그래서 str 이 순서에 있어도 len 은 핵 프로시저이고, str 의 프로시저는 str.len 으로 쓴다. set_order . 는 순서를 다시 비운다. 경로는 순서가 있든 없든 쓸 수 있다.

문답

물음. 다른 모듈을 다시 쓰지 않고 하나만 더하려면?

답. set_order 안의 get_order 는 지금의 순서를 뜻한다. set_order get_order
str . 는 str 을 그 뒤에, set_order str get_order . 는 앞에 둔다. 홀로 쓴 get_order 는 순서를 보인다. 파일을 검사할 때 알리므로, 그 줄은 파일이 찍는 어떤 것보다 먼저 나온다.

10-order-add.pnx

set_order io .
set_order get_order str .
get_order
"pinax" lower println

출력

$ pnx 10-order-add.pnx
order: (io, str)
pinax

문답

물음. 왜 io str set_order 가 아니고 set_order io str . 인가?

답. 프로시저가 실행 때 받는 것은 그 앞, 스택에 온다: 2 3 add. 프로시저가 컴파일될 때 읽는 것은 그 뒤에 온다: def 의 서명, to 의 이름, set_order 의 모듈(마침표로 끝난다). 모듈은 값이 아니므로 그 목록이 스택에 있을 수 없다.

10.4 자료 파일#

호스트는 소스를 자료 적재로 읽을 수 있다. 자료 적재는 선언과 값만 받고, 프로시저 정의와 부르기, 제어를 모두 거절한다. 그래서 믿지 못하는 설정 파일을 읽어도 그 파일이 코드를 돌릴 수 없다.

10-data.c

#include "pinax.h"
#include <stdio.h>
#include <string.h>

/* A settings file the host reads as data: declarations and values, no code. */
static const char settings[] =
    "global port int\n"
    "global name str 16\n"
    "8080 set port\n"
    "\"edge\" set name\n";
static const char hostile[] = "def boom do end\n";

int main(void) {
    static unsigned char block[1 << 20];
    pinax_config config = {.struct_size = sizeof config};
    pinax_state *st;
    if (pinax_open((pinax_mem){block, sizeof block}, &config, &st) != PINAX_OK)
        return 1;
    if (pinax_load(st, "settings", (pinax_str){(const unsigned char *)settings, strlen(settings)}, PINAX_LOAD_DATA) != PINAX_OK)
        return 1;
    pinax_global g;
    pinax_global_find(st, "port", &g);
    printf("port: %lld\n", (long long)*(const int64_t *)g.ptr);
    if (pinax_load(st, "hostile", (pinax_str){(const unsigned char *)hostile, strlen(hostile)}, PINAX_LOAD_DATA) != PINAX_OK) {
        pinax_str why = pinax_error_text(st);
        printf("refused: %.*s\n", (int)why.len, (const char *)why.ptr);
    }
    pinax_close(st);
    return 0;
}

출력

$ ./10-data
port: 8080
refused: a data source defines no procedures and uses no modules

pnx 는 자료 적재를 하지 않는다. 자료 적재는 호스트의 일이다(14장).

10.5 호스트가 빌려주는 모듈#

io file clock random env 는 표준 모듈이 아니라 호스트 모듈이다: 언어에 들어 있지 않고, 호스트가 등록할 때만 있다(14장). pnx 는 다섯을 모두 등록한다. 그래서 파일과 시계와 환경에 닿는 길은 호스트가 정한다 — 믿지 못하는 스크립트에는 file 을 주지 않으면 된다.

10-host-modules.pnx

rem run: args alpha beta
use io .
use str .
use env .
use random .
use clock .
def demo do
  args "arguments: " env.arg_count . cat io.println             rem 0 is the program file
  1 env.arg or_else to e "?" end io.println
  "PINAX_NO_SUCH_VARIABLE" env.getenv or_else to e args "getenv failed: " e err_text . cat end io.println
  7 random.seed                                             rem the same seed, the same numbers
  args 10 random.random_below " " 10 random.random_below " " 10 random.random_below . cat io.println
  clock.monotonic_ns to a
  clock.monotonic_ns to b
  args "the clock does not go back: " b a lt not . cat io.println
end
demo

출력

$ pnx 10-host-modules.pnx
arguments: 1
?
getenv failed: not_found
7 2 8
the clock does not go back: true

env.arg_count 와 env.arg 는 명령줄의 인자이고(0 번은 프로그램 파일), env.getenv 는 환경 변수다. random.seed 뒤의 random.random_below 는 같은 씨앗에 같은 수열을 내므로 시험에서 쓰기 좋다. clock.monotonic_ns 는 거꾸로 가지 않는 시계라 걸린 시간을 재는 데 쓰고, clock.now_ms 는 달력의 시각이며, clock.sleep 은 밀리초만큼 멈춘다. random.random 은 범위 없는 64 비트 난수다(암호에 쓰는 것이 아니다).

토큰그 뒤의 스택일어난 일
11몇 번째 인자인지.
env.arg"alpha"그 인자. 없는 번호면 실패한다.
or_else to e "?" end"alpha"성공이라 건너뛴다. 실패였다면 "?" 가 그 자리에 온다.
io.println—찍는다.

문답

물음. 모듈 파일 안에서 io.println 을 써도 되는가?

답. 모듈도 use io . 를 적으면 된다. 다만 모듈을 적재하는 호스트가 io 를 등록하지 않았으면 그 모듈은 거절된다. 널리 쓰일 모듈은 호스트 모듈에 기대지 않고 결과를 돌려주는 편이 낫다.

10.6 모듈로 쓴 맵#

글 키로 값을 찾는 표는 7장의 풀과 찾아보기(index)로 만든다. 그것이 기본이다. 다만 풀과 찾아보기는 프로시저의 매개변수가 될 수 없다(표준 9.9). 그래서 같은 일을 맵 여럿에 하려면 맵마다 프로시저를 다시 써야 한다. 배열은 매개변수가 되므로, 레코드의 배열 위에 맵을 모듈로 쓰면 프로시저 한 벌로 맵 여럿을 다룬다. 아래 kvmap 이 그런 모듈의 예다. 언어에 들어 있지 않으니 프로그램 옆에 복사해 두고 쓴다.

kvmap.pnx

rem kvmap: a map from text (up to 24 bytes) to int over an array of records the program declares (array m entry N)
rem and passes to every procedure. The start slot is the FNV-1a hash of the key modulo N, probing is linear, and a
rem deleted slot is a tombstone that a later store takes again. Keep N well above the number of keys.
use hash .
use str .

export const key_room 24
const empty 0
const live 1
const gone 2

export record entry
  key str key_room
  value int
  state int
end

def start m array entry, k str gives int do k hash.fnv1a raw m capacity u_mod end

rem the slot of k, or -1
def slot_of m array entry, k str gives int do
  m k start to i
  0 to tries
  loop
    tries m capacity lt not if break . end
    i m idx to r
    r entry.state empty eq if -1 return end
    r entry.state live eq if r entry.key k eq if i return end end
    i 1 add m capacity mod to i
    tries 1 add to tries
  end
  -1
end

rem k takes the value v: err.range when k is longer than key_room, err.full when every slot is live
export def store m array entry, k str, v int or fail do
  k str.len key_room gt if err.range fail end
  m k slot_of to at
  at 0 ge if v at m idx to entry.value return end
  m k start to i
  0 to tries
  loop
    tries m capacity lt not if break . end
    i m idx to r
    r entry.state live eq not if
      k r to entry.key  v r to entry.value  live r to entry.state
      return
    end
    i 1 add m capacity mod to i
    tries 1 add to tries
  end
  err.full fail
end

rem the value of k: err.not_found when it is not there
export def fetch m array entry, k str gives int or fail do
  m k slot_of to at
  at 0 lt if err.not_found fail end
  at m idx entry.value
end

export def holds m array entry, k str gives bool do m k slot_of 0 ge end

rem k is taken out; false when it was not there
export def forget m array entry, k str gives bool do
  m k slot_of to at
  at 0 lt if false return end
  at m idx to r
  gone r to entry.state  "" r to entry.key
  true
end

export def size m array entry gives int do
  0 to n
  m do to r r entry.state live eq if n 1 add to n end end each
  n
end

export def wipe m array entry do
  m do to r empty r to entry.state  "" r to entry.key end each
end

rem the numbers of the live slots put in l, for walking or for sort_by: err.full when l has too little room
export def live_slots m array entry, l list int or fail do
  0 l truncate
  0 m capacity range do to i
    i m idx entry.state live eq if i l push or_fail end
  end each
end

10-kvmap.pnx

use io .
use str .
use kvmap .
array fruit entry 16                       rem two maps of one entry: the same procedures serve both
array veg entry 16
list order int 16
def count_into m array entry, line str do
  line str.words do to w
    m w kvmap.fetch or_else to e 0 end 1 add to c        rem a missing key counts from 0
    m w c kvmap.store or_else to e args "no room for " w . cat io.println end
  end each
end
def show title str, m array entry do
  m order kvmap.live_slots or_else to e return end
  order m sort_by_desc entry.value
  title io.print
  order do to i i m idx to r args " " r entry.key "=" r entry.value . cat io.print end each
  "" io.println
end
fruit "pear fig pear plum pear fig" count_into
veg "leek kale leek" count_into
"fruit:" fruit show
"veg:" veg show
args "fig " fruit "fig" kvmap.holds ", gone " fruit "fig" kvmap.forget ", now " fruit "fig" kvmap.holds . cat io.println

출력

$ pnx 10-kvmap.pnx
fruit: pear=3 fig=2 plum=1
veg: leek=2 kale=1
fig true, gone true, now false

프로그램이 array 이름 entry N 으로 맵을 선언하고, 모든 프로시저에 그 이름을 넘긴다. store 는 키에 값을 주고, fetch 는 값을 찾는다(없으면 not_found 로 실패). holds 는 키가 있는지 묻고, forget 은 키를 지우고, size 는 키의 수를 주고, wipe 는 모두 지운다. live_slots 는 살아 있는 칸의 번호를 목록에 넣는다. 그 목록을 sort_by 로 정렬하면 키나 값의 차례로 걷는다.

kvmap풀과 찾아보기
프로시저에 넘기기된다. 맵이 배열이다안 된다
맵 여럿프로시저 한 벌맵마다 프로시저를 다시 쓴다
키와 값24 바이트까지의 글과 int 하나아무 레코드
빠르기두 배쯤 걸린다(키 5만 개로 잰 것)핵의 해시 표
자리키보다 넉넉히 둔다. 찰수록 느려진다키의 수만큼

문답

물음. 이름이 왜 put 과 get 이 아닌가?

답. put, get, has, count, clear, remove, lookup, drop 은 언어의 프로시저다. Pinax 로 쓴 모듈은 그 이름을 새로 정의할 수 없다(표준 9.5). 그래서 store, fetch, holds, forget 을 썼다.

흔한 오해: kvmap 은 표준 모듈이다

아니다. 이 매뉴얼의 예제 파일이다. 프로그램 옆에 kvmap.pnx 로 두어야 use kvmap . 이 찾는다. 키의 길이나 값의 타입이 다르면 복사본을 고쳐 쓴다. 맵을 넘길 일이 없으면 풀과 찾아보기를 쓴다.

정리

  • 파일 하나가 모듈이고, export 한 것만 밖에서 보인다(표준 13.1, 13.2).
  • use 모듈 [as 별명] . 뒤에 모듈.이름 으로 쓴다(13.1).
  • 프로시저, 상수, 전역은 경로로, 타입과 레코드는 이름만으로 쓴다. 내보낸 전역에는 set 모듈.이름 으로 넣는다(13.2).
  • 선언한 타입은 같은 타입끼리만 더하고 뺀다(7.4).
  • 자료 적재는 선언과 값만 받는다(13.4).
  • 풀과 찾아보기는 매개변수가 될 수 없다. 맵을 프로시저에 넘기려면 배열 위에 쓴 모듈(kvmap)을 쓴다(9.9).
