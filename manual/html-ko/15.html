14 C 프로그램에 끼워 쓰기

먼저 알아야 할 것: 1장부터 13장까지의 언어. C 를 안다고 본다.

이 장이 답하는 물음

  • C 프로그램은 Pinax 를 어떻게 열고, 스크립트를 어떻게 부르는가?
  • 스크립트가 할 수 있는 바깥일은 누가 정하는가?
  • 믿지 못하는 스크립트는 어떻게 돌리는가?

14.1 열고, 등록하고, 적재하고, 부른다#

호스트의 일은 넷이다.

  1. 메모리 한 덩이를 주고 pinax_open 으로 상태를 연다. 상태의 모든 것이 그 덩이 안에 있다.
  2. 스크립트가 쓸 호스트 프로시저을 pinax_register 로 등록한다. 서명은 Pinax 의 서명 그대로 적는다.
  3. 스크립트를 pinax_load 로 적재한다. 거절하면 까닭이 pinax_error_text 에 있다.
  4. pinax_find 로 프로시저를 서명과 함께 찾고 pinax_run 으로 부른다.

14-host.c

/* A host that lets users write pricing rules in Pinax. The host gives one word (the stock
   level), loads the user's rules, and asks them for a price; a broken rule never takes the
   host down. */
#include "pinax.h"
#include <stdio.h>
#include <string.h>

static int64_t stock[3] = {120, 4, 0};

static pinax_err stock_of(pinax_call *call, void *user, const pinax_args *args) {
    (void)call; (void)user;
    if (args->i[0] < 0 || args->i[0] >= 3)
        return PINAX_ERR_NOT_FOUND;                  /* (item int gives n int or fail) */
    args->ri[0] = stock[args->i[0]];
    return PINAX_OK;
}

static void report(pinax_state *st, const char *what, pinax_err err) {
    pinax_str why = pinax_error_text(st);
    printf("%s: error %#x, %.*s\n", what, (unsigned)err, (int)why.len, (const char *)why.ptr);
}

int main(void) {
    static unsigned char block[256 * 1024]; /* the state takes about 150 KB, a load its working memory */
    pinax_config config = {.struct_size = sizeof config, .region_bytes = 4096, .budget = 10000};
    pinax_state *st;
    pinax_err err = pinax_open((pinax_mem){block, sizeof block}, &config, &st);
    if (err != PINAX_OK) {
        printf("block too small: %zu bytes needed\n", pinax_needed(st));
        return 1;
    }
    static const pinax_word_def words[] = {{"stock_of", "(item int gives n int or fail)", stock_of, NULL, 0}};
    pinax_register(st, "shop", words, 1);

    /* the user's rules: scarce items cost more */
    static const char rules[] =
        "use shop .\n"
        "export def price item int, base int gives p int do\n"
        "  item shop.stock_of or_else to e 0 end to left\n"
        "  left 0 eq if 0 return end\n"
        "  left 10 lt if base 3 mul 2 div else base end\n"
        "end\n";
    err = pinax_load(st, "rules", (pinax_str){(const unsigned char *)rules, strlen(rules)}, PINAX_LOAD_CODE);
    if (err != PINAX_OK) {
        report(st, "rules refused", err);
        return 1;
    }
    pinax_word price;
    if (pinax_find(st, "price", "(item int, base int gives p int)", 0, &price) != PINAX_OK) {
        report(st, "no price word", PINAX_ERR_NOT_FOUND);
        return 1;
    }
    for (int64_t item = 0; item < 4; ++item) {
        int64_t in[2] = {item, 1000}, out = 0;
        pinax_args args = {.i = in, .ri = &out};
        err = pinax_run(st, price, &args);
        for (int slices = 1; err == PINAX_SUSPENDED && slices < 100; ++slices)   /* the budget bounds a slice; the host bounds the run */
            err = pinax_resume(st, &args);
        if (err != PINAX_OK)
            report(st, "price failed", err);
        else
            printf("item %lld: %lld\n", (long long)item, (long long)out);
    }

    /* a second set of rules with a mistake is refused; the first stays loaded */
    static const char broken[] = "def discount p int gives int do p \"10\" sub end\n";
    err = pinax_load(st, "broken", (pinax_str){(const unsigned char *)broken, strlen(broken)}, PINAX_LOAD_CODE);
    if (err != PINAX_OK)
        report(st, "broken rules refused", err);
    pinax_close(st);
    return 0;
}

문답

물음. 덩이는 얼마나 커야 하는가?

답. 여는 데 기본값으로 약 150 KB 가 든다. 대부분이 주 실행의 구역(64 KB)과 정수 뱅크(32 KB)이므로 config.region_bytes 와 config.int_slots 로 줄일 수 있다. 적재하는 동안은 덩이의 남은 부분이 컴파일러의 작업 메모리다: 작은 소스에 약 20 KB, 프로시저 하나에 약 1 KB 씩, 상수 패턴이 하나라도 있으면 64 KB 가 더 든다. 적재가 끝나면 프로그램만 남고 작업 메모리는 다시 빈다. 예제의 256 KB 는 짧은 스크립트에 넉넉하고, 긴 스크립트는 PINAX_ERR_NO_ROOM 을 받으면 pinax_needed 가 말하는 크기 이상으로 다시 연다. 그 크기는 하한이라 한 번 더 모자랄 수 있다.

문답

물음. 스크립트가 실제 입력에서 무엇을 필요로 하는지 어떻게 아는가?

답. 돌려 보고 묻는다. pinax_stats_get 은 실행 뒤에 뱅크의 슬롯, 구역, 핸들, 호출 깊이의 최고 사용량과 명령 수, 쓴 덩이의 바이트를 준다. 명령줄에서는 pnx --stats script.pnx 가 같은 것을 표준 오류에 한 줄로 쓴다. 가장 큰 입력의 최고 사용량에 고른 여유를 더해 config 와 덩이의 크기를 정한다. 더 필요한 실행은 모자란 것의 답(PINAX_ERR_NO_ROOM, PINAX_ERR_FULL, 또는 결함)으로 실패하고, 끝나지 않는 스크립트는 호스트가 멈춘다: 예산은 한 조각을 막을 뿐 실행 전체를 막지 않는다(위의 예제는 100 조각까지 허용한다). ./nob contract 가 이 약속들을 자기 컴파일러와 플랫폼에서 확인한다.

인자와 결과는 타입별 배열로 오간다: 정수는 args->i[] 와 args->ri[], 문자열은 args->s[] 와 args->rs[]. 호스트 프로시저가 PINAX_OK 가 아닌 값을 돌려주면, 서명에 or fail 이 있는 프로시저는 실패하고(스크립트가 or_else 로 받는다), 없는 프로시저는 결함이 된다.

문답

물음. 스크립트가 파일을 지우거나 네트워크에 닿을 수 있는가?

답. 호스트가 그런 프로시저를 등록하지 않았다면 없다. 표준 모듈은 바깥에 닿지 않고, 바깥일은 모두 호스트 프로시저이다. extern 으로 C 함수를 부르는 것도 호스트의 해결 함수가 허락한 함수뿐이다.

14.2 믿지 못하는 스크립트#

config.budget 은 한 번에 도는 명령의 수다. 예산이 다하면 실행이 멈춰 PINAX_SUSPENDED 로 돌아오고, 호스트가 pinax_resume 으로 잇거나 그만둔다. 멈춘 실행이 있는 동안 상태는 다른 실행을 받지 않는다. 그만둘 때는 pinax_abort 를 부른다. 결함으로 끝난 것처럼 그 실행이 연 핸들을 닫고 실행을 버린다. 스크립트가 그때까지 전역에 넣은 값은 남는다.

14-guard.c

/* Running code you do not trust. A budget stops a script that never ends. While a run is
   suspended the state takes no other run; pinax_abort gives the run up, and the state goes on
   with what the script had stored. */
#include "pinax.h"
#include <stdio.h>
#include <string.h>

static unsigned char block[256 * 1024]; /* the state takes about 150 KB, a load its working memory */

int main(void) {
    pinax_config config = {.struct_size = sizeof config, .budget = 50000};
    pinax_state *st;
    if (pinax_open((pinax_mem){block, sizeof block}, &config, &st) != PINAX_OK)
        return 1;
    static const char source[] =
        "global calls int\n"
        "def spin gives int do calls 1 add set calls  0 to n loop n 1 add to n end end\n"
        "def quick gives int do calls 1 add set calls  6 7 mul end\n"
        "def count_calls gives int do calls end\n";
    if (pinax_load(st, "main", (pinax_str){(const unsigned char *)source, strlen(source)}, PINAX_LOAD_CODE) != PINAX_OK)
        return 1;

    pinax_word w;
    int64_t r = 0;
    pinax_args args = {.ri = &r};
    pinax_find(st, "spin", "(gives int)", 0, &w);
    pinax_err err = pinax_run(st, w, &args);
    int slices = 0;
    while (err == PINAX_SUSPENDED && slices < 5) {     /* the host decides how long to wait */
        ++slices;
        err = pinax_resume(st, &args);
    }
    printf("spin after %d slices: %s\n", slices, err == PINAX_SUSPENDED ? "still running" : "ended");
    pinax_find(st, "quick", "(gives int)", 0, &w);
    printf("another run not if break . end it is suspended: %s\n", pinax_run(st, w, &args) == PINAX_ERR_STATE ? "PINAX_ERR_STATE" : "?");

    pinax_abort(st);                                    /* give the spinning run up */
    err = pinax_run(st, w, &args);
    printf("after pinax_abort, quick: %lld\n", (long long)r);
    pinax_find(st, "count_calls", "(gives int)", 0, &w);
    pinax_run(st, w, &args);
    printf("calls stored so far: %lld\n", (long long)r);
    pinax_close(st);
    return 0;
}

출력

$ ./14-guard
spin after 5 slices: still running
another run not if break . end it is suspended: PINAX_ERR_STATE
after pinax_abort, quick: 42
calls stored so far: 2

처리기가 지키는 것은 이렇다. 어떤 소스든 — 틀렸든, 일부러 나쁘게 쓴 것이든 — 그리고 pinax_load_bytecode 의 검사를 통과한 바이트코드든, 스크립트는 상태의 덩이와 호스트가 준 메모리 밖을 읽거나 쓰지 못한다. 예산이 0 이 아니면 실행 한 번은 언제나 정해진 명령 수 안에 돌아온다. 틀린 스크립트는 적재 때 거절되거나 결함으로 멈출 뿐, 호스트를 무너뜨리지 않는다. 다만 상(image), 공유 파일, pinax_bind 로 묶은 메모리의 바이트는 호스트가 믿고 주는 자료다. 처리기는 그 모양만 검사한다.

흔한 오해: 멈춘 실행은 새 pinax_run 이 덮어쓴다

덮어쓰지 않는다. 새 실행은 PINAX_ERR_STATE 로 거절된다. 멈춘 실행을 끝까지 잇거나 pinax_abort 로 버린다. 전역까지 실행 앞으로 되돌려야 한다면 실행 앞에 상을 저장해 두고 그 상에서 다시 연다(표준 19.9).

14.3 여러 스레드에서#

상태 하나는 한 번에 한 스레드에서만 돈다. 코어를 여럿 쓰려면 상태를 여럿 연다. 호스트 라이브러리의 호스트 루프 (pinax_loop.h)가 상태들을 정한 수의 스레드에서 돌리고, 채널이 상태 사이로 메시지를 나른다. 루프는 상태처럼 설정으로 연다: 스레드의 수, 한 번에 쥐는 상태의 수, 그리고 루프와 채널이 사는 메모리 블록 하나. 크기는 함수 둘이 알려 준다. 블록이 없으면 그 크기의 조각 하나를 힙에서 받는다. 호스트는 pinax_loop_start 로 상태와 프로시저를 루프에 넘기고, 끝나면 넘길 때 준 함수로 듣는다. 채널은 호스트가 이름을 지어 모듈로 등록한다. 스크립트는 use orders 뒤에 orders.send, orders.receive, orders.close 를 쓴다. 차 있는 채널에 넣거나 빈 채널에서 꺼내는 작업은 기다리고, 그동안 스레드는 다른 상태를 돌린다.

14-threads.c

/* Two states on two threads. The shop packs each order into bytes and sends it through the
   channel `orders`; the clerk unpacks and prints them. Nothing is shared but the messages. */
#include "pinax.h"
#include "pinax_host.h"
#include "pinax_loop.h"
#include <stdio.h>
#include <string.h>

static const char shop[] =
    "use orders .\nuse bytes .\n"
    "record order\n  item str 8\n  qty int\nend\n"
    "array rows order 1\n"
    "buffer wire 32\n"
    "def send_order name str, q int do\n"
    "  0 rows idx to r\n"
    "  name r to order.item  q r to order.qty\n"
    "  wire clear\n"
    "  r wire bytes.pack or_else to e end\n"
    "  wire contents orders.send or_else to e end\n"
    "end\n"
    "def open_shop n int gives r int do\n"
    "  \"apple\" 3 send_order  \"pear\" 1 send_order  \"plum\" 12 send_order\n"
    "  orders.close\n"
    "  3\n"
    "end\n";

static const char clerk[] =
    "use orders .\nuse bytes .\nuse io .\nuse str .\n"
    "record order\n  item str 8\n  qty int\nend\n"
    "array rows order 1\n"
    "def serve n int gives r int do\n"
    "  0 to served\n"
    "  0 rows idx to r\n"
    "  loop\n"
    "    orders.receive or_else to e \"\" end to m\n"
    "    m str.is_empty if break . end\n"
    "    m r bytes.unpack or_else to e \"\" end drop\n"
    "    args r order.item \" x\" r order.qty . cat io.println\n"
    "    served 1 add to served\n"
    "  end\n"
    "  served\n"
    "end\n";

typedef struct side {
    unsigned char block[1 << 20];
    pinax_state *state;
    pinax_word word;
    int64_t in, out;
    pinax_args args;
} side;
static side shop_side, clerk_side;

static void done(void *user, pinax_state *state, pinax_err outcome) {
    (void)user; (void)state;
    if (outcome != PINAX_OK)
        printf("a run ended with %#x\n", (unsigned)outcome);
}

static int prepare(side *s, pinax_channel *orders, const char *source, const char *word) {
    pinax_config config = {.struct_size = sizeof config, .budget = 10000};
    if (pinax_open((pinax_mem){s->block, sizeof s->block}, &config, &s->state) != PINAX_OK ||
        pinax_channel_register(s->state, orders) != PINAX_OK || pinax_host_register(s->state, "io") != PINAX_OK ||
        pinax_load(s->state, "main", (pinax_str){(const unsigned char *)source, strlen(source)}, PINAX_LOAD_CODE) ||
        pinax_find(s->state, word, "(n int gives r int)", 0, &s->word) != PINAX_OK)
        return 1;
    s->args = (pinax_args){.i = &s->in, .ri = &s->out};
    return 0;
}

int main(void) {
    pinax_loop_config loop_config = {.struct_size = sizeof loop_config, .threads = 2};
    pinax_loop *loop;
    pinax_channel *orders;
    if (pinax_loop_open(&loop_config, &loop) != PINAX_OK || pinax_channel_open(loop, "orders", 2, 32, &orders) != PINAX_OK ||
        prepare(&shop_side, orders, shop, "open_shop") || prepare(&clerk_side, orders, clerk, "serve"))
        return 1;
    pinax_loop_start(loop, clerk_side.state, clerk_side.word, &clerk_side.args, done, NULL);
    pinax_loop_start(loop, shop_side.state, shop_side.word, &shop_side.args, done, NULL);
    pinax_loop_wait(loop);
    printf("sent %lld, served %lld\n", (long long)shop_side.out, (long long)clerk_side.out);
    pinax_loop_close(loop);
    pinax_close(shop_side.state);
    pinax_close(clerk_side.state);
    return 0;
}

출력

$ ./14-threads
apple x3
pear x1
plum x12
sent 3, served 3

메시지는 바이트다. 레코드의 줄은 bytes.pack 으로 싸서 보내고 받는 쪽이 bytes.unpack 으로 푼다(11장). 그래서 두 쪽이 같은 레코드를 선언한다. 닫힌 채널이 비면 receive 가 not_found 로 실패하므로, 받는 쪽은 그 실패를 끝으로 읽는다.

문답

물음. 두 상태가 같은 전역을 함께 쓸 수 있는가?

답. 고치는 전역은 안 된다. 같은 값을 여러 상태가 고치면 경합을 적재 때 잡을 수 없기 때문이다. 고친 것은 채널의 메시지로 건넨다. 기다릴 상대가 없는데 모두 채널을 기다리면 루프가 그 실행들을 PINAX_ERR_DEADLOCK 으로 끝낸다(표준 17.4).

읽기만 하는 큰 자료(사전, 요율표, 프로시저 목록과 그 찾아보기)는 상태마다 싣지 않고 한 벌을 함께 읽는다. 한 상태가 자료를 싣고, 읽는 상태들은 같은 선언 앞에 shared 를 붙인다. 호스트가 pinax_share 로 자료 상태의 저장소를 빌려 주면 복사 없이 같은 바이트를 읽는다. 공유 전역을 바꾸는 코드는 적재 때 거절되고, 저장소를 빌려준 상태는 그 뒤로 돌지도 적재하지도 않는다. 바이트가 바뀌지 않으니 여러 스레드가 잠금 없이 함께 읽는다.

14-shared.c

/* A word list loaded once and read by two states on two threads at the same time. The states
   declare it `shared`; the host lends them the dictionary state's storage. */
#include "pinax.h"
#include "pinax_loop.h"
#include <stdio.h>
#include <string.h>

static const char dictionary[] =
    "record pair\n  term str 12\n  meaning str 12\nend\n"
    "list pairs pair 64\n"
    "index by_term pairs pair.term\n"
    "row pairs \"sagwa\" \"apple\" .\n"
    "row pairs \"bae\" \"pear\" .\n"
    "row pairs \"podo\" \"grape\" .\n";

static const char translator[] =
    "use str .\n"
    "record pair\n  term str 12\n  meaning str 12\nend\n"
    "shared list pairs pair 64\n"
    "shared index by_term pairs pair.term\n"
    "def known w str gives int do w by_term lookup or_else to e 0 return end drop 1 end\n"
    "def count_known n int gives r int do\n"
    "  n 0 eq if \"sagwa\" known \"kiwi\" known add return end\n"
    "  \"bae\" known \"podo\" known add \"sagwa\" known add\n"
    "end\n";

typedef struct worker {
    unsigned char block[1 << 20];
    pinax_state *state;
    pinax_word word;
    int64_t in, out;
    pinax_args args;
} worker;
static unsigned char dict_block[1 << 20];
static worker w[2];

static void done(void *user, pinax_state *state, pinax_err outcome) {
    (void)user; (void)state;
    if (outcome != PINAX_OK)
        printf("a run ended with %#x\n", (unsigned)outcome);
}

int main(void) {
    pinax_config config = {.struct_size = sizeof config, .budget = 10000};
    pinax_state *dict;
    if (pinax_open((pinax_mem){dict_block, sizeof dict_block}, &config, &dict) != PINAX_OK ||
        pinax_load(dict, "dictionary", (pinax_str){(const unsigned char *)dictionary, strlen(dictionary)},
                   PINAX_LOAD_DATA) != PINAX_OK)
        return 1;
    pinax_loop_config loop_config = {.struct_size = sizeof loop_config, .threads = 2};
    pinax_loop *loop;
    if (pinax_loop_open(&loop_config, &loop) != PINAX_OK)
        return 1;
    for (int k = 0; k < 2; ++k) {
        if (pinax_open((pinax_mem){w[k].block, sizeof w[k].block}, &config, &w[k].state) != PINAX_OK ||
            pinax_load(w[k].state, "main", (pinax_str){(const unsigned char *)translator, strlen(translator)},
                       PINAX_LOAD_CODE) != PINAX_OK ||
            pinax_share(w[k].state, "pairs", dict, "pairs") != PINAX_OK ||     /* the table first */
            pinax_share(w[k].state, "by_term", dict, "by_term") != PINAX_OK || /* then its index */
            pinax_find(w[k].state, "count_known", "(n int gives r int)", 0, &w[k].word) != PINAX_OK)
            return 1;
        w[k].in = k;
        w[k].args = (pinax_args){.i = &w[k].in, .ri = &w[k].out};
        pinax_loop_start(loop, w[k].state, w[k].word, &w[k].args, done, NULL);
    }
    pinax_loop_wait(loop);
    printf("first knows %lld of 2, second knows %lld of 3\n", (long long)w[0].out, (long long)w[1].out);
    pinax_loop_close(loop);
    for (int k = 0; k < 2; ++k)
        pinax_close(w[k].state);
    pinax_close(dict); /* last: the others read its storage */
    return 0;
}

14.4 요청을 많이 받을 때#

서버는 요청을 한꺼번에 많이 받고, 요청의 시간은 대부분 기다리는 데 든다. 데이터베이스, 파일, 다른 서버를 기다린다. C 함수 안에서 기다리는 호스트 프로시저는 스레드와 상태 전체를 붙잡는다. 그래서 기다리는 호스트 프로시저는 PINAX_WORD_AWAITABLE 로 등록한다. 그 프로시저는 pinax_call_pending 으로 표를 받아 두고, 일을 시작하고, PINAX_PENDING 을 돌려준다. 부른 작업은 기다리고, 상태의 다른 작업은 계속 돈다. 더 돌 작업이 없으면 pinax_run 이나 pinax_resume 이 PINAX_WAITING 을 돌려준다. 호스트의 이벤트 루프가 pinax_complete 로 일을 끝내고 pinax_resume 을 다시 부른다.

요청 하나는 자기 작업 하나가 맡는다(13장). spawn 의 블록은 지역 변수를 보지 못하므로, 요청의 번호는 큐로 작업에 건넨다. 작업은 요청과 함께 끝나고, 작업이 구역에 만든 바이트도 함께 사라진다. 그룹의 작업이 모두 차 있으면 spawn 이 full 로 실패하고, 스크립트는 바로 «바쁨» 으로 답한다. 한 상태가 한 번에 몇 요청을 받는지는 호스트가 아는 것이므로, 스크립트는 그 수를 host 로 쓰고(tasks requests host) 호스트가 적재 전에 pinax_capacity(state,
"requests", 64) 로 준다(표준 8 (4a), 19.4 (1d)). pnx 에서는 --capacity requests=64 로 준다(표준 20 (3a)).

14-requests.c

#include "pinax.h"
#include <stdio.h>

/* Requests as tasks. web.next gives the id of the next request (-1: no more). Each request is
 * served by a task of its own, which asks the host for a page with web.fetch. fetch waits: it
 * keeps a token and returns PINAX_PENDING, so the other tasks go on. The host answers the first
 * fetch, and gives up on the second as a timeout would: a failure, which the task takes. The
 * third request faults (the array `served` was sized for ids 0 to 2), and only its task ends: the
 * group is `apart`, the task named itself with its id, and the host is told and answers it. */
static const int64_t arriving[] = {1, 2, 3, -1};
static int next_at;
static pinax_err web_next(pinax_call *call, void *user, const pinax_args *args) {
    (void)call; (void)user;
    args->ri[0] = arriving[next_at < 3 ? next_at++ : 3];
    return PINAX_OK;
}

static pinax_token fetching[3];
static int n_fetching;
static pinax_err web_fetch(pinax_call *call, void *user, const pinax_args *args) {
    (void)user; (void)args;
    fetching[n_fetching++] = pinax_call_pending(call);
    return PINAX_PENDING;
}

static pinax_err web_reply(pinax_call *call, void *user, const pinax_args *args) {
    (void)call; (void)user;
    printf("request %lld: %.*s\n", (long long)args->i[0], (int)args->s[0].len, (const char *)args->s[0].ptr);
    return PINAX_OK;
}

static void faulted(void *user, const pinax_state *state, const pinax_task_fault *fault) {
    (void)user; (void)state;
    printf("request %lld: 500 (%.*s)\n", (long long)fault->tag, (int)fault->where.len, (const char *)fault->where.ptr);
}

int main(void) {
    static unsigned char block[1 << 19];
    pinax_config config = {.struct_size = sizeof config, .budget = 100000};
    pinax_state *st;
    if (pinax_open((pinax_mem){block, sizeof block}, &config, &st) != PINAX_OK)
        return 1;
    static const pinax_word_def words[] = {
        {"next", "(gives id int)", web_next, NULL, 0},
        {"fetch", "(id int gives page str or fail)", web_fetch, NULL, PINAX_WORD_AWAITABLE},
        {"reply", "(id int, body str)", web_reply, NULL, 0},
    };
    pinax_register(st, "web", words, 3);
    pinax_on_task_fault(st, faulted, NULL);
    static const char source[] =
        "use web .\n"
        "tasks requests 4 apart\n"
        "queue incoming int 4\n"
        "array served int 3\n"
        "def serve do\n"
        "  incoming take or_return to id\n"
        "  id task_tag\n"
        "  id web.fetch or_else to e args \"gave up: \" e err_text . cat end to page\n"
        "  id served idx 1 add  id set served\n"
        "  id page web.reply\n"
        "end\n"
        "def start id int do\n"
        "  ref serve requests spawn or_else to e id \"busy\" web.reply return end drop\n"
        "  id incoming put or_else to e end\n"
        "end\n"
        "def main do\n"
        "  loop web.next to id  id 0 lt if break . end  id start end\n"
        "  requests run_all\n"
        "end\n";
    if (pinax_load(st, "main", (pinax_str){(const unsigned char *)source, sizeof source - 1}, PINAX_LOAD_CODE) != PINAX_OK) {
        pinax_str why = pinax_error_text(st);
        fprintf(stderr, "%.*s\n", (int)why.len, (const char *)why.ptr);
        return 1;
    }
    pinax_word w;
    pinax_find(st, "main", "()", 0, &w);
    pinax_err err = pinax_run(st, w, &(pinax_args){0});
    printf("%s: %d requests wait for the host\n", err == PINAX_WAITING ? "PINAX_WAITING" : "?", n_fetching);

    pinax_str page = {(const unsigned char *)"page one", 8};
    pinax_complete(st, fetching[0], PINAX_OK, &(pinax_args){.rs = &page}); /* the first fetch came back */
    pinax_complete(st, fetching[1], PINAX_ERR_CANCELLED, NULL);             /* the second took too long */
    pinax_complete(st, fetching[2], PINAX_OK, &(pinax_args){.rs = &page});
    err = pinax_resume(st, &(pinax_args){0});
    printf("%s\n", err == PINAX_OK ? "PINAX_OK" : "?");
    pinax_close(st);
    return 0;
}

요청 하나를 포기하려면(시간 초과, 떠난 손님) 호스트가 그 표를 실패로 완료한다. 여기서는 PINAX_ERR_CANCELLED 다. 기다리던 작업에서 프로시저가 실패하고, or_else 가 그 실패를 받으며, 다른 요청은 건드리지 않는다. pinax_abort 는 실행 전체를 끝내므로 상태의 요청이 모두 함께 끝난다.

요청 하나의 결함이 다른 요청을 끝내서는 안 된다. 요청 작업의 묶음을 apart 로 선언한다(13장). 그러면 결함 난 작업은 혼자 끝난다. 호스트는 그래도 그 요청에 답해야 하므로, 작업은 요청의 번호를 받자마자 그것으로 자기 이름을 정한다(id task_tag, 표준 14.5). 호스트가 pinax_on_task_fault 에 준 함수가 그런 결함마다 그 꼬리표와 함께 불린다. 여기서는 번호가 배열 served 를 넘는 세 번째 요청이다. 한 실행의 여러 결함은 하나씩 알린다(표준 19.10).

문답

물음. 기다리는 프로시저에 or fail 이 없으면?

답. 그러면 호스트의 실패는 결함이 될 수밖에 없고, 결함은 실행 전체를 끝낸다. 묶음이 apart 가 아니면 상태의 요청이 모두 끝난다. 호스트가 포기할 수 있는 프로시저는 위의 fetch 처럼 or fail 로 선언한다 (표준 19.8).

작업은 기다리거나 양보하는 자리에서만 차례를 넘긴다. 오래 계산하는 요청은 기다리거나 끝날 때까지 같은 상태의 다른 요청을 붙잡는다. 예산은 작업 하나가 아니라 상태 전체를 멈춘다. 오래 걸리는 일은 따로 연 상태에 맡기거나, 루프 안에서 yield 로 차례를 넘긴다. 너무 오래 도는 요청을 멈추려면 그 묶음에 차례 한도를 준다. tasks requests 64 32 8192 1000000
apart 의 네 번째 크기다. 양보하거나 기다리지 않고 그것을 넘긴 작업은 cancelled 로 결함을 내고 혼자 끝나며, 결함 콜백에서 답을 받는다(표준 14.6).

문답

물음. 요청마다 상태를 복제하면 안 되는가?

답. 된다. 그리고 요청끼리 떨어진다. 한 요청이 저장한 것을 다른 요청이 보지 않는다. 그러나 복제는 요청마다 상태 전체, 곧 고정 부분과 프로그램을 복사하고, 다시 닫아야 한다. 작업은 tasks 로 선언한 자기 구역과 프레임만 든다(표준 14 (2)). 한 상태의 작업들은 전역을 함께 보므로, 요청 하나에 속한 것은 그 지역 변수에 둔다. 복제하는 호스트는 pinax_clone_with(source, block, PINAX_CLONE_KEEP_HOSTS, &clone) 를 쓴다. 복제는 원본의 호스트 프로시저와 내보낸 코드를 지니고, 그것을 다시 받지 않고 돈다(표준 19.9 (2b)).

14.5 더 빠르게: 코드를 C 로#

프로그램이 정수 루프, 배열 일, 작은 프로시저를 많이 부르는 데 시간을 쓴다면, 그 코드를 호스트의 C 컴파일러로 컴파일할 수 있다. pnx export-c prog.pnx > prog_native.c 가 그것을 하나도 돌리지 않고 쓴다. 호스트는 그 파일을 자기 파일 옆에서 컴파일하고 (./nob dist 가 pinax.h 옆에 쓰는 pinax_native.h 를 포함한다), 같은 프로그램을 적재하기 전이나 뒤에 pinax_native_attach(state, &pnx_native) 를 부른다. 다른 것은 바뀌지 않는다. 결과, 결함, 예산, 기다림, 작업이 전과 같다(표준 19.11).

상태가 그 뒤에 적재하는 것, 곧 세션의 줄이나 나중에 적재한 모듈은 해석으로 돌고, 내보낸 부분은 그대로 내보낸 코드로 돈다. 뒤의 프로시저가 프로그램의 프로시저를 부르면 그 호출은 컴파일한 코드로 들어간다. 내보낸 프로그램의 프로시저를 redefine 할 때만 그것이 끝나고, 상태는 그때부터 모두 해석으로 돈다.

문답

물음. 얼마나 빨라지는가?

답. 정수 루프는 두 배에서 일곱 배 빠르다. 적재기가 울릴 수 없다고 증명한 검사는 빼기 때문이기도 하다. 라이브러리의 문자열 함수 안의 일과 호스트 호출은 거의 그대로다.

흔한 오해: 내보낸 코드는 상태가 더는 필요 없는 따로 된 프로그램이다

그렇지 않다. 해석기처럼 상태 위에서 돌고, 어떤 명령은 여전히 해석기가 대신 한다. 내보낸 Pinax 빌드와 같은 빌드로 컴파일한다. 다른 빌드는 해시가 달라 표를 결코 쓰지 않는다.

14.6 웹 페이지와 node 에서#

./nob wasm 은 핵을 웹어셈블리 모듈 build/wasm/pinax.wasm 으로 만들고, 그 곁에 JavaScript 모듈 pinax.mjs 를 둔다. 필요한 것은 clang 과 wasm-ld 뿐이다. C 라이브러리는 쓰지 않는다. pinax.mjs 의 createPinax(바이트, { write }) 가 모듈을 열고, 돌려준 객체의 run(소스, 이름) 이 소스를 새 상태에 적재해 정의 밖의 코드를 돌린다. 성공하면 { ok: true }, 아니면 { ok: false, error } 다. write(흐름, 글) 은 io.print 와 io.println 이 찍는 것을 흐름 1 로, io.eprint 와 적재 오류, 결함의 줄과 지역 변수를 흐름 2 로 받는다. 글의 꼴은 pnx 와 같다.

pinax.mjs 의 session() 은 pnx repl 과 같은 세션을 준다. 그 eval(글) 은 글을 세션의 한 줄로 돌리고 { ok, error, unfinished, stack } 을 돌려준다. stack 은 남은 값들이다. 정의나 블록 안에서 끝난 글은 unfinished 이고 아무것도 바꾸지 않는다: 더 붙여 다시 준다. reset() 은 세션을 처음부터 다시 시작하고, clear() 는 스택을 비운다. createPinax 가 준 객체의 blocks(글) 은 아무것도 돌리지 않는다. 글의 끝에서 아직 열린 정의와 블록을 바깥 것부터 알린다(["def sq", "loop", "if"]).

./nob wasm 은 build/dist/pinax-playground.html 도 쓴다. 모듈을 안에 담은 페이지 하나라서 서버 없이 디스크에서 바로 연다. 릴리스마다 이 페이지를 pinax-playground.html 로 함께 올리고, 같은 페이지가 https://rubidus-api.github.io/pinax_lang/playground/ 에도 있다. 페이지는 터미널이다. :help 와 터미널 옆의 안내판(F1)이 명령과 키를 알리고, 페이지에는 이 매뉴얼로 가는 링크가 있다.

코드가 도는 때

코드는 다 들어왔을 때 돈다. , 나 . 로 끝나거나, 연 블록의 end 로 끝날 때다.

  • use 이름 . 과 set_order … . 는 마침표로 끝난다. get_order 는 받는 것이 없어서 마침표 없이 치는 대로 돈다.
  • 루프나 블록은 end 가 들어올 때까지 기다렸다가 한꺼번에 한 번 돈다. 그동안 아래 상태줄이 몇 겹째 무엇 안에 있는지 보인다(depth 2: loop › if).
  • 블록이 열려 있지 않을 때 빈 줄은 모인 글을 돌린다. 마침표를 잊었을 때의 출구다.
  • 스택은 문장마다 보인다.
프로그램

결함 없이 돈 문장은 모두(def, use, 수, 프로시저 부르기 …) GW-BASIC 처럼 프로그램에 더해진다. 같은 이름을 다시 선언하면 그 줄들을 바꾼다. 거절되거나 결함이 난 문장은 더하지 않는다. 콜론으로 시작하는 명령도 더하지 않는다. 명령은 효과만 낸다. :clear 와 :stack 은 프로그램의 줄이 아니고, 문장 clear. 와 stack. 은 줄이 된다.

줄 맨 앞의 콜론은 명령 목록을 펼치고, 명령은 프로시저처럼 골라 쓴다. 프로그램을 보고 고치는 명령은 다음과 같다. :edit, :insert, :delete 로 줄을 바꾸면 그때마다 프로그램이 다시 돈다.

명령키하는 일
:listF4프로그램을 줄 번호와 함께 보인다. 중단점은 *, 멈춘 자리는 => 로 표시한다.
:runF5초기화다. 스택을 비우고 모든 정의를 잊은 뒤 프로그램을 1 번 줄부터 돌린다. 줄은 그대로 둔다.
:editF2프로그램 전체를 편집기로 연다.
:edit NN 번 줄을 입력 줄로 가져온다.
:edit 이름프로시저(또는 레코드, 상수 …)를 여러 줄째 편집기에 불러, 저장하면 제자리에 돌려놓는다.
:edit N-MN 번부터 M 번 줄을 :edit 이름 과 같이 다룬다.
:insert NN 번 줄 위에(0 이면 맨 끝에) 빈 줄이 올 때까지 줄을 끼운다.
:delete N줄을 지운다. :del 로 줄여 쓰고, N-M 도 된다.
:procs프로그램의 프로시저를 시그니처와 함께 보인다.
:get_order검색 순서를 알린다.
:clear, :stack스택을 비운다. 스택을 보인다.
:helpF1명령과 키를 알린다.
프로시저를 쓸 때

프로시저 안에서는 줄마다 돌리지 않는다. , 나 . 마다 그때까지의 줄을 컴파일만 하고, 틀린 줄은 그 줄 번호로 알리며 그 줄을 입력 줄에 돌려주어 고치게 한다. 프로시저는 부를 때 돈다. 인수를 먼저, 이름을 나중에 쓴다. 방금 컴파일한 프로시저는 시험해 볼 호출을 입력 줄에 채워 둔다(매개변수마다 견본 값, 그다음 이름과 마침표). 값을 고치고 Enter 로 돌린다.

추적과 중단점
명령키하는 일
:traceF7:run 처럼 초기화한 뒤 프로그램을 문장 하나씩(마침표마다) 돌린다. 문장마다 스택을, 그리고 회색으로 프로시저 몸의 줄이 돌 때마다 그 줄과 지역 변수를 보인다. F7 은 켜고 끈다.
:trace offF7프로시저의 줄 추적을 멈춘다.
:break 4 7중단점을 걸고 프로그램을 다시 돌린다. :break sq 는 프로시저 sq 의 첫 몸 줄에 건다.
:continue, :cF8이어 간다. 멈춘 것이 없으면 F8 은 :run 이다.
:next, :nF10다음 줄이나 문장까지 간다. 멈춘 것이 없으면 프로그램을 1 번 줄부터 문장 하나씩 돌린다.
:toggleF9프롬프트에 친 줄에, 없으면 멈춘 줄에 중단점을 걸거나 없앤다.
:stop실행을 끝낸다.
:unbreak중단점을 없앤다.

프로그램은 중단점의 줄 앞에서, 프로시저 안이든 문장 앞이든 멈추고, 지역 변수와 멈춘 자리 둘레의 줄을 보인다. 프롬프트에 친 문장도 프로시저 안에서 멈춘다. 중단점은 줄 번호라서 :insert 나 :delete 뒤에도 그 번호에 남는다.

자동완성

프로시저는 입력 줄과 편집기(F2) 모두에서 치는 대로 후보로 나오고, 그 줄 위에 모듈, 시그니처, 뜻(표준에서 뽑은 것)이 보인다. 프로그램의 프로시저가 후보 맨 앞에 시그니처와 함께 온다. use 뒤에서는 아직 쓰지 않은 모듈을, set_order 뒤에서는 쓰고 있는 모듈(과 get_order)을 모듈마다 무엇인지와 프로시저들과 함께 아래로 펼쳐 보인다. 후보는 타자에 필요 없는 키로만 다룬다.

키하는 일
Alt+위, Alt+아래후보를 고른다. Alt+아래는 후보를 띄우기도 한다.
Alt+1 … Alt+9n 번째 프로시저를 쓴다.
Tab고른 프로시저를 쓴다. 편집기에서 후보가 없으면 빈칸 넷을 쓴다.
Esc후보를 닫는다.
Alt+0커서 자리에서 후보를 부른다. 치던 프로시저가 있으면 그것을, 빈자리면 프로그램이 선언한 이름 열 개를 커서에서 가깝고 최근인 순으로 보인다.

이 판의 웹어셈블리 호스트가 등록하는 모듈은 io 하나다. io.read_line 은 늘 not_found 로 실패한다. file, clock, random, env 와 extern 은 없다. 핵의 모듈(str, json, csv, rex 따위)과 작업은 그대로 돈다.

흔한 오해: 웹어셈블리에서는 작업이 여러 코어에서 돈다

돌지 않는다. 작업은 어디서나 한 상태 안에서 차례로 돈다(13장). 웹어셈블리 판도 같은 코어 하나를 쓰고, 같은 스크립트는 같은 것을 찍는다.

14.7 더 보기#

핸들(C 객체를 스크립트에 쥐여 주기), 묶기(호스트 메모리를 전역으로), 나중에 끝나는 호스트 프로시저, 상과 복제, extern 은 표준 18절과 19절에 예제와 함께 있다.

정리

  • 덩이를 주고 열고, 프로시저를 등록하고, 적재하고, 찾아 부른다(표준 19.2–19.5).
  • 호스트 프로시저의 실패는 or fail 이 있으면 실패, 없으면 결함이다(19.3).
  • 스크립트가 할 수 있는 바깥일은 호스트가 등록한 것뿐이다(13.3, 18).
  • 예산으로 멈춘 실행이 있으면 새 실행은 거절된다. 상으로 되돌린다(19.5, 19.9).
  • 여러 코어에는 상태를 여럿 열어 호스트 루프로 돌리고, 상태 사이는 채널의 메시지로 잇는다(17.4).
  • 읽기만 하는 자료는 shared 로 선언하고 pinax_share 로 한 벌을 함께 읽는다(8.13, 19.7).
  • 여러 프로세스는 pinax_share_save 로 쓴 파일을 pinax_map_file 로 사상해 함께 읽는다(19.7).
  • 기다리는 호스트 프로시저는 기다릴 수 있다고 등록하고 나중에 pinax_complete 로 끝낸다. 그동안 다른 작업은 돈다(19.8).
  • 요청 하나는 자기 작업 하나다. 요청 하나는 그 표를 실패로 완료해서, 실행 전체는 pinax_abort 로 포기한다(14, 19.5, 19.8).
  • apart 로 선언한 묶음은 결함 난 작업만 잃고, 호스트는 결함마다 작업의 꼬리표와 함께 듣는다(14.4 (3a), 14.5, 19.10). 차례 한도는 양보하지 않는 작업을 멈춘다(14.6).
  • 내보낸 코드는 C 로 컴파일한 프로그램의 코드를 같은 동작으로 돌린다(19.11).
